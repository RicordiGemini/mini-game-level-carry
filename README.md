## 一句话概括玩法

> 拖动走位，攻击方式由**武器类型 × 形态**共同决定。五种瞄准方式 × 十种打击形状，
> 换一把武器就等于换一套操作手感。每关有一个**阵型**，阵型既真的改变刷怪位置，
> 也决定推荐（伤害 ×1.25）与克制（伤害 ×0.80）武器名单。

## 十四点设计摘要

1. **难度**：每关三档（普通 / 困难 / 噩梦），通关一档解锁下一档。难度越高敌人越硬越多，
   **远程怪比例越高（跨档位硬上限 45%，专门为噩梦档设）**；难度反过来开放能力 —— 出战槽位与新武器。
2. **战斗**：拖动走位。铁剑只有前攻击（靠走位对准）、短弓锁定追踪、铁锤朝拖动方向砸、
   冰晶球自动打最近、回旋轮全屏横扫。18 把武器（12 常规 + 6 高阶专属）。
3. **每关最合适的武器都不一样**：每关一个阵型（零散 / 成列 / 扎堆 / 人海），
   既真的改刷怪分布，也决定推荐（×1.25）与克制（×0.80）名单，且推荐名单按关卡轮转。
4. **属性**：24 种属性（6 组 × 4 种），单表 `COUNTERS` 推导抵抗。克制 ×1.6 / 被克 ×0.9，
   多属性相乘封顶 ×2.0。武器可镶属性石；对局角落常驻克制面板，装备够好可以**无视克制**。
5. **局内三选一**：打怪攒经验升级，弹固定三张卡（主类别 2 + 其他 1）。武器与辅助各 6 槽
   （复玩 +2），天赋不占槽、可叠层、永远有货保底。
6. **形态图**：`FormNode` + `EvolutionEdge`。三类进化 —— upgrade（不耗槽）、
   fusion（耗一槽并立刻补选）、advanced（**只有带老档进场才出现**）。
7. **局外双轴**：局外等级 `level` 1~5（金币，基础数值）× 品阶 `rarity` 0~6
   （同阶装备 + 金币，强度倍率 + 镶嵌槽 + 自带属性）。两条轴都必须投入。
8. **防具四部位套装**：头 / 身 / 裤 / 鞋，23 套 × 4 = **92 件**。
   单件专属词条 + 2 件小套 + 4 件大套，品阶阶梯词条（传说 7 条）。
9. **三池抽卡**：武器池 18 / 辅助池 14 / 装备池 92，保底进度各自独立。
   通关按难度发许愿水晶（普通 10 / 困难 30 / 噩梦 100），10 水晶 = 1 抽。
10. **重复件必有回报**：重复武器 → 专属材料 ×2；重复辅助 → 金币 120；
    **重复防具 → 入库为新实例（升阶燃料，不回炉）**。绝不静默消失。
11. **祝福值**：献祭水晶或看广告获取，每抽消耗 1 点使钻石及以上权重翻倍（12% → 24%）。上限 30。
12. **同关复玩继承**：通关封存本关档案，复玩看广告继承装备开局（数值 100%，形态与天赋恢复）。
    **首次进更高难度默认免费继承** —— 不做成广告位，避免被判"强制观看广告"。
13. **复玩加难**：已通关难度进场前自选 +0% ~ +120%，代价提前明示，金币收益同步抬升。
14. **教学**：4 步新手引导 + 14 条首通提示（每个系统第一次出现弹一次），去重持久化。

**八条贯穿全工程的不变量**（任何改动不得破坏）：

1. 战斗层不认识属性表 / 装备表 —— 只吃 `WeaponSpec` 与 `BattleSetup` 两个纯数据接口
2. 没有任何成长动作必须看广告 —— 所有 `Manager` 函数不接收广告参数
3. 重复件必须有回报，绝不静默消失
4. 抽卡不提供数值碾压 —— 抽到的一律 1 级
5. 刻意不做成硬克制（×1.25 / ×0.80 是"更爽"不是"必须带"）
6. 单条线不能点满 —— 无视克制必须金币、品阶、镶嵌三样共同投入
7. 推荐与数值同源 —— 阵型表既决定刷怪分布也决定推荐/克制名单，文案与数值永不打架
8. 教学只讲"现在该做什么"，且同一条提示只弹一次

### 架构不变量

- **`battle/` 与 `core/FormGraph.ts` 不 import `data/` 的业务表**，
  靠 `setElementResolver()` 与 `aggregateModifier()` 的回调注入实现 ——
  这让战斗与形态图可以在 Node 里跑完整仿真而无需建档。
- **`REWARD` 阶段是真的冻结**：`GameEntry.update()` 直接 `return`，不调 `tick(dt)`。
  只把面板盖在画面上而世界继续 tick，玩家会在选卡时被围殴致死。

## ⚠️ 接手前必读

本项目**设计文档完整度很高，但存在三类必须先解决的问题**：

### 1. 测试覆盖仍很薄（P0）

✅ **类型检查**：`npm run typecheck` → 全工程 0 错误
（`tsconfig.json` + `types/cc-stub.d.ts`，因为 Cocos 的类型定义在 gitignore 的 `temp/` 里）

✅ **测试框架已跑通**：`npm test`

```bash
npm test        # 编译测试目标 + 跑全部套件
npm run typecheck
```

第一套是 `validateFormGraph()` 的硬校验：**49 项断言**，
并且用**变异测试验证过 23/23 条校验都能被抓到**（不是假绿）。

❌ **其余 10 套历史测试仍不存在** —— `e2e.js` / `balance_guard.js` 等
共 1159 项断言，交付物里一个都没有，历史文档的"全绿"结论无法复现。

框架已就位，加新套件只要在 `tests/` 放 `*.test.mjs`，`npm test` 自动收编。
下一批建议见 [docs/10-开发指南 §6.2](docs/10-开发指南.md)。

### 2. 三个功能性缺陷 —— ✅ 2026-10-16 已全部修复

| 缺陷 | 修法 |
|---|---|
| ~~`armorBonus()` 未接入战斗~~ | `ForgeManager.mergeArmorBonus()` 在 `LevelFlow.modifierOf()` 合并，三处调用点自动一致 |
| ~~升级不消耗材料~~ | `UPGRADE_MATERIAL_COST = [1,2,3,4]`，`upgrade()` 先校验后扣费，UI 显示材料进度 |
| ~~`t_critdmg` 天赋无效~~ | `addEffect` 按 `CRIT_MUL_BASE` 分绝对/增量两种语义 + `_critMulAbs` 两层记账 |

详见 [docs/12-缺口与风险.md §1](docs/12-缺口与风险.md)。

### 3. 一个核心设计前提未验证

**「站桩不动能不能通关噩梦」在代码中没有任何支撑。**

历史文档对此有两份**互相矛盾**的结论，且因为探针脚本全部不存在而无法判定。
这直接决定"拖动走位是核心操作"这个前提是否成立 ——
**必须用真机数据回答，模拟回答不了。**

完整清单与建议优先级见 [docs/12-缺口与风险.md](docs/12-缺口与风险.md)。
