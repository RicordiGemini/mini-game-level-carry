# Roguelike 怪物波次规划

根据用户参数产出一份能直接交给策划或程序使用的怪物波次配置。先识别目标格式：如果用户指定了项目字段、CSV、JSON、Markdown 或表格模板，按指定格式输出；否则默认输出“设计假设 + Markdown 配置表 + 汇总校验 + 可复制的 JSON”。

## 输入与缺省

优先使用用户明确给出的值，不用默认值覆盖它们。至少需要确认或合理推断：

- 关卡标识、难度、总波数或总战斗时长。
- 敌人类型及其基础属性、威胁成本或可接受的强度比例。
- 总敌人数或每波预算，以及远程、精英、首领等比例上限。
- 波次节奏：入场间隔、每波持续时间、是否允许重叠刷怪、阵型或出生方向。

信息不足时，明确列出假设并继续生成可调整的初版；只有缺少关键数值会改变玩法方向时才提问。不要虚构项目中不存在的敌人 ID、资源 ID、奖励或平台配置。

## 生成流程

1. 把用户参数规范化为统一单位：数量为整数，比例为 0~1，时间为秒，倍率以 `1.0` 为基准。
2. 先确定总预算，再按节奏分配到波次；最后才在每波内分配敌人类型。任何取整造成的余数必须在表中可追溯，且总数与预算相等。
3. 为每波填写开始时间、生成间隔、敌人类型、数量、属性倍率、阵型和特殊词缀。首领或精英应有明确的登场波次、预警时间和数量上限。
4. 生成汇总校验：总敌人数、总波数、预计时长、远程占比、精英/首领占比、最高同屏数、强度预算和未满足约束。
5. 检查玩法可读性：开局留出反应时间；高压波之间有恢复或走位窗口；远程压制、快速近战和高血量单位不要在没有预警的情况下同时达到峰值。

## 默认数值边界

以下只是在用户未给出项目规则时的起点，不是硬编码。若任务针对本项目，优先遵循 [references/wave-schema.md](references/wave-schema.md) 中的代码约束：

- 普通波通常占 25%~40% 的敌人预算，后续波逐步提高密度；最后一波才承载首领或主要精英压力。
- 单波数量、生成间隔、同屏上限必须同时检查，不能只看总数量。
- 远程敌人应单独统计；无明确设计时默认不超过总敌数的 30%，项目噩梦档的硬上限按项目规则收敛到 45%。
- 精英、冲锋、快速和远程单位共享同一波时，优先降低数量或延长预警，不用简单叠加倍率制造不可读的难度。
- 任何波次都不能因为取整产生 0 数量的占位行；数量为 0 的类型省略。

## 输出格式

默认按下面顺序输出，内容保持紧凑：

### 设计假设

只列会影响结果的假设，例如总预算来源、波次比例、未提供的敌人基础值和取整方式。

### 波次配置表

至少包含这些列：

| waveId | startSec | durationSec | enemyType | count | hpMul | atkMul | speedMul | ranged | formation | spawnIntervalSec | warningSec | special |
|---:|---:|---:|---|---:|---:|---:|---:|:---:|---|---:|---:|---|

用户若要求项目落地表，追加项目所需字段；不要把解释文字塞进数值列。

### 汇总校验

用表格或短清单报告总数、各类占比、预计结束时间、最高同屏数、预算偏差和约束状态。总数、比例和时长要从明细重新计算，不凭目测填写。

### JSON

提供与 Markdown 明细一一对应的数组。数值使用 JSON number，布尔值使用 JSON boolean；不要把百分号或单位拼进数值。若用户只要表格，可省略 JSON。

## 本项目适配

当前工程是 Cocos Creator 3.8 + TypeScript。针对本项目时：

- 先读 `docs/00-文档索引.md`、相关关卡文档和实际代码，再判断字段；代码优先于文档。
- 关卡总览字段映射到 `assets/scripts/data/LevelConfig.ts` 的 `LevelConfigItem`；战斗层只接收 `assets/scripts/battle/BattleTypes.ts` 的 `EnemySpawnSpec`。
- 项目默认关卡成长、定时波次、波内统一攻防、同屏上限和敌人类型比例见 [references/wave-schema.md](references/wave-schema.md)。不要在表中擅自改写这些全局规则；若用户要改规则，单独标出“规则变更”。
- 当前战斗层支持 `EnemySpawnSpec.waves`：每波使用 `duration`、`spawnInterval`、`spawnCount`、`hpMul`、`atkMul`，`maxAlive` 控制同时存活上限；`batchSize` / `batchInterval` 保留用于旧固定数量模式。定时模式数量为未限流投放估算，不能将估算描述为保证实际生成或击杀数量。
- 只生成配置表时不要修改 `assets/scripts`、场景、预制体或存档。用户同时要求接入运行时，才转入项目开发流程，并按 `wechat-minigame-development` 的验证要求执行。

## 质量检查

交付前逐项检查：

- 明细数量之和等于总预算；波次 ID 连续且时间不倒退。
- 所有倍率、比例、间隔和预警时间在用户约束内；取整误差有说明。
- 远程、精英、首领和特殊词缀分别统计，避免同一敌人被重复计数。
- 每波至少有一种可解释的压力来源；连续高压波之间有节奏理由。
- 未提供的字段使用“待定/需项目确认”，不要用看似精确的伪造数值填空。
