# 从需求到微信上线

按本轮任务使用相关阶段。新增按钮不需要重新立项；完整游戏任务应持续完成可执行的各阶段。流程中出现的功能是可选能力，依据用户需求决定范围。

## 1. 定义可验收的游戏

明确核心操作、胜败规则、单局节奏、局内/局外循环、目标玩家、屏幕方向及目标设备。已有策划时复用；对会改变方案的缺项集中提问，其余采用可解释的默认值。

将需求转成可观察的验收条件，例如“结算后奖励仅入账一次，重启后保持”；再拆成能实际试玩的里程碑。完整开发宜先打通一局，再扩展关卡、装备、表现与平台能力。只在用户要求完整游戏时扩展到全流程，不能把小修复变成全面改造。

跨模块或多轮开发按 [需求与交付约定](task-delivery.md) 保留有效需求、重要决定和验收进度。计划中的玩法和当前已实现行为分开描述，用户变更需求后更新受影响部分。

## 2. 建立真正可运行的工程

核对实际 Cocos 版本、工程标识、设置、启动场景、资源目录与构建目标。当前若只有脚本，补工程时使用兼容的 Cocos 编辑器/模板生成，再接入既有逻辑，不手编未经引擎验证的场景 JSON 充当成品。

检查节点树、组件、事件、UI 引用、相机、Canvas、分辨率策略及初始可见状态。保留资源 UUID，避免覆盖现有 `.meta`。优先在可用编辑器里验证场景打开、资源导入和一局闭环；若工具不可用，完成可落盘的部分并说明准确缺口。

## 3. 实现玩法与内容

- 纯逻辑负责战斗、配置、状态和结算；UI 处理输入与展示。新增规则沿既有数据接口传递。
- 开局、暂停、三选一、胜败、成长、继承、重玩都要确认玩家能进入和退出，状态不会卡死。
- 配置数据验证引用完整、解锁可达、随机与保底合理；新增装备或属性遵守项目开发指南中的联动修改。
- 存档按版本迁移；奖励领取、货币扣除、结算与广告回调具备幂等性。测试重入、中断和重复操作。
- 美术、字体、音效与动画落实到实际资源，记录所需来源和使用许可。临时占位应明确，不冒充最终表现。

## 4. 按需接入微信平台与后端

先读取 [官方资料路由](official-docs.md) 中对应页面，核对小游戏支持范围及当前版本。

| 能力 | 实现与验收关注点 |
|---|---|
| 平台生命周期 | 前后台切换、音频中断、触摸取消、计时器和大帧间隔；恢复后不重复结算 |
| 登录 | `wx.login` 临时凭证与服务端交换、自有会话过期/续期；不把 AppSecret 或 session_key 交给客户端 |
| 存储/云存档 | 本地容量与失败路径、写入节奏、版本迁移、账号隔离、离线恢复与多设备冲突策略 |
| 网络/云服务 | 合法域名、超时、重试边界、服务端鉴权与幂等；云环境和地域使用明确配置 |
| 激励广告 | 有效广告位、预加载、失败/无填充、提前关闭、完整观看、重复点击与一次性发奖；工具模拟不算真机证据 |
| 分享/排行 | 当前开放能力和准入、主域与开放数据域的通信/渲染边界；不能将分享回调作为可靠完成证明 |
| 支付 | 产品确实需要时才接；核对当前平台/系统支持和开通条件，服务端校验订单并去重发货 |
| 隐私与授权 | 按实际收集的数据和调用接口配置隐私说明、授权/拒绝路径；不无故索取无关个人信息 |

后端可以是已有服务、按需新增服务或适用的云开发；单机玩法不强制引入账号与联网。需要联网时同时交付数据模型、接口、部署配置说明和错误处理，不能只留客户端伪调用。

## 5. 构建、资源与性能

通过当前 Cocos 版本支持的微信小游戏目标构建，核验入口、基础库选择和生成配置。对需跨构建保留的改动使用受支持模板或扩展。生成目录可重建，发布配置要可追踪。

从当前官方代码包文档确认主包、分包、整体包与下载缓存限制，按实际构建产物测量，不复用旧文档里的固定数字。按需规划 Asset Bundle、远程资源、CDN、版本哈希、缓存回收和资源回滚；不要强加到不需要的项目。

真机关注冷启动/热启动、下载体积、首帧、峰值内存、帧时间、GC、Draw Call、纹理/音频占用与持续运行。以目标设备实测决定对象池、图集、分辨率、特效上限和降级方案；报告设备、版本、场景、时长和测量方式。

涉及关键业务异常、构建复现、最终视觉表现或实际发布时，按 [实现质量与发布证据](quality-and-release.md) 核对对应边界。

## 6. 测试与验收

| 层级 | 证据与适用边界 |
|---|---|
| 类型/逻辑 | 当前本地命令、通过/失败摘要；覆盖实际业务行为，不能证明引擎运行 |
| Cocos 编辑器 | 工程导入、场景/预制体、资源、输入与完整对局预览 |
| 微信开发者工具 | 导出工程打开、配置有效、基础库兼容、分包/域名/平台接口和错误日志 |
| 真机 | Android/iOS 目标设备，屏幕安全区域、触摸、前后台、广告/音频、弱网、存档升级、性能 |
| 发布版本 | 生产配置、模拟开关、包体、版本号与变更说明、隐私/资质材料、体验版复测 |

只对实际执行的层级给出结论。缺工具时提供可复现步骤、预期结果和待操作位置；外部阻塞不影响其他开发工作。新改动不需要反复重跑无关测试。

## 7. 提审、发布与迭代

根据当日官方要求及账号后台实际状态准备类目、隐私、所需资质与素材、测试说明、广告/支付开通状态等。备案、版号、防沉迷等适用性须按游戏类型、主体及当前要求核对，不能从历史笔记推断已满足或一概适用。

给出构建版本、变更内容、测试记录、外部配置、尚未解决的阻塞与回退方式。上传、提交审核、正式发布及云端变更依据用户已有授权执行；缺授权时先准备可审阅结果，再询问实际动作。

上线后按需求接入启动失败、脚本异常、关卡漏斗、存档故障、广告失败和性能监控，保护日志中的个人信息和密钥。资源/存档格式变更考虑向前兼容，避免代码回退后旧客户端无法加载新资源或存档。
