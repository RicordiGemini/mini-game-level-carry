# 实现质量与发布证据

按改动选择相关部分。这里给出容易被脚本级验证遗漏的边界，不要求每次修改执行全量审查或搭建新的基础设施。

## 可复现的工程与构建

- 识别实际 Cocos 完整版本及微信构建方式，核对当前引擎手册；不能仅凭“3.8”猜测补丁版本、命令行参数或工程格式。
- 保留并使用依赖锁文件，记录构建确实需要的运行时/工具版本。缺依赖时按项目现有管理方式安装；安装、升级和权限按当前环境与授权处理。
- 资源 UUID、场景引用、预制体和构建模板纳入可复现的源文件；避免只保留本机编辑器缓存或手工修改后的导出目录。
- 区分编辑器模拟、开发与生产配置。公开标识与服务端密钥分开，客户端包及日志不含 AppSecret、私钥或服务端凭证。
- 发布版本核对启用功能所需的配置和模拟开关。缺失广告位等配置应准确暴露不可用状态，不能静默发放“模拟成功”奖励。

## 关键业务的一致性

| 改动区域 | 需要防止的具体故障 |
|---|---|
| 消耗与奖励 | 校验失败仍扣费、扣费未得到产物、重复回调重复奖励、快速连点导致负数或重复结算 |
| 存档 | 写入失败被当成功、迁移失败覆盖唯一旧档、未知新版本被当坏档删除、账号切换串档 |
| 异步任务 | 场景销毁后回写、旧请求覆盖新状态、超时与成功回调同时结算、取消后监听/定时器泄漏 |
| 登录与服务端 | 使用客户端自报身份、未鉴权读取他人数据、重试重复发货、会话失效后继续写入 |
| 资源与生命周期 | 重开后重复订阅、资源未释放持续增长、前后台大时间差造成瞬间伤害或加速 |

按实际存储语义设计失败恢复：本地涉及消耗/产物的状态尽量作为同一业务提交保存；写入失败明确恢复或提示。迁移先验证旧数据和新结果，失败时保留可恢复副本，不在损坏时无提示覆盖或删档。

联网经济、支付或多设备账户由服务端承担权威状态、鉴权和幂等处理；客户端本地签名只提供有限的异常检测，不能保证防篡改。广告奖励是否有服务端校验能力必须查当前官方支持，不能发明一个不存在的验证接口。

## 玩法、数值与界面

- 数值变更检查它实际影响的伤害、生存、关卡时长和资源收支。关联项目既有不变量和保底机制，避免单改展示值却未改变生效路径。
- 随机、保底和模拟结果需要记录样本或种子等复现条件；模拟用于验证假设，手感和真实设备体验依赖试玩。不要只凭平均值或单局结果宣称平衡。
- 主要操作、反馈层级、字号和对比度保持清晰；说明信息和可点击区域在目标分辨率下可读可操作。UI 只展示会帮助玩家决策的信息，不塞入开发术语和调试状态。
- 按功能处理加载、空状态、失败、禁用、快速重复点击、返回与中断恢复。广告不可用、离线或权限拒绝不能把整局卡死。
- 完整视觉交付应有一致的风格、图标、字体、动画和音频反馈，并在实际场景中检查遮挡、层级、裁切与安全区域；已有美术规范优先，临时占位清楚标记。没有视觉方向时提出适合玩法的默认方案，用户指定风格则按其要求实现。
- 音频检查首次触发、静音设置、前后台恢复与重叠播放；记录资源来源和使用权。调用可用的素材/生成能力时遵循对应工具流程，不假装已生成资源。

## 有效的验证

为有实际风险的行为选择测试：新旧存档样本、失败注入、重复操作、异步乱序、奖励/消耗边界。断言可观察结果和不变量，不只是字段存在或复刻实现。低影响说明调整不用增加玩法测试。

对项目原有失败保留结果并判断影响。修复本次引入的回归；确实无关的故障需说明，不能因此声称所有检查通过，也不默认扩展为修复整个项目。

真机验证记录构建版本、微信/基础库版本、设备系统、关键操作和实测结果。性能报告说明测量场景与时长，区分实测、估计与目标值。不预设没有依据的“全机型流畅”或固定帧率保证。

## 发布与回退

仅在准备实际交付构建或发布时整理必要信息：源代码版本/工作区状态、引擎与关键工具版本、构建目标、产物位置、对应资源版本、配置项和已执行测试。无需为了小功能另外建设流水线；已有自动化则使用并维护。

发布前处理会造成启动失败、核心循环中断、数据丢失或错误扣费/发奖的已知问题；真实限制和未验证事项明确列出，不能用虚构的绿色结果绕过。

按用户授权执行外部动作，保留实际返回的版本或状态证据。上传成功不代表审核通过，审核通过不代表已发布；未授权时先准备可审阅产物和准确操作说明。

回退同时考虑代码、资源、服务端接口和存档版本。不能假设降级代码就能读取新版本存档，也不能未经授权通过清空玩家数据回退。按实际能力准备兼容策略、恢复路径及线上异常定位方式。
