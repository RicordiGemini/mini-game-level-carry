# 微信小游戏全流程开发

目标是交付符合用户需求、能在微信中实际运行且可维护的游戏。完整交付包含工程和资源接线、可玩的闭环、平台适配与验证证据，不能用代码骨架替代。知识来自当前代码与按任务查阅的官方文档，不假定已经掌握未来的平台变化。

## 按需读取

- 接手本项目、定位模块或恢复开发上下文：读 [references/project-context.md](references/project-context.md)，然后检查实际文件。
- 用户提出新功能、完整游戏、性能优化或上线需求：读 [references/development-workflow.md](references/development-workflow.md) 对应阶段；小修复不需要走完整生命周期。
- 使用或修改微信 API、引擎构建、平台规则：读 [references/official-docs.md](references/official-docs.md)，再打开对应官方页面。链接目录不是接口细节或实时规则的替代品。
- 完整游戏、跨模块需求、需求变更或跨会话接续：读 [references/task-delivery.md](references/task-delivery.md)，建立需求与验收的对应关系并保留必要进度。
- 修改存档、经济、异步平台能力，或准备可试玩/发布版本：读 [references/quality-and-release.md](references/quality-and-release.md) 的相关部分，核对具体故障路径和交付证据。

## 把需求变成实现

1. 从用户描述提取玩家操作、目标体验、范围和验收条件。完整游戏需求明确核心循环、目标机型与画面方向；现有信息足够时直接给出合理假设并动手。
2. 将验收条件映射到当前代码入口、数据和界面。区分可复用、需改造及确实缺失的部分；用户指定玩法时围绕该玩法实现。
3. 先做可运行的纵向闭环，再扩展内容、表现和平台能力。一次功能交付应包含实际入口、状态变化、反馈、存储与失败恢复等相关部分。
4. 修改微信能力前核对官方签名、异步事件语义、最低基础库、机型限制和错误路径。记录关键来源、查阅日期、适用版本和需要的后台配置；不凭记忆编造上限和审核规则。
5. 实现并运行适合改动的验证。发现已有失败时区分原有问题和本次回归，不通过放宽断言、删除测试或清档制造通过。
6. 将结果逐项对照本轮验收条件，检查实际差异、遗留占位和配置，更新模块文档与缺口状态。多轮任务保存必要的决策和进度，继续已有工作，不反复从需求访谈开始。

## 微信与 Cocos 的关键边界

- 保持 Cocos 3.8 的引擎版本兼容。场景/预制体引用、`.meta` UUID、资源加载与释放、节点生命周期都属于实现的一部分。缺少完整工程时，应在对应开发任务中补齐可打开、可预览、可构建的工程入口。
- Cocos 导出与微信运行工程各司其职：检查微信构建目标、启动场景、构建配置及导出的 `game.js`、`game.json`、`project.config.json`。需长期保留的调整落在引擎支持的构建配置、模板或扩展中，避免只改一次性构建产物。
- 微信能力封装环境识别、能力检测、初始化、事件订阅/解绑、超时和失败返回。编辑器模拟与真实环境明确区分，生产缺配置不能静默走“成功”。
- 激励广告核验当前官方关闭事件语义；处理完整观看、提前关闭、无填充、加载失败、重复点击、监听清理和奖励去重。广告展示等待与实际播放阶段分开处理，不能用短加载超时结束长视频的奖励判定。
- 前后台切换暂停/恢复战斗、音频和输入，处理大时间差；异步回调不得操作已销毁场景。按需测试弱网、离线、缓存过期和重启恢复。
- 有账号或后端需求时，临时登录凭证由服务端交换登录态；服务端验证身份和关键业务，不能信任客户端上报的余额、广告奖励或排行。支付按当前官方能力与实际准入条件实现。
- 资源、音频、字体与 UI 在目标设备上验收，兼顾安全区域、触摸坐标、不同屏幕比例、内存、首屏加载和长时间运行。性能目标来自需求和设备实测。

## 完成交付的判定

按用户本轮范围逐项给出证据；整款游戏交付时至少覆盖下表。未要求的广告、支付、社交或联网功能可标记“不适用”并说明原因。

| 方面 | 可审阅的交付证据 |
|---|---|
| 需求 | 玩家操作和验收标准可对应实现；重要假设明确 |
| 工程 | 真实 Cocos 工程入口、可加载资源、场景绑定、目标构建配置齐全 |
| 玩法 | 启动/引导 → 主界面 → 开局 → 战斗/互动 → 胜败结算 → 成长/重玩可完成 |
| 持久化 | 首次启动、正常保存、杀进程重启、升级迁移及异常存档有处理 |
| 微信能力 | 本轮启用的能力有配置说明、真实调用及失败路径；模拟行为已隔离 |
| 表现与性能 | 所需美术音频和适配落地；记录目标设备的加载、帧率和内存实测 |
| 质量 | 适用的本地检查通过；编辑器、微信工具和真机结果分别记录 |
| 发布准备 | 生产配置、包体核验、所需隐私/资质材料、版本说明与回退方案明确 |

开发完成、真机验收、审核通过和正式发布是不同状态。账号操作、工具缺失或规则无法核实时，交付可继续推进的部分和精确的剩余步骤，不能把未验证内容标为完成。

规则文件只能约束工作方法，不能代替引擎、账号、官方资料或实际验证。修改本技能时检查规则冲突、引用和现实任务下的决策是否一致；结构检查通过不证明 Agent 的开发行为已经验证。
