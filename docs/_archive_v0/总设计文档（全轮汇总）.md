## 一、项目概览

| 项 | 内容 |
|---|---|
| 定位 | 微信小游戏 · 休闲肉鸽 + 局外武器收集养成 |
| 技术栈 | Cocos Creator 3.8 + TypeScript；战斗层为纯逻辑，可脱离引擎在 Node 跑 |
| 验证环境 | `tscheck`（从 `assets/scripts` 同步的纯逻辑镜像）；`tsc` 0 类型错误 |
| 测试规模 | 10 套 e2e 测试，**1159 项断言全绿**（rarity 111 / gacha 123 / armor 168 / tutorial 38 / e2e 181 / evolution 117 / battle 104 / ui 60 / balance 53 / forge 204） |
| 内容体量 | 12 把武器（6 常规根形态 + 6 高阶专属）· 8 件常规辅助 + 6 高阶 · **23 套防具 × 4 部位 = 92 件** · 24 种属性 · 三档难度 · 关卡公式化至 200 关、24 关一轮循环 |

**八条贯穿全工程的不变量**（任何改动都不得破坏）：

1. **战斗层不认识属性表** —— 战斗与装备系统只通过 `WeaponSpec` / `BattleSetup` 两个纯数据接口交互。
2. **没有任何成长动作必须看广告** —— 广告只做"加速"，所有 `Manager` 函数不接收广告参数。
3. **重复件必须有回报**，绝不静默消失（重复武器→材料、重复辅助→金币、重复防具→升阶燃料）。
4. **抽卡不提供数值碾压** —— 抽到的一律 1 级。
5. **刻意不做成硬克制**（推荐 ×1.25 / 克制 ×0.80，是"更爽"不是"必须带"）。
6. **单条线不能点满**：无视克制 / 破防必须由金币、材料、镶嵌三样共同投入才能堆高。
7. **推荐与数值同源**：阵型表既决定刷怪分布，也决定推荐/克制名单，文案与数值永不打架。
8. **教学只讲"现在该做什么"，且同一条提示只弹一次**（第十轮起）。

## 三、系统全景（按模块汇总）

### 3.1 战斗层
- **操作核心**：拖动走位（JOYSTICK 虚拟摇杆 / FOLLOW 跟随，每帧轮询重算，规避"按住不动丢失 TOUCH_MOVE"）。
- **五种瞄准** × **十种打击形状**：`FRONT`(前向，需走位) / `LOCK_ON`(锁定) / `MOVE_DIR`(移动向) / `NEAREST`(最近) / `SCREEN_ROLL`(全屏)。形态可覆盖瞄准方式（终局→全屏割草）。
- **射程/弹道**：索敌默认全屏；弹道飞行距离单独算，保证"锁定必中、不飞出屏"。
- **战斗循环**：移动→逐武器结算→判定体→敌人 AI→清理→胜负；判定体统一处理挥砍/弹丸/震荡波/陨石。
- **敌人底线**：移速(92) 远低于玩家(330)；不从下边缘刷；分波投放。
- **局内成长对接**：升级→三选一→`syncWeapons` 就地合并并保留冷却与锁定；`REWARD` 阶段战斗真冻结。

### 3.2 关卡与难度
- **三档**：普通 / 困难 / 噩梦，按六维调（血量/攻击/数量/移速/远程比例/金币倍率），远程比例是"质变"（废掉站桩）。
- **解锁**：顺序解锁，每关独立难度轴（`maxTiers`），`globalMaxTier` 驱动跨关卡解锁。
- **难度驱动能力**：通关解锁新装备（12 把武器按"关卡×难度"两轴铺开）+ 出战槽位（2/3/4 件）。
- **阵型**：每关一个 `FormationKind`（scatter/line/cluster/swarm），既改刷怪分布也定推荐/克制。
- **噩梦专属**：精英(厚甲+护盾) / 突进(高速) / 冲锋(蓄力冲刺)，仅占噩梦档。

### 3.3 局内成长（形态图 v3）
- **四条成长线**互不重叠：局外升级（金币，永久）/ 局内武器形态（占武器槽）/ 局内辅助（占辅助槽、进化不耗槽）/ 局内天赋（不占槽、可叠层）。
- **形态图**：`FormNode` + `EvolutionEdge`；`sources`（血脉）同时解决"合成不亏伤害、关卡适配不失效、档案继承不断"。
- **三类进化**：upgrade（不耗槽）/ fusion（耗一槽，随即补选新武器）/ advanced（仅携带老档出现）。
- **三选一**：固定 3 张（主类 2 + 其他 1），主类按关卡等级轮转，天赋永远有货保底。
- **经验双曲线**：关卡等级触发三选一节奏；形态经验决定可进化深度，溢出经验带入下一层。

### 3.4 局外养成（双轴：等级 × 品阶）
- **武器等级 `level` 1~5**：金币 + 该类型突破材料（`mat_<type>`）升级，提供基础数值。
- **品阶 `rarity` 0~6**（第八轮）：青铜→白银→黄金→钻石→史诗→神话→传说；强度倍率 ×1.00→×3.30，镶嵌槽 1→4。
  - 升阶消耗**同阶装备**（件数 1/1/2/2/2/1，不卡），神话→传说额外需**神话之核**。
  - 品阶**吸收**了旧 `forge.rank` 的职责，旧 rank 在迁移中映射成品阶。
  - 钻石及以上专属装备**自带复合属性 `innate`**（升阶继承、不可卸）；玩家另可镶属性石（可卸、继承）。
- **辅助**：局外**阶数** `rank` 1~5（金币，放大 effect）× 品阶 `rarity`（抽卡+升阶，放大 effect）× 自带属性。
- **防具**（第九轮补齐，与武器对称）：
  - **四部位**：头 `head` / 身体 `body` / 裤子 `pants` / 鞋子 `shoes`，四件可同时穿戴，全部在防具池抽取。
  - **23 套 × 4 件 = 92 件**：青铜 5 套（从零起步、可用材料开孔）、白银~传说每阶 3 套。
  - **专属内容双轨**：每件自带 1 条**单件专属词条**（`innate`）；同套穿 2 件触发**小套属性**、4 件触发**大套属性**。
  - **品阶阶梯词条**：大套词条数 = 青铜1/白银2/黄金3/钻石4/史诗5/神话6/传说7，小套 = `ceil(大套/2)`。
  - **升阶**：消耗**同阶同部位**装备（曲线同武器）+ 金币，每次 **+3 镶嵌孔**，抗性/词条随品阶倍率自动重算。
  - **开槽**：基础孔 = `raritySockets(品阶)`（免费）；额外孔用**许愿水晶** 10/孔开；升到神话免费解锁累计孔；**青铜**可用突破材料开孔。
  - **抗性仍在**：每件带 1 条轴的 6 维抗性（按部位权重分摊），与词条**双轨并存**。

### 3.5 抽卡与资源
- **三池**：武器池(18) / 辅助池(14) / **防具池(92 件套装部件)**；保底进度各池独立。
- **许愿水晶**：通关按难度发放（普通 10 / 困难 30 / 噩梦 100，不打折），10 水晶=1 抽。
- **一次抽卡三类结果**：装备 74% / 材料 18% / 高阶碎片 8%；品阶权重指数衰减（青铜 46→神话 1，传说不可抽）。
- **重复转化**：重复武器→专属材料×2；重复辅助→金币 120；**重复防具→入库为新实例（升阶燃料，不回炉）**。
- **祝福值**：10 水晶=1 点 / 看广告+3 点，上限 30；每抽耗 1 点使钻石及以上权重翻倍（12%→24%）。
- **高阶碎片**：25 个任意兑换一件高阶(钻石)装备，三池通用，是"抽不到也不被卡死"的确定路径。
- **神话之核**：仅第 9~12 关（属性数=3）× 噩梦，掉率 25%，不可买/换/广告得。

### 3.6 继承与复玩
- **同关复玩继承**：通关封存本关档案，复玩看广告继承装备开局（数值 100% 继承，形态/天赋恢复）。
- **跨难度默认继承**：首次进更高难度免费继承上一难度通关装备（避免劝退）。
- **复玩加难**：已通关难度进场前自选 +0~+120%，代价提前明示，金币收益同步抬升。
- **"重新开始"不删档**（`DROP_ARCHIVE_ON_RESTART=false`）。
- **白名单** `CARRY_WHITELIST` 只放行指定资源/属性字段；装备做结构收敛（阶数夹合法、非法形态丢弃）。

### 3.7 属性与克制（24 种）
- 6 组 × 4 种，参考洛克王国扩至 24（五行/自然/气象/造物/灵异/法则）。
- 单表 `COUNTERS` 推导抵抗，双向克制/同属性互克/普通系无克制单独声明；倍率 ×1.6/×0.9，多属性相乘封顶 ×2.0。
- **破防**（无视克制）：(等级−1)×3% + (品阶−1)×6% + 镶嵌×3%，上限 90%，单条线无法点满；用线性收敛而非开关。**第九轮起防具不再贡献破防**（`armorCounterBreak()` 恒为 0），破防完全由武器承担。
- **防具抗性** 24 维（第九轮改为四部位聚合）：每件带 1 条轴、按部位权重（身 .34 / 头 .30 / 裤 .20 / 鞋 .16）分摊套装总抗性；穿戴 4 件各乘品阶倍率、软上限压缩后**求和**，单维再压一次防溢出（永不 100%）。
- 关卡属性编排：1~4 关 1 种 → … → 13 关起 4 种，24 关一轮；同组周期=4 与种类边界对齐。

### 3.8 成就与图鉴
- 成就定位为"引导"而非"墙"：把"把所有系统玩一遍"做成可达成目标。
- 进化图鉴标注"★ 复玩解锁的更上级进化"及触发条件。
- 第十轮起，**真正的上手引导由教学体系承担**（见 3.10）；成就从"软引导"退回为"长线目标"。

### 3.9 存档与迁移
- 键位：`mg_profile`(全局) / `mg_level`(局内) / `mg_archive_<levelId>_<tier>`(关卡×难度双主键)，均带 `fnv1a` 加盐签名。
- 版本轨迹：`v1→v2`(补难度维度) `→v3`(形态图 formId 反查) `→v4` `→v5`(抽卡/辅助阶数) `→v6`(品阶吸收 rank) `→v7`(防具改为四部位实例模型 + 补 `tutorials` 教学标记)。
- 迁移原则：**不白送任何养成资源**（老 rank 映射成品阶不清零、水晶从 0、辅助从图鉴回填但 1 阶、碎片/祝福从 0）。
- **v6→v7 防具迁移**：旧单件防具（`armor_fire` 等已不在新表）**清退**并生成 `uid`、`worn` 置空/four-part 重映射；旧档防具补齐品阶基础孔。

### 3.10 新手引导与首通教学（第十轮）
- **新手引导**：4 步线性卡片（是什么 → 怎么操作 → 目标与产出 → 开始第 1 关），首次进入游戏播放，可跳过；看过即写档 `tutorials.newbie`。
- **首通教学**：14 条提示，覆盖三选一、进化、通关结算、属性克制、抽卡、锻造、防具套装、装备、难度、继承、复玩、成就、图鉴、走位；**每个系统第一次出现时弹一次**，靠 `TutorialManager.consumeTip()` 去重。
- **实现分层**：文案集中在 `data/TutorialConfig.ts`；去重/持久化在 `core/TutorialManager.ts`（纯逻辑可单测）；显示在 `ui/TutorialLayer.ts`（用 `Graphics`+`Label` 代码绘制，零美术资源，运行时挂到 Canvas）。
- **一致性保障**：`tutorial_e2e` 会扫描编译产物里所有 `showTipById('x')` 调用，断言**每个触发 id 都有文案、每条文案都有人触发**（防打错 id 导致静默失效）。

## 五、验证现状

- **类型校验**：`tsc` 零类型错误（`tscheck` 镜像；同步时勿漏顶层 `GameEntry.ts`）。
- **10 套 e2e 共 1159 项全绿**：

### B. 设计层面未覆盖（系统存在，但无策略 / 边界 / 终局）

**B-1 经济系统通胀与后期金币 sink 未分析。**
金币产出随关卡 `goldReward` 增长，消耗端有升级/升阶/镶嵌。但当玩家满级满阶满图鉴后，金币是否溢出、有无"深坑"消耗（如洗练、重铸、外观）未设计。后期"金币无用"会拖垮抽卡/养成动机。

**B-2 留存与终局循环缺失（最影响长线）。**
关卡公式化至 200 关、24 关一轮，内容不会"耗尽"，但**满传说/满图鉴之后玩家做什么**完全没有设计：无日常/周常/赛季、无排行榜、无社交分享、无好友助战。而这些都是微信小游戏留存的核心手段，文档对此只字未提。

**B-3 辅助装备"三轴过载"风险。**
辅助现在同时有 局外阶数(rank) × 品阶(rarity) × 自带属性(innate) 三条成长轴，语义可能与武器差异过大、且阶数与品阶都是"放大 effect"，存在概念重叠（玩家难区分"升阶"和"升阶数"）。建议用户确认是否有必要这么重。

**B-4 传说无碎片保底，长尾方差大。**
神话之核掉率 25%（仅 9~12 关噩梦），平均 4 次但方差大；抽卡最高只到神话(1%)，传说只能神话进化。整条传说线完全依赖随机掉落，没有"碎片保底"之类的兜底（对比高阶碎片可换钻石装备）。是否给传说也设一条确定路径？

**B-5 献祭水晶→祝福值可能形成捷径。**
"不抽、直接献祭水晶换祝福值"使高阶权重翻倍。若玩家纯刷水晶（噩梦 100/局）后集中献祭，可能绕过抽卡随机、稳定高产高阶——这条路径的产出上限是否评估过？祝福值上限 30 是否足够封死？

**B-6 性能 / 低端机 / 多分辨率适配未设计。**
全屏弹幕 + 大量敌人 + 24 属性实时计算 + 全属性防具多轴减免，无对象池、掉帧、低端机降级、720×1280 以外的分辨率/刘海屏适配说明。微信小游戏用户机型跨度极大，这是上线硬门槛。

**B-7 美术 / 音效 / 动画 / 分包 / 包体规划缺失。**
明确用 `Graphics` 画圆做占位。真实美术资源、音效、打击感动画、特效，以及 Cocos 分包、首包大小（微信小游戏主包限制 4MB 等）均未规划。

**B-8 剧情 / 世界观 / 合规包装缺失。**
游戏无任何叙事与世界观包装，也未见隐私协议、用户授权、版号/类目等合规设计。微信小游戏过审需要内容健康度与合规材料。

### C. 已识别但未实现的风险（文档自承）

**C-1 防作弊仅本地。** 文档明确"本地存档可被反编译"，给出的云端校验/服务端档案/异常检测三项进阶方案均**未实现**，目前只有加盐签名 + 结构收敛。外挂改档（如刷传说）在真机上可行。

**C-2 平衡只靠机制模型，无真机数据。** `balance_guard` 用机制模型守不变量，但文档自承机器人探针有系统性偏差（charge 偏袒近战、aggr 冤枉移动向），"不作裁判"。所有数值标定基于模拟，**无真实玩家数据回流**验证。
