# 难度体系设计

本文说明三档难度（普通 / 困难 / 噩梦）的规则、实现落点、两种继承的成本差异，
以及数值标定的实测数据与调参方法。

---

## 一、为什么是「每关 × 三档」而不是一条全局难度线

常见的做法是给整局游戏一条难度线：通关第 N 关后，所有内容整体变难。
这个做法有一个结构性缺陷：

```
玩家在第 12 关卡住
  → 唯一出路是"变强"
  → 变强只能靠打通第 12 关拿金币
  → 死循环
```

**每关独立解锁**没有这个问题：

```
第 12 关（困难）打不过
  → 回头打第 11 关的困难
  → 既能练手，金币产出还比第 12 关普通高 80%
  → 是平行可选项，不是唯一出路
```

这条设计同时解决了另一个问题：玩家不需要"为了继续玩而被迫重复最讨厌的那一关"。

## 二、解锁规则

难度**只能靠打过了解锁**，不能跳级：

```
第 1 关：只有普通
  通关普通 → 解锁困难
  通关困难 → 解锁噩梦
```

顺序解锁保证玩家进入噩梦之前，已经通过困难采集到足够的金币把局外等级升上去，
并且拿到了难度专属的装备。**不存在"直接跳级被劝退"的路径。**

实现：

```ts
// SaveManager
maxTiers: Record<string, number>   // { "3": 2 } = 第 3 关已解锁到困难
globalMaxTier: number              // 所有关的最大值，驱动跨关卡的解锁

static unlockTier(levelId, tier): boolean   // 只在真的提升时返回 true
```

`LevelFlow.onLevelClear()` 里：

```ts
const nextTier = tier + 1;
const tierJustUnlocked = hasNextTier(tier) && SaveManager.unlockTier(state.levelId, nextTier);
```

`tierJustUnlocked` 会被带进 `SettlePayload`，结算页据此把「挑战下一难度」按钮文案拉满。

### 为什么档位存在每关而不是全局

`maxTiers` 按 levelId 分开存而不是一个全局数字，是因为**关卡难度差异很大**：
玩家可能第 8 关只能打普通，但第 9 关（敌人少、地形开阔）能打困难。
用一个全局数字表达不了这种差异，而且会让"回头刷低难度"变得没有意义。

`globalMaxTier` 只是 `maxTiers` 的最大值，它单独存在是因为**跨关卡的东西需要它**：
出战槽位数量、新装备的开放条件。

## 三、难度提升是多维度的

只加血量会把战斗从"刺激"变成"磨损" —— 玩家体感是累，不是难。
所以每档难度同时调六个维度：

| 参数 | 普通 | 困难 | 噩梦 | 作用 |
|---|---|---|---|---|
| `hpMul` | 1.0 | 1.9 | 3.3 | 拉长单只敌人的对抗时间 |
| `atkMul` | 1.0 | 1.45 | 2.05 | 提高失误的代价 |
| `countMul` | 1.0 | 1.30 | 1.60 | 提高场面压力与走位需求 |
| `speedMul` | 1.0 | 1.10 | 1.20 | 压缩走位空间（**始终远低于玩家 330**） |
| `rangedRatio` | 10% | 24% | **42%** | **改变战斗结构**，见下（跨档位硬上限 45%，普通/困难永远到不了 42%） |
| `goldMul` | 1.0 | 1.8 | 3.0 | 高难度必须有回报，否则没人打 |

### 远程怪比例是"结构变化"，不是数值变化

前四个维度都是量变，玩家感受到的是"同一件事做得更久/更痛"。
远程怪比例是质变：**它把"站着不动也能赢"这件事直接废掉**。

- 近战怪会一路贴脸，玩家站桩也能自动反击
- 远程怪保持 300px 间距射击，站桩就只能挨打
- 想赢必须**主动绕后切入** —— 这正是拖动走位这个核心操作的存在意义

实测（第 1 关，新号「铁剑+短弓」，站桩不动，无任何继承）：

| 难度 | 远程怪比例 | 结果 |
|---|---|---|
| 普通 | 10% | 通关 4/4，剩 88 HP |
| 困难 | 24% | **战败 3/5** |
| 噩梦 | **42%** | **站桩战败（远程+精英+突进+冲锋复合压制）** |

同一个玩家只要肯走位，三档都能过 —— 差别全在"要不要主动切入"。
（`difficulty_probe.js` 的 D 节就是这张表，改数值后重跑即可复核。）

难度提升因此被玩家"看得见"：不是血条变长了，而是敌人行为变了。

远程怪比例还会随关卡进度再涨（`levelRangedBonus`，每关 +0.5%，封顶 **+6%**）：
同一档难度下越靠后的关卡，远程压制越明显。

三档基础值 10 / 24 / 42 加上关卡进度与复玩加难之后会超过这个数，
最终一律收敛到 `RANGED_RATIO_MAX = 45%` —— 这是一个**跨档位的硬上限**，
难度基础值 + 关卡进度 + 复玩加难三者相加后必须收敛到它，不允许任何组合突破。

定 45% 的理由（**它是专门为噩梦档设的**，不是三档通用上限）：
普通 10% 与困难 24% 加满所有加成也到不了 45%，只有噩梦（42% 起步）才可能顶到它；
而 45% 之上同屏弹丸就太多了，玩家注意力被“躲弹”分走，游戏从爽游变成手忙脚乱。

## 四、难度驱动能力扩张

难度不只是"怪更硬"，它同时是**能力解锁的闸门**：

| 通关 | 解锁 |
|---|---|
| 普通 | 冰晶球（关卡 2）、长枪（关卡 3）、飞刃（关卡 4）、巨镰（关卡 6）、手里剑（关卡 8）；出战槽位 **3 件** |
| 困难 | 铁锤（关卡 3）、雷杖（关卡 5）、重炮（关卡 7）；出战槽位 **4 件** |
| 噩梦 | 回旋轮（关卡 5）、光矛（关卡 9） |

> 括号里是**关卡门槛**。装备发放是「关卡进度 **AND** 难度进度」，
> 所以"通关困难"本身不够 —— 还要关卡号也够。反过来只推关卡不推难度也拿不到。

### 出战槽位（开局带几件）≠ 局内槽位上限

```ts
// DifficultyConfig —— 开局带几件武器进场
getEquipSlotCount(globalMaxTier) = min(1 + globalMaxTier, 4)

// RunConfig —— 一局内最多能持有几件（靠三选一一路扩上来）
weaponSlotCap(replay) = 6 + (replay ? 2 : 0)
auxSlotCap(replay)    = 6 + (replay ? 2 : 0)
```

两套数字都叫"槽位"但不是一回事，最容易混：

| | 含义 | 数值 | 谁决定 |
|---|---|---|---|
| 开局出战槽位 | 进场时手上有几件 | 2 / 3 / 4 | 全局最高难度（永久） |
| 局内槽位上限 | 一局内最多持有几件 | 6 / 6（复玩 8 / 8） | `RunConfig`（每局重来） |

多一件武器不是数值增长 —— 它是**多一套瞄准方式同时生效**：

```
2 件：前向挥砍（要瞄准） + 锁定射击（自动）
4 件：前向 + 锁定 + 最近（自动） + 移动向/全屏
```

玩家的操作负担不增反降，但输出结构完全不同。这是"推进难度"最直观的回报。

`EquipmentManager.syncProfile()` 在槽位增加时会**自动补满**，
让玩家在通关那一刻就立刻感受到变化，而不是要去背包里手动选。

### 新装备

```ts
// EquipmentConfig
unlockLevel: 3,        // 关卡进度门槛
unlockDifficulty: 2,   // 难度门槛
// 两个条件是"与"关系
isEquipUnlocked(def, unlockedLevel, globalMaxTier)
```

| 装备 | 关卡 | 难度 |
|---|---|---|
| 铁剑 / 短弓 | 1 | 普通 |
| 冰晶球 | 2 | 普通 |
| 长枪 | 3 | 普通 |
| 铁锤 | 3 | 困难 |
| 飞刃 | 4 | 普通 |
| 雷杖 | 5 | 困难 |
| 回旋轮 | 5 | 噩梦 |
| 巨镰 | 6 | 普通 |
| 重炮 | 7 | 困难 |
| 手里剑 | 8 | 普通 |
| 光矛 | 9 | 噩梦 |

12 把武器按"关卡 × 难度"两轴铺开，于是每一档难度通关都会**立刻**开出新的手感，
而不是只给一个数值奖励。这也是"推进难度"的第二条动机（第一条是槽位）。

两条门槛是"与"关系而不是"或"，是为了让难度真正成为必选项：
只推关卡不给难度，新装备一样拿不到。

## 五、两种继承，两种成本

这是本体系最容易做错的地方。

| 场景 | 是否继承 | 成本 | 原因 |
|---|---|---|---|
| **首次进入更高难度** | **默认继承** | 免费 | 噩梦敌人血量 ×3.3、数量 ×1.6，而玩家带的是未进化的**根形态** —— 不给继承纯属劝退 |
| **同一难度复玩** | 看激励视频 | 一次广告 | 此时玩家要的是"冲更高纪录"，带巅峰装备重来的动机最强，广告价值最高 |

实现落点在 `LevelFlow.openLevel()`：

```ts
const archive = SaveManager.loadArchive(levelId, t);
if (archive) {
    // 该难度通关过 → 弹 LOADOUT，玩家自己选：看广告继承 / 重新开始
    this._phase = 'LOADOUT';
    this.emitLoadout(this.buildLoadoutPayload(archive));
    return;
}

// 首次进入更高难度 → 直接免费继承上一难度通关时的装备，不弹面板、不请求广告
if (t > 1) {
    const lower = SaveManager.loadArchive(levelId, t - 1);
    if (lower) {
        this.enterLevel(levelId, t, lower.loadout, true, 'lowerTier');
        return;
    }
}
```

`LevelState.carrySource` 记录继承来源，HUD 与日志据此区分：

```ts
'none' | 'archive' | 'lowerTier'
```

### 为什么跨难度继承不能做成广告位

看起来"看广告才能打高难度"能显著提高 eCPM，但它会带来三个问题：

1. **提审风险**：把游戏机制（难度推进）做成广告门槛，容易被判定为强制观看广告。
2. **流失**：玩家打到困难关卡住 → 需要看广告才能继续 → 但看广告本身不能提升数值 →
   看完还是打不过 → 直接卸载。
3. **体验断裂**：难度递进应该是"我变强了所以能打更难"，而不是"我付了广告费所以能打更难"。

广告的位置应该留在**玩家已有明确动机的地方**（刷纪录），而不是**卡住玩家的地方**。

### 同一难度复玩仍然走广告，成本是否合理

合理，因为两个选项对玩家都是净收益：

- 看广告 → 带巅峰装备开局，冲纪录（明确收益）
- 重新开始 → 从初始装备开局，档案**保留**（没有损失）

`DROP_ARCHIVE_ON_RESTART = false` 保证了"重新开始"永远不删档，
玩家不会被"看了广告"和"清空数据"夹在中间。

## 六、存档：关卡 × 难度 双主键

```
mg_archive_<levelId>_<tier>      例：mg_archive_3_2 = 第 3 关困难难度档案
统计键 = "<levelId>_<tier>"       例：bestScores["3_2"]
```

**为什么必须按难度分开存：**
第 3 关的普通和噩梦是两个完全不同的挑战。混在一个键里，玩家打完噩梦回头看，
会发现普通难度的最高分被覆盖了 —— 纪录直接失效，"刷新纪录"这个复玩核心驱动也就废了。

### v1 → v2 迁移

老版本（`mg_archive_3` + `bestScores["3"]`）在 `migrateToV2()` 里整体补上难度维度 = 1：

```ts
mg_archive_3      → mg_archive_3_1   （原始字符串直接搬运，签名依然有效）
bestScores["3"]   → bestScores["3_1"]
maxTiers          → 所有已解锁关卡补 1
globalMaxTier     → 1
```

搬运的是**原始 localStorage 字符串**而不是重新序列化，所以老数据的签名不会被破坏，
迁移是原子且无损的。老玩家的通关记录、最高分、金币、装备等级一条不丢。

### v2 → v3 迁移

v3 引入了形态图（`formId` / `kind` / `talents` / `boostPercent` / `achievements` / `seenForms` …）。
存档里的 `(装备 id, stage)` 需要反查成新的 `formId`：

```ts
{ equipStates: [{ id: 'blade', stage: 2 }] }
  → { loadout: [{ formId: 'blade_rift', kind: 'weapon', exp: 0, lv: 3 }] }
```

反查靠 `evolveTo` 数组的**第一项是主线**这条约定逐级走 —— 这也是形态表里
`evolveTo` 顺序不能随意调的原因。迁移代码在 `SaveManager.migrateToV3()`，
测试覆盖在 `evolution_e2e.js`。

新增的字段（成就、图鉴、复玩加难记录）在老档上补默认空值，不清档、不重置进度。

## 七、数值标定实测

用 `BattleWorld` 真跑仿真（无渲染），模拟一个从零开始的玩家逐档推进：
`stats.hp` 随关卡累加、金币全投入局外升级（模拟真实玩家的花钱行为）、
形态按「通关结算 → 逐只发经验 → 升级时三选一」的真实规则攒出来。

> 复算命令：`node chain_probe.js aggr | dodge | stand`、`node difficulty_probe.js`。

### 第 1 关：三档难度的操作门槛（新号，无继承，站桩）

| 难度 | 远程怪比例 | 结果 |
|---|---|---|
| 普通 | 10% | 通关 4/4，剩 88/100 |
| 困难 | 24% | **战败 3/5** |
| 噩梦 | **42%** | **站桩战败（远程+精英+突进+冲锋复合压制）** |

结论：**新号站桩只能过普通**。从困难起就必须动起来 —— 因为远程怪比例从 10% 涨到 24% / 42%，
站桩就是纯挨打。同一个玩家只要肯走位，三档都能过。

（`difficulty_probe.js` 的 D 节就是这张表，改数值后重跑即可复核。）

### 完整推进链（三种操作水平各跑一遍，5 关 × 3 档 = 15 局）

| 操作水平 | 通关档数 | 卡在哪 |
|---|---|---|
| **进攻走位**（主动朝最近敌人切入） | **15 / 15** | 无 |
| 简单躲避走位（远离最近敌人） | 15 / 15 | 无 |
| 站桩不动 | 15 / 15 | 无 |

**链路上没有死结** —— 这是这次标定最重要的结论。任何一档难度如果打不过，
玩家的进度就永久卡死，那是灾难。

> ⚠️ **一个副作用被解决后的副作用**：把远程比例从 28% / 42% 压到 24% / 34%
> （第五轮按需求封顶 40%）之后，被动玩法的通过率从 13/15 提到了 **15/15** ——
> "噩梦难度必须走位"这堵墙被削平了。
>
> **第六轮修补**（用户原话"只有恶魔难度达到 42% 甚至更高，然后噩梦难度的怪种类和智能性加高"）：
> 噩梦 rangedRatio 从 0.34 提到 **0.42**，封顶从 0.40 提到 **0.45**；
> 普通 / 困难 基础值不变（0.10 / 0.24），加完所有加成也到不了 42% —— 符合"只有恶魔难度"；
> 噩梦档**新增三种敌人**（精英 / 突进 / 冲锋），普通 / 困难 不会刷出。
>
> 实测：被动玩法（站桩 / 简单躲避）回到 3/5 通关噩梦，
> 主动走位 5/5 通关。**"必须走位"这堵墙回来了**。

> 📌 **本块引用的 24% / 34% / 40% 均为第五轮的历史值，已作废。**
> 现行值只有一组：基础 **10% / 24% / 42%**，封顶 `RANGED_RATIO_MAX = 45%`（专门为噩梦档设），
> 与 `DifficultyConfig.DIFFICULTY_TABLE` / `RANGED_RATIO_MAX` 一致。
> 本块只作修订追溯用，不要按里面的数字调参。

第 2 关起通关耗时收敛到 7~12 秒，说明**成长曲线仍然快于难度曲线**，
符合"微信小游戏宁易勿难"的基调（用户明确要求"难度不要太大"）。

如果觉得后期太软，调参顺序是：

1. `DIFFICULTY_TABLE[].hpMul` —— 先加噩梦（3.3 → 3.8 之类），不动普通
2. `LEVEL_GROWTH` —— 0.10 → 0.13，让关卡间成长更陡
3. `EQUIPMENT_TABLE[].levels[].upgradeCost` —— 抬高局外升级成本，放缓战力增长
4. `EQUIP_SLOT_LIMIT` —— 从 4 降到 3，削弱后期强度（但会削弱"难度推进的回报"）

**不要动 `DIFFICULTY_EASE`** —— 那是全局旋钮，会把普通难度也一起调难，
破坏"不惩罚新手"的基调。

> ⚠️ 改完任何数值后，`chain_probe` 只看趋势，**不要拿它当平衡裁判**：
> 站桩模式系统性偏袒远程武器（不动的玩家近战永远够不着），
> 躲避模式又冤枉了移动向武器。武器之间的强弱交给 `balance_guard.js` 的机制模型守。

## 八、噩梦专有的三种敌人（第六轮新增）

> 把"噩梦更难"从单纯的"怪更硬更多"升级成"怪有性格"。
> 这三种怪**只在噩梦难度出现**，普通 / 困难完全不会刷出。
> 理由是：它们各自把玩家逼向不同的应对动作，
> 三种同时出现时玩家不可能靠单套走位套路撑过去。

| 种类 | 外观隐喻 | 血 / 速 / 特殊 | 逼迫玩家做的事 |
|---|---|---|---|
| **精英 (elite)** | 厚甲步兵 | 3x 血、0.7x 速、**护盾 = maxHp x 45%** | 持续输出，不能靠走位躲——打它必须站桩 |
| **突进 (swift)** | 敏捷斥候 | 0.7x 血、**1.7x 速** | 反应走位，看到它就要提前调整方向 |
| **冲锋 (charger)** | 蓄力野兽 | 1.2x 血、**蓄力 0.8s -> 冲刺 0.5s x 3.5 倍速、命中 x2 伤害** | 读招预判，看到蓄力就要侧移躲冲刺 |

### 占比

| 种类 | 噩梦档占比 | 设计意图 |
|---|---|---|
| 普通近战 | ~50% | 保留基础压力 |
| 远程 | 42% | 远程压制（沿用上一轮基础值） |
| 精英 | 8% | 少而肉，一关只刷 1~2 只，是持续压力源 |
| 突进 | 12% | 较多，足够多的"突然加速贴脸"练习 |
| 冲锋 | 5% | 更少，太多会让战斗变成躲蓄力圈 |

### 冲锋怪的三阶段状态机

```
1) 走近（chargeTimer == 0）
   -> 玩家进入 trigger 范围（kiteRange x 0.7）-> 进入蓄力

2) 蓄力（chargeTimer > 0）
   -> 几乎不动（speed x 0.3），锁住方向
   -> 蓄力 0.8 秒完成 -> 进入冲刺
   -> 玩家跑出 trigger x 1.4 -> 取消蓄力，回到阶段 1

3) 冲刺（isCharging）
   -> 朝 chargeDir 冲刺 0.5 秒（速度 = speed x 3.5）
   -> 撞到玩家 -> chargeDmg 单次高伤
   -> 时间到 -> 回到阶段 1
```

【为什么计时在状态机里减，而不是主循环里减】
主循环统一减所有 cd（atk / shot）省事，但 chargeTimer 必须用
`chargeTimer - dt <= 0` 判完成 —— dt 是浮点，主循环减过再判断
会出现 0.0003 之类的残留值，让"完成 -> 进入冲刺"这一支跳过去。
蓄力是"我曾经进入过这个状态"才有意义，所以计时收在子函数里。

### 实现落点

`data/BattleTypes.ts` — `EnemyState` 加 9 个新字段（shield / maxShield /
chargeTimer / chargeMax / chargeDir / isCharging / chargeDashLeft /
chargeSpeed / chargeDmg），`EnemySpawnSpec` 加 3 个比例参数。
`battle/BattleWorld.ts` — `buildSpawnKinds` 扩展为 5 类，`makeEnemy` 按
`kind` 决定血 / 速 / 护盾 / 冲锋参数，`updateEnemies` 分 5 个 case
（melee / ranged / elite / swift / charger）。

## 九、难度面板的文案要点

锁定态只写"未解锁"是无效反馈 —— 玩家不知道要做什么才能开。必须写成：

```
通关「普通」难度后解锁
解锁后可获得：出战槽位 +1 · 金币 ×1.8 · 远程小怪增多
```

即**把动作和目标绑在一起**。未通关的难度也要显示奖励预告，
让玩家在还打不到的时候就看见"困难能给 3 个出战槽位"。

`DifficultyConfig.describeTierReward(tier)` 负责生成这段文案，
`ui/DifficultyPanel.ts` 负责渲染。
