# 新手引导与首通教学体系设计

> 对应审计项 **A-2：完全没有新手引导 / 首通教学体系**。
> 本文档先定方案，再据此落地代码（`data/TutorialConfig.ts` / `core/TutorialManager.ts` / `ui/TutorialLayer.ts` / 各面板触发点）。

---

## 一、问题

此前游戏没有任何教学：玩家进入后不知道怎么移动、不知道目标是什么、遇到抽卡 / 锻造 / 属性克制 / 三选一 / 进化 / 难度 / 继承 / 复玩加难等系统时没有任何上下文，学习曲线陡峭、容易弃游。

## 二、两套体系的定位

| 体系 | 触发 | 形态 | 是否重复 | 目标 |
|------|------|------|----------|------|
| **新手引导**（Onboarding） | 首次进入游戏 | 线性、多步脚本化卡片 | 只看一次（`tutorials.newbie`） | 让玩家**立刻会玩**：这是什么→怎么操作→目标是什么→开始第一关 |
| **首通教学**（First-Encounter Teaching） | 第一次遇到某系统 | 单张上下文提示卡 | 每系统只看一次（按 id 去重） | 在**玩家真正需要**时解释一个系统，不打断、不重弹 |

两者互补：新手引导是"第一印象"，首通教学是"随用随教"。新手引导覆盖移动/目标/CTA；更细的系统解释全部交给首通教学，避免引导过长导致跳过率升高。

## 三、持久化

`PlayerProfile` 新增字段：

```ts
/** 已看过的教学（新手引导 / 首通教学），key = 教学 id，存在即"已看" */
tutorials?: Record<string, boolean>;
```

- `SaveManager.defaultProfile()` 初始化为 `tutorials: {}`；
- `SaveManager.migrateProfile()` 兜底 `p.tutorials = p.tutorials || {}`；
- 不依赖版本号升级（只是新增可选字段，老存档默认可安全迁移）。

## 四、架构

```
data/TutorialConfig.ts   所有文案集中地（NEWBIE_STEPS / FIRST_TIME_TIPS）
core/TutorialManager.ts  读取/标记已看；内容查询（纯逻辑，可单测）
ui/TutorialLayer.ts      纯代码构建的覆盖层（遮罩 + 卡片 + 按钮），运行时挂 Canvas
各 UI 面板 / 事件         首次出现时调用 TutorialLayer.showTipById(id)
```

**为什么 TutorialLayer 用代码构建 UI**：场景编辑器无法在本次开发流程中改动，且教学覆盖层应当"零依赖资源"。TutorialLayer 在 `onLoad` 时用 `Graphics` + `Label` 画出遮罩与卡片，并通过 `TutorialLayer.ensure()` 在 `Canvas` 下按需创建节点，无需在编辑器里挂预制体。

## 五、新手引导步骤（NEWBIE_STEPS）

1. **欢迎 + 目标**：这是一款"拖动走位 + 自动开火"的闯关游戏。击败敌人、攒金币与许愿水晶、解锁更高难度。
2. **操作**：按住屏幕拖动角色移动；角色会**自动攻击最近的敌人**，你只需要专注走位躲伤害。
3. **目标与产出**：清空本关全部敌人即通关。通关获得**金币**（去装备界面升级武器）与**许愿水晶**（去许愿抽更稀有的武器/防具）。
4. **CTA**：按钮"开始第 1 关" → 调用 `LevelFlow.inst.openLevel(1)` 进入首关。

> 移动 / 三选一 / 进化 / 通关等更细的内容交给首通教学，不塞进引导。

## 六、首通教学清单（按 id 首遇触发）

| id | 触发条件 | 教学要点 |
|----|----------|----------|
| `tip_move` | 首次进入战斗（且仅当新手引导尚未覆盖时补一句操作提示） | 拖动走位、自动开火、躲远程怪弹丸 |
| `tip_element` | 首次出现属性克制面板（CounterPanel.show） | 24 种属性互相克制，用克制武器打本关属性有伤害/金币加成；破防可无视克制 |
| `tip_reward` | 首次弹出三选一（REWARD 阶段） | 升级/拿新武器/拿辅助/点天赋，是变强的主要来源；合成会占用一个武器槽但可补选 |
| `tip_evolve` | 首次 HUD 出现"★可进化"或首次进化事件 | 攒经验让武器进化；分支进化需在三选一里选路线；合成两件合一更强 |
| `tip_clear` | 首次通关结算（SETTLE） | 金币升级装备、水晶去许愿、可挑战更高难度或复玩加难刷纪录 |
| `tip_equip` | 首次打开装备面板（EquipPanel.show） | 用金币升级出战武器的局外等级（永久生效） |
| `tip_gacha` | 首次打开许愿面板（GachaPanel.open） | 水晶抽卡获得武器/辅助/防具；保底与祝福值机制；高阶碎片可兑换专属 |
| `tip_forge` | 首次打开锻造面板（ForgePanel.open） | 突破升阶、属性石镶嵌、碎片合成、防具套装；材料全靠打关卡 |
| `tip_armor` | 首次打开锻造防具页 / 首次获得防具 | 四部位套装（头/身/裤/鞋），套装有专属属性，低阶可升到高阶 |
| `tip_difficulty` | 首次打开难度选择（DifficultyPanel.show） | 三档难度独立解锁，越高敌人越强但金币/水晶越多 |
| `tip_loadout` | 首次出现继承选择（LoadoutPanel.show） | 看广告继承上次通关装备；否则从初始数据开局 |
| `tip_replay` | 首次出现复玩加难（ReplayEnhancePanel.show） | 同一关可自选加难百分比，冲更高分与纪录 |
| `tip_achievement` | 首次打开成就面板（AchievementPanel.open） | 成就覆盖所有系统，是"把游戏玩一遍"的引导 |
| `tip_tree` | 首次打开进化图鉴（TreePanel.open） | 查"哪些武器能合成/进化成什么"，规划养成路线 |

## 七、触发时机表（与 LevelFlow 阶段 / 事件对应）

| 阶段 / 事件 | 触发 |
|-------------|------|

| `REWARD` 阶段首次 | `tip_reward` |

| `onLevelClear`（SETTLE，首次） | `tip_clear` |

| `GachaPanel.open` | `tip_gacha` |
| `ForgePanel.open` | `tip_forge` +（切到防具页时）`tip_armor` |
| `DifficultyPanel.show` | `tip_difficulty` |
| `LoadoutPanel.show` | `tip_loadout` |
| `ReplayEnhancePanel.show` | `tip_replay` |

| `TreePanel.open` | `tip_tree` |

## 八、防重复与克制

- 每个 id 仅弹一次：`TutorialLayer.showTipById` 内部先查 `TutorialManager.hasSeen(id)`，已看直接返回。
- 新手引导可一键跳过（"跳过引导"按钮），跳过即标记 `newbie` 已看。
- 首通教学不抢镜：新手引导进行中（newbie 未看完）时，不弹 `tip_move`（避免"怎么移动"讲两遍）；其余首通教学仍可在引导结束后正常触发。
- 覆盖层点击遮罩非卡片区域可快速关闭当前卡，但不影响"已看"标记（关了就算看过了，不重复弹）。

## 九、测试（已落地：`tutorial_e2e.js`，38 项全绿）

Node 端复用现有 verify 环境，覆盖：

1. 新手引导：非空多步、每步有 title/body、最后一步有 CTA、覆盖"操作/目标/产出"三要素。
2. 文案表：条目数、每条的标题与正文非空、正文长度足够（不是单词）。
3. ★ **触发点 ↔ 文案表双向一致**（本套件最有价值的一条）：扫描编译产物里所有
   `showTipById('x')` 调用，断言「每个触发 id 都有文案」**且**「每条文案都有人触发」
   —— 前者防"打错 id 导致提示静默不弹"，后者防"死文案"。
4. 路径断言：有入口调用 `startNewbie`；关键系统（克制/三选一/进化/通关/抽卡/锻造/防具/装备/图鉴）都有提示。
5. `TutorialManager`：`needNewbie` / `markSeen` 幂等 / `consumeTip` 只弹一次 / 不存在 id 返回 null / `getTip` / `allTipIds`。
6. 持久化：标记写进**签名存档**（载荷里可见 `"tip_tree":true`），清缓存后重新载入仍然记得、未标记的仍会弹。

## 十、与第九轮（防具套装）的关系

防具已是四部位套装模型（见 `防具套装系统设计.md`）。本体系的 `tip_armor` 直接解释该模型："四部位套装，套装属性 + 单件专属词条，低阶可升到高阶"，与新防具系统对齐，不引入任何旧的单件防具表述。
