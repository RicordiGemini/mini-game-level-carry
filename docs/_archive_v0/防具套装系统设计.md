# 防具套装系统设计（第九轮 + 第十一轮）

> 第九轮修复第八轮遗留的「防具缺局外等级轴、与武器不对称」问题。设计决策已与用户逐项确认（4 项）。
> **第十一轮增补 §9 / §10**：关闭复核时新发现的缺口 A-6（全属性石成死道具），落地隐藏养成线「万象线」→ 四件套「万象套」。

## 0. 设计决策确认

| # | 问题 | 决策 |
|---|------|------|
| 1 | 防具属性模型 | **抗性 + 词条双轨并存**：每件防具保留全 24 轴属性抗性（管减伤），同时新增「专属词条」（增益）与「套装属性」。 |
| 2 | 开槽机制 | 槽位 = 镶嵌「属性石」的孔。每次升阶 +3 孔；升到神话可一次性解锁前面累计的全部孔；「开孔」消耗许愿水晶。 |
| 3 | 词条阶梯 | 传说 7 / 神话 6 / 史诗 5 / 钻石 4 / 黄金 3 / 白银 2 / 青铜 1（基础专属词条数，随品阶递减）。 |
| 4 | 套装获取与激活 | 抽卡给**单件**（随机部位/随机套）；同套同部位穿 **2 件激活小套属性、4 件激活大套属性**（两段式）。 |
| 5 | 全属性石（240 碎片）怎么处理（第十一轮，A-6） | **走第四条路**：不镶孔、不做万能材料、不下架；改造成**隐藏**的四级养成线「万象线」，终点授予**四件套「万象套」（全部传说 / 24 轴抗性）**，且**不进任何卡池**。详见 §10。 |

## 1. 核心结构

### 1.1 四部位
防具按身体部位分为四类，全部进入防具池，可同时穿戴：
- `head` 头 · `body` 身体 · `pants` 裤子 · `shoes` 鞋子

### 1.2 套装（ArmorSetDef）
- 每套由一个 `setId` 标识，含 4 个部位各 1 件（共 4 件）。
- **数量**：青铜 5 套、白银/黄金/钻石/史诗/神话/传说 各 3 套 = 23 套 / 92 件。
- 每套有：
  - **2 件套装属性**（小套）：约半数基础词条。
  - **4 件套装属性**（大套）：完整基础词条（词条数 = 当前品阶阶梯值）。
  - **单件专属属性**：每件防具自带 1 条 innate 增益（「单个防具里面也有专属的属性」）。

### 1.3 品阶与武器对称
防具复用 `RarityConfig` 的 7 阶（青铜→传说）、品阶倍率 `rarityPowerMul`、镶嵌槽位 `raritySockets`。
- 抗性数值乘品阶倍率（沿用旧 `currentResist` 的软上限压缩，避免超过 100% 免伤）。
- 词条/套装属性增益乘品阶倍率。
- 升阶消耗同阶同部位装备（件数曲线同武器 `ascendCopiesOf`），金币曲线同武器。

### 1.4 基础词条阶梯（已确认）
| 品阶 | 传说 | 神话 | 史诗 | 钻石 | 黄金 | 白银 | 青铜 |
|------|------|------|------|------|------|------|------|
| 基础词条数 | 7 | 6 | 5 | 4 | 3 | 2 | 1 |

- 该数量 = 该品阶「4 件大套属性」的词条条数。
- 2 件小套属性 = 取前 `ceil(数量/2)` 条。
- 青铜 5 套因「从零开始」额外自由：可通过**添加材料**获得额外词条（见 §3.3）。

## 2. 数据模型（GameTypes）

```ts
export type ArmorPart = 'head' | 'body' | 'pants' | 'shoes';

export interface OwnedArmor {
  uid: string;          // 实例唯一 id（支持同 id 多份/多品阶）
  id: string;           // 防具部件定义 id，如 armor_dragon_head
  rarity: number;       // 0~6
  sockets?: (ElementId | null)[];  // 已镶嵌属性石（null=空孔）
  openedSlots?: number; // 已用水晶开出的额外孔数
}

// 穿戴：4 部位各指向一个 OwnedArmor.uid
export interface ArmorWorn {
  head?: string; body?: string; pants?: string; shoes?: string;
}

// PlayerProfile.armor
armor: {
  owned: OwnedArmor[];
  worn: ArmorWorn | null;
};
```

## 3. 养成轴

### 3.1 获取
- 防具池（gacha, `pool='armor'`）两段式随机：先定品阶（权重同武器），再在「该品阶全部套装部件」中按部件等概率抽 1 件。
- 抽到写入 `OwnedArmor{ uid, id, rarity, sockets }`；**该部位首次获得时自动穿上**（后续可在锻造界面自由换装）。
- **基础孔**：新到手/迁移得到的防具自带 `raritySockets(rarity)` 个空孔（品阶给的，免费，与武器对称）。
- 保底 `pityArmor`：连续抽到已拥有（同 id+同 rarity）达阈值（30）后下次必给未收集件。防具允许**重复持有**（重复件 = 升阶燃料），全收集判定用「不重复部件数」。
- **第四条途径（第十一轮新增）**：隐藏的「万象线」—— 碎片 → 全属性石 → 4 级递进 → 四件套「万象套」。
  **它不进防具池**（`allArmorPieces()` 恒为 92），因此是**唯一**一条不靠抽卡的整四件套获取途径。详见 §10。

### 3.2 升阶（与武器对称）
- `ascendArmor(uid)`：消耗同阶同部位装备 `ascendCopiesOf(rarity)` 件 + 金币 `ascendGoldOf(rarity)`，该件 `rarity+1`。
- **每次升阶 +3 镶嵌孔**（`sockets` 长度 +3）。
- 升到神话（rarity=5）时可一次性解锁前面累计的全部孔（即把 `openedSlots` 拉满到当前可用上限，无需再逐孔花水晶）。
- 升阶继承：抗性倍率、词条数、套装属性全部随 `rarity` 自动重算（与武器「升阶继承属性」一致）。

### 3.3 开槽与镶嵌
- **孔的来源**：基础孔 = `raritySockets(rarity)`（品阶给的）；升阶额外 +3/次；青铜 5 套还可用**材料**解锁额外孔（「添加材料给添加额外的词条」）。
- **开孔**：超过「已开出」的孔需用许愿水晶开（`openArmorSlot(uid)` 消耗 `CRYSTAL_PER_SLOT` 水晶，开 1 孔）。神话后可用累计孔免水晶。
- **镶嵌**：孔内镶「属性石」(`stone_<element>`)，获得该属性词条（与武器 `socketElement` 同源，材料可退）。
- 属性石词条 + 套装/单件专属词条 = 该件生效的全部增益。

### 3.4 青铜 5 套的自由度
青铜 5 套定位「从零起步」，比高阶套多一条成长线：
- 基础词条仅 1 条，但可用**突破材料**解锁额外孔（材料开孔不花水晶），靠堆砌孔+属性石追平高阶。
- 升阶路径仍通向其高阶形态（青铜→…→传说），不锁死。

## 4. 战斗聚合（ForgeManager）

`GameEntry` 仍只调三个函数，但内部改为聚合 4 部位：

- `currentResist()`：4 件穿戴防具的**全 24 轴**抗性，分别乘各自品阶倍率 + 软上限后**求和**（单维再压缩一次防溢出）。
- `armorBonus()`：4 件穿戴防具的「单件 innate + 套装 2/4 件属性 + 镶嵌属性石」汇总为 `ElementBonus`，乘各自品阶倍率。
- `armorCounterBreak()`：**恒返回 0** —— 本轮防具不再贡献破防。破防完全由武器承担
  （保持第八轮「没有任何单一路线能点满无视克制」的原则；早期草案曾设想"4 件破防求和"，已废弃）。
- 套装激活：统计穿戴中 `setId` 出现次数；同 setId ≥2 触发小套、≥4 触发大套（按该套 4 件穿戴件的**平均品阶**缩放套装属性）。

## 5. 存档迁移 v6 → v7

- 旧 `armor.owned`（string[] 或旧 OwnedArmor{id,rarity}）与 `worn: string` 退役。
- 旧单件防具 id（`armor_fire`/`armor_omni` 等）不再存在于新表，迁移时直接清退（旧防具属不同模型，无等价映射）。
- 新结构：`owned` 赋 `uid`（迁移时生成），`worn` 置 `null`（旧单件无法映射到 4 部位）。
- `SAVE_VERSION` 6 → 7，`migrateToV7` 在 `loadProfile` 时执行；老档缺字段补默认。

### 5.1 v7 → v8（第十一轮：补万象线进度字段）

- 新增 `PlayerProfile.omni?: { stage: number }`，`SAVE_VERSION` 7 → **8**，`migrateToV8` 在 `loadProfile` 时执行。
- **只补结构、不白送任何资源**：老档一律补 `{ stage: 0 }`；防具库、金币、材料分文不动（实测金币 100 → 100）。
- 坏档兜底：`stage` 非数字按 0；越界/负数被 clamp 到 `[0, OMNI_MAX_STAGE]`（实测 `'abc'` → 0、`99` → 4、`-5` → 0）。
- 见 §10.5。

## 6. UI

- **ForgePanel 防具区**：4 个部位槽位（头/身/裤/鞋），点击穿戴/卸下；选中单件显示其抗性、单件专属、镶嵌孔（开孔/镶石）、升阶预览。套装收集进度（同套已集几件、是否激活小/大套）。
- **GachaPanel 防具 Tab**：抽卡结果与「套装图鉴」进度（每套 4 件收集度），碎片兑换任选高阶部件。

**`armor_e2e.js`（第九轮 83 项 → 第十一轮 168 项）** 与 **`tutorial_e2e.js`（38 项）** 为新增套件；旧的防具断言在 `rarity_e2e` / `gacha_e2e` / `forge_e2e` 中改为新模型。
（第 11 节的 85 项万象线断言见 §10.7。）

- 套装/部位结构：23 套 × 4 件、每阶套数（青铜5/其余3）、部位权重与"每件只抗 1 轴"。
- 词条阶梯：大套词条数 = 7/6/5/4/3/2/1；小套 = `ceil(阶梯/2)`（用 `setBonusOf === roleBonus` 校验接线）。
- 2/4 件激活：同套 2 件只出小套、4 件出大套、**跨套不触发**（同 role 两套对比 exact 数值）。
- 升阶：+3 孔、品阶倍率继承（抗性上升）、消耗同阶同部位、不同部位不可当燃料、金币不足/满阶报错。

- 镶嵌/卸下：基础孔可直接镶、同属性不可重复、换属性退还旧材料、越界/空槽拒绝。
- 迁移：v6 旧档 → v7 新结构、**旧 id 清退**、悬空 worn 置空、补 uid 与基础孔。
- 战斗聚合：只穿 1 件 vs 穿满 4 件的抗性求和、传说品阶软上限仍 < 100%、防具不提供破防。
- 受影响：`gacha_e2e` / `forge_e2e` / `rarity_e2e` / `ui_e2e` 中旧防具断言已改为新模型；**全量 10 套 1159 项保持全绿**。

## 9. ✅ 本轮引入的缺口（A-6：全属性石失去消费方）—— 已于第十一轮关闭

第九轮把防具从"材料打造"改成"抽卡获取"，顺手移除了 `ForgeManager.craftArmor()` ——
但**忘了处理它消费的「全属性石」**，导致：

| 事实 | 位置 |
|---|---|
| `craftOmni()` 仍可用 **24 种碎片各 10 个（240 个）** 合成 `stone_omni` | `core/ForgeManager.ts` |
| `stone_omni` 全工程**只有产出（`bagAdd`）与 UI 展示，没有任何消费（`bagTake`）** | 全仓检索确认 |
| 原本唯一的消费方 `craftArmor()`（打造"万象镜甲"全属性防具）已在本轮移除 | `ForgeManager.ts` 文件头注释自承 |
| `ForgePanel` 原本还写着"★可以打造全属性防具"（已随本次复核修正为"★可以合成全属性石"） | `ui/ForgePanel.ts` |
| 第四轮承诺的"全属性防具破防 +15%"随 `armorCounterBreak() = 0` 一并作废 | `docs/锻造与属性设计.md` §八 已加作废标记 |

**结论**：玩家现在能花 240 个碎片造出一个**用不掉的道具**。功能缺口未关闭，只修了会误导玩家的文案。
（**该结论已被第十一轮推翻**——见下方"已关闭"，此处保留原文以便追溯当时的事实判断。）

**✅ 已关闭（第十一轮）**：用户拍板走"第四条路"——把万象镜甲改造成一条**隐藏的独立养成线**，
终点是四件套「万象套」（全部最高阶）。详见下面的 **§10 万象线**。
原候选（(a) 镶孔 / (b) 万能升阶材料 / (c) 下架）均**未采用**，保留在此仅作决策追溯。

## 10. 万象线（第十一轮：A-6 的关闭方案）

### 10.1 用户拍板原文与拆解

> 将万象镜甲变成一个隐藏合成逻辑，变成一个基础装备在装备升级的时候升级出来，
> 添加一条单独路线，这个路线从碎片开始慢慢升级，然后将最终的这个万象镜甲
> 变成一个四件套，万象套，然后整套都是最高阶的装备。

拆成四条可验证的需求：

| # | 需求 | 落地方式 |
|---|---|---|
| R1 | **隐藏合成逻辑** | 未满足可见条件前，UI / 图鉴 / 合成表**完全不出现**这条线（§10.4） |
| R2 | **一条单独路线，从碎片开始慢慢升级** | 独立养成链 `stage 0→4`，起点是 24 种碎片、逐级升（§10.3） |
| R3 | **最终变成四件套「万象套」** | 满级一次性授予 4 件（头/身/裤/鞋），**不进抽卡池**（§10.2） |
| R4 | **整套都是最高阶的装备** | 4 件全部 `rarity = 6`（传说），无需再升阶 |

### 10.2 数据（`data/ArmorConfig.ts`）

```ts
export const OMNI_SET_ID = 'armor_wanxiang';        // 万象套
export const OMNI_RARITY = 6;                        // 传说，四件全部
export const OMNI_RESIST_PER_AXIS = 0.03;            // 每件、每轴抗性基准（乘品阶倍率）
export const OMNI_ARMOR_SET: ArmorSetDef;            // ★ 单独导出，**不进 ARMOR_SETS**
export function omniPieces(): ArmorPieceDef[];       // 4 件
export function isOmniPiece(id: string): boolean;
```

- **四件全部 24 轴**：与 92 件常规防具"每件只 1 轴"不同，万象套每件都铺满 24 轴
  —— 这正是"万象镜甲 = 永远不用换装"这条身份的延续。
- **每轴抗性 0.03 × 品阶倍率 3.30 = 0.099 / 件，四件合计 0.396 / 轴**，
  远低于 `RESIST_MAX = 0.75`，**不给免疫**。
- **"越广越薄"实测成立**（同口径实测，`currentResist()` 的软压缩之后）：

  | 套装 | 品阶 | 轴数 | 每轴抗性 | 总抗性 |
  |---|---|---|---|---|
  | 烈焰套（青铜 · 单轴） | 0 | 1 | 0.420 | 0.420 |
  | 龙裔套（钻石 · 双轴） | 3 | 2 | 0.425 | 0.850 |
  | 终焉套（传说 · 三轴） | 6 | 3 | 0.850 / 0.628 / 0.370 | 1.848 |
  | **万象套（传说 · 全轴）** | 6 | **24** | **0.396** | **9.504** |

  万象套的**每轴**抗性是上表里最低的（0.396），但**总抗性** 9.504 远超任何常规套
  —— **它是终局装备，本就该是"最广但不是最厚"的通用解**：追求"永远不用换装"就要付"每轴薄"的代价。
- **不进池**：`allArmorPieces()` 仍为 **92**，`poolIds('armor')` 仍为 92 件；
  `getArmorDef()` / `getArmorSet()` 同时检索隐藏套，所以万象套可被查询、穿戴、升阶（虽然已满阶）。
- 附带修正：`ArmorConfig` 文件头与 `ArmorPieceDef.resist` 注释里的"6 维抗性"是第四轮残留，
  已改为"24 轴"。

### 10.3 养成链（`core/ForgeManager.ts`）

| stage | 阶段名 | 消耗 | 产出 |
|---|---|---|---|
| 0 | （未开始，隐藏） | — | — |
| 1 | 万象·碎片之核 | 1 个全属性石 + 6,000 金币 | 进度 |
| 2 | 万象·镜胚 | 1 个全属性石 + 12,000 金币 | 进度 |
| 3 | 万象镜甲 | 1 个全属性石 + 24,000 金币 | 进度 |
| 4 | **万象套** | 1 个全属性石 + 48,000 金币 | **授予 4 件传说万象套并自动穿戴空位** |

- 合计 **4 个全属性石 = 24 种碎片 × 10 × 4 = 960 碎片 + 90,000 金币**。
  这是全游戏最贵的一条养成线，与"最高阶装备"的定位相称。
- **起点就是"从碎片开始"**：碎片 → `craftOmni()` 合成全属性石 → 逐级升级。
  `craftOmni()` 与 `canCraftOmni()` **保持原样可用**（不再改动语义）。
- **这就是 A-6 的关闭**：全属性石第一次有了真正的消费方，不再是死道具。
- 拒绝条件（都要 `ok:false` 且**不扣任何资源**）：满级、全属性石不足、金币不足。
- 幂等：满级后再调 `advanceOmni()` 返回失败，不重复发装备。

**API**

```ts
export const OMNI_MAX_STAGE = 4;
export const OMNI_STAGE_NAMES: string[];           // ['未开始','万象·碎片之核','万象·镜胚','万象镜甲','万象套']
export function omniStage(): number;               // 读档，clamp 到 [0,4]
export function omniStageName(): string;
```

### 10.4 可见性（R1「隐藏合成逻辑」）

```ts
omniVisible() = omniStage() > 0
             || (stoneBag()[OMNI_STONE_ID] || 0) > 0
             || canCraftOmni();
```

- 三条任一成立才可见：**已经开始 / 手里有全属性石 / 材料够合成全属性石**。
- 未满足 → ForgePanel 不渲染该区块 → 玩家在凑齐 240 碎片之前**根本不知道有这条线**。
- 一旦可见就**永久可见**（stage > 0 是单调递增的），不会"看着看着消失"。

### 10.5 存档与迁移
