# 战斗层设计：拖动走位 + 五种瞄准方式 × 十种打击形状

这一层解决的是"玩家在关卡里到底怎么动、怎么打"。

核心设计是一句话：**攻击方式由武器类型与形态共同决定，玩家换一把武器就等于换一套操作手感。**

两个维度是正交的 —— `瞄准方式` 决定"打谁"，`打击形状` 决定"打几个"。
12 把武器是这两个维度的 12 种具体取值，形态进化还可以改写其中任一维度（例如"铁剑 → 全屏剑雨"
就是把瞄准方式从 `FRONT` 换成 `SCREEN_ROLL`）。

---

## 一、五种瞄准方式

需求里那串描述 ——「有的只有前攻击，有的可以锁定，有的根据移动方向攻击，有的根据最近距离攻击，有的是全屏滚动」—— 在代码里是一个枚举：`AimModeId`。

它们的**本质区别是"目标信息从哪来"**：

| 瞄准方式 | 取值 | 方向来源 | 有记忆？ | 需要玩家操作吗 | 对应武器 |
|---|---|---|---|---|---|
| 前向 `FRONT` | 0 | 玩家朝向 | — | **必须**走位对准 | 铁剑 |
| 锁定 `LOCK_ON` | 1 | 锁定的敌人 | ✅ 目标死/出射程才换 | 不需要 | 短弓 |
| 移动向 `MOVE_DIR` | 2 | 拖动方向 | ❌ 实时跟随 | 需要（决定方向） | 铁锤 |
| 最近 `NEAREST` | 3 | 最近的敌人 | ❌ 每次重算 | 不需要 | 冰晶球 |
| 全屏 `SCREEN_ROLL` | 4 | 无方向 | — | 不需要 | 回旋轮 |

### 最容易混淆的三个

`FRONT` / `NEAREST` / `LOCK_ON` 都能"打到敌人"，但手感完全不同：

- **FRONT** —— 「我朝哪打哪」。完全不索敌，背后有敌人也照挥不误，玩家可以故意打空。命中 100% 由走位决定，是三者中唯一有操作门槛的。
- **NEAREST** —— 「哪近打哪」。每帧重算，两个敌人交替靠近时弹道会左右横跳。
- **LOCK_ON** —— 「锁住不放」。目标死了或跑出射程才换，弹道稳定，但可能追着一个远目标跑。

这三条路必须都配得出来，否则"换武器 = 换手感"就是空话。

### 射程：统一按全屏来

索敌射程由 `BattleWorld.engageRange` 决定，**默认就是场地对角线**（720×1280 → 1469px）：

- 屏幕上任何位置的敌人都够得着，不会再出现"看得见打不到、只能等敌人走进射程"这种憋屈手感。
- 想给某关做"够不着就不开火"的克制手感，给 `BattleSetup.engageRange` 传一个小值即可。

武器的差异保留在**判定体形状与打击尺度**上（近战要贴身、法球穿透、滚轮横扫），
而不是靠"谁够得着"来区分 —— 后一种差异玩家只会当成 bug。

### 射程外就解锁 + 停火

`LOCK_ON` / `NEAREST` 共用一条规则：目标超出 `射程 × AIM_RANGE_SLACK(1.6)` 时

- **解锁**（`lockedId` 归零）、**停火**（本次攻击 `skip`），而不是对着打不到的目标空挥；
- 目标回到射程内立刻恢复锁定。

默认射程是全屏，所以这条规则平时不会触发 —— 它是一道**安全网**：一旦关卡把射程调小，
或者将来加了相机、敌人跑到可视范围外，武器不会白白浪费弹药。
`FRONT` 和 `MOVE_DIR` 不受此约束 —— 它们本来就允许打空，那是玩家主动的选择。

### 弹道飞行距离：不去打空气

`WeaponSpec.range` 现在只管**打击尺度**（近战够不够得着、剑气多宽、震荡波扩多大），
**不再决定够不够得着**。弹道能飞多远由 `AttackFactory.travelDist()` 单独算：

```
有目标：min( 全屏射程, max( 武器射程, 目标距离 + AIMED_SHOT_TAIL(90px) ) )
无目标：全屏射程
穿透弹：全屏射程（它的设计意图就是一路贯穿全场）
```

三条规则各自解决一个问题：

1. **`目标距离 + 尾巴`** —— 保证「锁定了必定打得到」。之前子弹寿命直接按武器射程算，
   会出现**锁定 400px 外的敌人、子弹飞到 337px 就凭空消失**，玩家看到的是"锁定了却打不到"，
   这是最典型的假 bug 来源。
2. **`max(武器射程, …)`** —— 武器射程变成弹道的**最短飞行距离**，
   进化表里的「攻击距离%」因此依然有意义（飞得更远 = 顺路能扫到更多敌人）。
3. **`min(全屏射程, …)`** —— 上限就是场地对角线，不会飞出屏幕外做无用飞行。

## 二、武器类型 → 瞄准方式的映射

写在 `EquipmentConfig.ts`，一行一件：

```ts
铁剑 blade   → AimModeId.FRONT        只有前攻击，靠走位对准
短弓 bow     → AimModeId.LOCK_ON      锁定目标持续追踪
铁锤 hammer  → AimModeId.MOVE_DIR     朝拖动方向砸出震荡波
冰晶球 orb   → AimModeId.NEAREST      自动打最近的敌人
回旋轮 wheel → AimModeId.SCREEN_ROLL  横扫整屏，无需瞄准
```

### 形态可以覆盖它

`FormNode.aimModeId` 是可选的覆盖位。不填就沿用武器类型的默认值，填了就换。

设计上用它做了「**终局形态 → 变全屏割草**」：

```
铁剑   铁剑/淬锋剑/阔刃剑  前向        ← 操作门槛还在，逼玩家学走位
       裂空剑/环刃剑       前向        （剑气变大，但方向还得自己给）
       天罚剑/斩星剑       前向 → 全屏  ← 覆盖为 SCREEN_ROLL，门槛消失
       创世刃（复玩限定）   全屏

铁锤   铁锤/震地锤         移动向
       裂地锤/震荡锤       移动向      （震荡波以自己为中心扩散）
       灭世锤              全屏陨石    ← 覆盖为 SCREEN_ROLL
```

> 注意这是**树而不是链**：同一层的两个形态（淬锋剑 / 阔刃剑）走的是不同路线，
> 前者继续单点爆发，后者转向范围覆盖。完整结构见 [装备与进化设计.md](装备与进化设计.md)。

这条曲线的好处：**前期靠操作换取强度，后期用强度换回省心**。成长感明确，而且不会一开始就把玩家劝退。

## 三、拖动走位

`ui/DragInput.ts` 实现了两种模式，用 `dragMode` 切换：

### JOYSTICK（默认，推荐）

相对拖动 / 虚拟摇杆。手指按下记起点，方向取「当前点 − 起点」，力度正比于拖动距离。

- 手指可以放在屏幕任意位置，**不遮挡角色**
- 力度可调（拖得远跑得快），走位精度高
- 死区 14px，避免手指微抖导致角色乱飘

### FOLLOW

角色朝手指位置跑，越远越快，进入到位半径（100px）就停下。

- 直觉最强，新手一秒上手
- 代价是手指会挡住角色，精细走位稍差

两种模式最终归一到同一个输出：**方向 + 强度**。战斗层因此完全不需要知道用的是哪种输入方式。

### 一个必须知道的坑

**手指按住屏幕不动时，系统不会再派发 `TOUCH_MOVE` 事件。**

如果角色移动只由触摸回调驱动，玩家按住不动的那一刻输入就会丢失，角色半路停下 —— 这是个在真机上必现、在编辑器里却不容易复现的问题。

解法是 `DragInput.compute()` **每帧轮询重算**，而不是只依赖回调。`FOLLOW` 模式更是必须轮询：角色一边跑一边靠近手指，方向得实时重算才不会绕着手指画圈。

`BattleWorld._inputHold` 保留了 0.12 秒的安全网 —— 万一事件彻底丢失，角色会在 0.12 秒后自行停下，而不是一直朝某个方向跑。

## 四、战斗循环

`battle/BattleWorld.ts` 每帧的顺序（顺序错了会出现穿模和重复结算）：

```
1. 读取拖动输入 → 移动玩家 → 更新朝向
2. 每件武器独立结算冷却 → 瞄准 → 生成判定体
3. 判定体移动 + 命中判定 + 伤害结算
4. 敌人 AI：朝玩家移动，贴身则按间隔攻击
5. 清理死亡实体
6. 判定胜负
```

### 每件武器独立开火

玩家可以同时带 2 件装备，它们各自按自己的瞄准方式工作。铁剑在前方挥砍的同时，短弓锁定着另一个目标在射箭 —— "换武器 = 换手感"这件事才真正成立。

### 判定体而不是子弹

近战挥砍、震荡波、陨石这些并不是飞行物，但它们和子弹共享同一套生命周期：**出现 → 存在一段时间 → 判定命中 → 消失**。统一成 `Projectile` 之后，战斗循环里只有一条 update 分支。

几个特殊字段：

| 字段 | 用途 |
|---|---|
| `attachDist` | 挂靠在玩家身上（沿朝向），走位时判定跟着动。挥砍/剑气/震荡波用它 |
| `growRate` | 半径持续变大。震荡波用它实现扩散 |
| `delay` | 落地延迟。陨石/剑雨先用空心圈预警，给玩家反应时间 |
| `pierce` | 剩余穿透数，`-1` = 无限穿透 |
| `chainLeft` | 连锁剩余跳数，命中后跳向下一个敌人 |

### 敌人设计的两条底线

1. **敌人移速（92）必须明显低于玩家移速（330）**。这是个走位游戏，敌人跑得比玩家快的话走位就失去意义，玩家会被无限贴脸。压力应该来自"数量多、多方向来"，不是"跑得快"。
2. **不从下边缘刷怪**，且出生点与玩家保持 260px 以上。贴脸刷怪在走位游戏里是致命的体验问题。

### 分波生成

`batchSize` / `batchInterval` 控制分批投放（默认 3 波）。一开局就把敌人全放出来，玩家会被瞬间围殴致死。

### 固定随机种子

`setup({ seed })` 固定后，整场战斗可完整复现。关卡号会被当作种子（`1000 + levelId × 977`），因此"第 7 关打不过"这个问题是可以稳定复现并定位的。

## 五、局内成长如何当场生效

这是整套设计里最关键的一次对接。注意 v3 起**进化不再自动发生** ——
经验攒够只会"攒出一张卡"，真正的形态变化由玩家在三选一里做决定（见 [装备与进化设计.md](装备与进化设计.md)）。

```
击杀敌人
  → BattleWorld 触发 onEnemyKilled
      → GameEntry 调 LevelFlow.onEnemyKilled()
          → 加分 / 掉资源 / gainExp()
              → 升了级？→ openReward() 组装三张卡
                  → phase = 'REWARD' → emitReward()
                      → RewardPanel 弹出；GameEntry.update() 直接 return（战斗真的冻结）
                          → 玩家选卡 → LevelFlow.chooseReward(i)
                              → applyReward() 改局内 build
                                  → 发 onEvolve → GameEntry 灌新参数给战斗层
                                      → BattleLayer.syncWeapons() 就地更新武器
                              → 合成？→ 立刻再开一次三选一（补选）
                              → 否则 → phase = 'PLAYING'，战斗继续
```

两处容易踩的点：

1. **冻结必须是"真的不推进世界"，而不是"不画"**。
   `GameEntry.update()` 在 `REWARD` / `REPLAY_BOOST` 阶段直接 `return`，
   如果只是把面板盖在画面上而世界继续 tick，玩家会在选卡时被围殴致死。

2. **`REWARD` 显示战斗层，`REPLAY_BOOST` 不显示**。
   `REWARD` 是**战斗中**弹出来的，背景留着刚打出来的战场最连贯；
   `REPLAY_BOOST` 是**进关之前**弹出来的，此时战斗层里只有上一关的残留画面，
   显示出来会让玩家误以为"我已经开打了"。这两个阶段不能用同一个标志位。

`syncWeapons` 按 `equipId` **就地合并**，并特意保留两个字段：

- **保留冷却** —— 否则进化瞬间会白送一发，手感很怪
- **保留锁定** —— 进化不该丢掉当前锁定的目标

战斗层（`battle/`）不认识"装备等级""形态图""合成"，装备系统也不认识"敌人""判定体"。双方只通过 `WeaponSpec` 与 `BattleSetup` 两个纯数据接口交互。

## 六、阵型：让"每关最合适的武器不一样"真的成立

`LevelAffinity.formationForLevel(levelId)` 给每关一个 `FormationKind`
（`scatter` / `line` / `cluster` / `swarm`），战斗层的刷怪位置生成会照着它摆位。

| 阵型 | 刷怪位置特征 |
|---|---|
| `scatter` | 从各个方向零散出现，彼此离得远 |
| `line` | 倾向于排成一列推进，前排会挡住后排 |
| `cluster` | 挤成一团冲过来，越打越密 |
| `swarm` | 数量多但各自为战，满场乱窜 |

**为什么必须让阵型真的改位置，而不只是改一句推荐文案**：
如果推荐武器只是 UI 上的一句话、而怪永远从同一个分布里冒出来，
玩家第一次不信、第二次就无视了。

要做到"每关最合适的武器不同"，必须同时满足两条：

1. 关卡真的**有一种形状**
2. 那种形状真的**偏爱某些武器**（贯穿打一列很强、范围打散兵很弱）

两条来自同一张表（`LevelAffinity`），所以文案和数值不会互相打架。

阵型对武器强度的影响也在 `balance_guard.js` 里被建模成了"覆盖率红利"：

```js
const CLUMP = { scatter: 0.25, line: 0.55, cluster: 1.0, swarm: 0.8 };
const covEff = 1 + (coverage - 1) * CLUMP[formation];
```

覆盖率 1.8 的意思是"一次挥砍平均打到 1.8 个敌人"，
但敌人零散分布时场上根本没有 1.8 个敌人挨在一起，覆盖率就退化成 1。
**这张表是"阵型"这个概念唯一真正的数值落点** ——
如果所有阵型都用同一个系数，"每关最合适的武器不一样"就只是文案上的。

## 七、战斗修正：天赋与辅助装备怎么作用到每一发攻击

天赋与辅助装备不占武器的打击节奏，它们汇总成一个 `CombatModifier`
（见 `FormGraph.aggregateModifier`），在 `buildWeapons` 时下发到每一件武器：

| 字段 | 作用点 | 备注 |
|---|---|---|
| `atkPct` | 单发伤害乘算 | 与形态 `atkPct` 相加后再乘 |
| `atkSpeedPct` | 缩短 `interval` | `interval = base / (1 + atkSpeedPct)`，下限 0.2s |
| `critRate` / `critMul` | 命中时判定暴击 | 默认 `critMul = 2.0` |
| `lifesteal` | 造成伤害的一部分回血 | 每件武器各自结算 |
| `rangePct` | 放大 `range` | 影响近战够不够得着、剑气多宽 |
| `extraShots` | 额外弹道数 | 每次攻击多打几发 |
| `maxHpFlat` | 生命上限 | 进场时加到 `playerHp` |
| `shield` | 护盾值 | **走 `setup` 而不是武器表** |
| `thorns` | 荆棘反伤 | 同上 |

### 为什么护盾和荆棘要单独走 `setup`

它们是**玩家被打时**生效的属性，不是"这把武器打出去的效果"。
挂在武器上会有两个问题：

1. 合成会吃掉一把武器，挂在它身上的护盾就一起没了 —— 玩家会觉得凭空丢了东西
2. 一把武器都不带时（理论上）护盾会失效

所以 `BattleLayer.begin(cfg, weapons, hp, hooks, extra)` 的第五个参数
`{ shield, thorns }` 专门传它们，最终落到 `BattleSetup` 上。

护盾在血条上方单独画一条，受到的伤害**先扣护盾再扣血**
（`BattleStats.shieldAbsorbed` 会统计被护盾吃掉的量）；
荆棘只在**近战接触**时反伤 —— 远程弹丸打到身上不触发，
否则"站着不动弹死全场"会变成一种无风险的挂机策略。

## 八、渲染层

`ui/BattleLayer.ts` 用 `Graphics` 直接画圆和矩形，**零美术资源就能跑通完整玩法**。

这是一个刻意的取舍：预制体方案需要先做一套美术资源，工程拿到手跑不起来。用 Graphics 可以先验证手感和数值，等玩法定下来再逐个换成预制体 + 序列帧。

配色即语义，调试时一眼可辨：

| 对象 | 颜色 |
|---|---|
| 玩家 | 蓝色实心圆 + 朝向短线 |
| 敌人 | 红色实心圆（被击中闪白，受伤后显示血条） |
| 锁定目标 | 红色双环标记 ← **让"锁定"这个瞄准方式和另外四种一眼区分开** |
| 近战/剑气 | 黄 |
| 弹丸 / 穿透 | 绿 / 青 |
| 震荡波 / 陨石 | 橙 / 深橙 |
| 剑雨 | 紫 |
| 连锁闪电 | 蓝 |
| 全屏滚轮 | 粉 |
| 落地预警 | 白色空心圈 |

**朝向短线**是"前向攻击"能不能命中的唯一视觉依据，不能省。

## 九、调参入口

| 想调什么 | 改哪里 |
|---|---|
| 五种瞄准方式的取目标逻辑 | `battle/AimResolver.ts` |
| 各武器打击尺度 / 攻击间隔 | `EquipmentConfig.WEAPON_BASE_RANGE` / `WEAPON_BASE_INTERVAL` |
| 各攻击形态的判定体尺寸、速度 | `battle/AttackFactory.ts` |
| 玩家移速、碰撞半径、战场尺寸 | `battle/BattleTypes.ts` 顶部常量 |
| 敌人移速 / 攻击间隔 / 波次 | `data/LevelConfig.ts` |
| 开火射程（默认全屏） | `BattleSetup.engageRange`（不传 = 场地对角线） |
| 瞄准射程余量 | `AimResolver.AIM_RANGE_SLACK`（默认 1.6） |
| 制导弹道的收尾余量 | `BattleTypes.AIMED_SHOT_TAIL`（默认 90px） |
| 摇杆手感（死区、半径） | `DragInput` 组件属性面板 |

**关于 `WeaponSpec.range` 的语义变更**：它现在只表示"这件武器打出去长什么样"的尺度，
与"够不够得着"无关。如果想让近战也能隔屏打人（不推荐，会让武器失去差异），
把 `WEAPON_BASE_RANGE.blade` 调大即可。

### 战斗层逐条验证

- 拖动走位：位移量、力度缩放、方向归一化、边界钳制、事件丢失安全网
- 前向：正前方命中、**背后完全打不到**、转身后能打到
- 移动向：向上拖动只打上方、改向下拖动只打下方
- 最近：只打近的，远的完全不碰
- 锁定：**出现更近的敌人也不换目标**（与"最近"的分水岭）、目标死亡后换、出射程解锁并停火、回射程恢复
- 全屏：全程零输入命中全场
- 射程：默认等于场地对角线、对角最远处的敌人也被锁并被击中、弹道在目标身后收尾、
  武器射程更长则弹道飞得更远（攻击距离% 仍生效）、目标比射程远时依然够得到、
  无目标时飞满全屏、穿透弹贯穿全屏、短射程武器的打击尺度不受全屏射程影响
- 形态热更新：`syncWeapons` 后伤害立即提升，且保留冷却与锁定
- 分波：开局只放一批、间隔后放第二批、出生点满足安全距离、固定种子可复现
- 远程小怪：维持射击间距、玩家贴近时后撤、弹丸按速度飞行不是瞬间命中、
  数量随难度递增、第一波里就混有远程怪
- 战斗修正：暴击、护盾优先吸收、荆棘只对近战反伤、额外弹道数量、攻速缩短间隔

### 测试过程中抓到的真问题

1. **无敌人的战场在第一帧就判定通关**，导致后续 update 全部提前返回。虽然线上 `enemies` 恒 ≥ 4 不会触发，但它暴露了 `checkEnd` 缺少"开局保护"。
2. **锁定目标在射程外仍然持续开火**，白白浪费弹药并让玩家困惑。已改为射程外解锁 + 停火。
3. **弹道寿命按武器射程算**，导致锁定 400px 外的敌人时子弹飞 337px 就消失 —— 玩家看到的是"锁定了却打不到"。已改为按全屏射程飞行，并在目标身后 90px 收尾。
4. **三连射的散布角太大**（±12°，三发飞过 200px 后相距 42px，比敌人半径还大），
   导致"靠频率压死敌人"的武器对单目标时其实只有一发能中，频率优势直接腰斩。已收紧到 7°。
5. **巨镰在所有阵型里都是最优解**：它是 `SWEEP`（半径 = 射程×0.7、命中范围内全部敌人），
   却只有 0.72s 间隔，而铁剑同为"近身全命中"半径只有 0.5×射程。
   结果是"每关最合适的武器都不一样"这个设计目标根本不成立。已把间隔拉到 0.95s 并下调伤害。
6. **光矛是长枪的严格上位替代**：两者都是 `PIERCE`，但长枪是 `FRONT`（要靠走位对准、会打空），
   光矛是 `LOCK_ON`（自动瞄准、从不落空）且射程更长。硬数据显示长枪 11 发只打出 70 伤害
   （约 36% 的挥击打空），光矛 8 发打出 120 伤害。已给 `WeaponSpec` 加 `pierce` 字段：
   长枪最多穿 5 个（它是贯穿专家）、光矛只穿 3 个，并把光矛间隔 0.95s → 1.35s。
   **教训：`PIERCE` 不能所有武器统一给一个穿透数，"能不能自动瞄准"必须参与定价。**
7. **三连射的实际 DPS 被高估了一倍**：`AttackFactory.buildBullet` 对 `count > 1` 的攻击
   有 `damage × 0.62` 的衰减，而平衡脚本一开始漏算了这一项，于是把飞刃与手里剑
   误判成"全表 DPS 偏低"而错误上调。修正后回退（`dagger 5→4`、`shuriken 6→5`）。
   **教训：任何"每次攻击多发"的形态，都必须按 `多发 × 单发衰减 / 间隔` 计算真实 DPS。**

还有一个是在写输入层时发现的设计问题：**手指按住不动时没有 `TOUCH_MOVE` 事件**，只靠回调驱动会让角色半路停下 —— 已改为逐帧轮询。
