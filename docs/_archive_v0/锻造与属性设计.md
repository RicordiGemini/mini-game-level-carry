# 锻造 · 属性 · 防具 —— 设计说明

这一章覆盖第四轮新增的三套系统：**武器突破等阶**、**属性材料**、**防具抗性**，
以及把它们串起来的**关卡属性编排**与**无视克制**。

它们回答的是一个老问题：**同一把铁剑，为什么打第 1 关和打第 15 关应该用不同的配装？**
上一轮用"武器类型适配"回答了一半（成列关适合贯穿），这一轮用"属性"回答另一半。

> **本轮把属性从 6 种扩到 24 种，参考《洛克王国》。**
> 洛克现行版本是 18 种（普通/火/水/草/电/冰/石/土/机械/翼/武/毒/虫/幽/龙/恶魔/光/萌），
> 按需求再补 6 种：金属性、剑、木、风、空间、时间。

---

## 一、为什么扩到 24 种，以及代价

6 种属性时玩家两局就打透了，属性材料很快变成"每种都攒一点、镶哪都一样"。
洛克王国的辨识度来自**每种属性都有独立的性格**：火就是爆、水就是持续、机械怕火、龙怕冰。

但这个规模带来一条**不可省的实现约束**：

> **24 种属性下，UI 必须实时把克制关系标出来。**
> 6 种时玩家边玩边学就能记住；24 种时 24×24 的表不可能靠脑子记 ——
> 不把"我这套武器打这一关到底是什么关系"直接写出来，
> 属性系统就退化成查字典，玩家被属性克制 5 次之后就会放弃镶嵌。

所以新增了两处**必需**的显示：
- `ui/CounterPanel.ts` —— 对局角落常驻，显示本关属性 + 逐颗镶嵌的实际倍率 + 破防
- 关卡确认页（难度面板标题下方）—— 直接列出"本关怪物属性"

`石 / 时间`（无视抗性）、`虫`（连锁）、`龙`（对高血量加伤）、`金属 / 龙`（贯穿 +1）。

## 三、克制表：单表推导 + 三类特殊关系

只写一张 `COUNTERS`（X 克制谁），**抵抗关系由它反推**：

```ts
resistedBy(X) = 所有满足 X ∈ COUNTERS[Y] 的 Y
```

洛克原表是 18×18 的双向手写表，而手写必然出现"A 克 B 但 B 也克 A 却倍率不同"的矛盾。
反推从根上杜绝这种不一致 —— 有测试逐对校验两者不可能矛盾。

三类特殊关系单独声明，不混进主表：

| 类型 | 关系 | 语义 |
|---|---|---|
| **双向克制** | 光 ↔ 幽、空间 ↔ 时间 | 双方攻击对方都吃 ×1.6，**只算一次**（不叠成 2.56） |
| **同属性互克** | 龙克龙、幽克幽（洛克设定） | `COUNTERS` 严禁自指，所以单独一个 `SELF_COUNTER` 集合 |
| **无克制** | 普通系不克任何（洛克设定） | 但会被武 / 石 / 机械克制，所以它有弱点 |

### 倍率

| | 本作 | 洛克 | 为什么不同 |
|---|---|---|---|
| 克制 | **×1.6** | ×2 | 洛克是回合制，看得见下一招；我们是实时走位，×2 会被当成 bug |
| 被克 | **×0.9** | ×0.5 | 同上 |
| 多属性叠加 | 相乘，**封顶 ×2.0** | 双属性 ×4 | 4 阶武器镶 4 个克制属性能叠到 1.6⁴ = 6.5 倍，那是"一套装备通吃"而不是"配装决策" |

**洛克的"光属性免疫克制"没有实现** —— 它依赖双属性精灵才有意义，
我们的敌人只有 1 种属性，搬过来等于给某一种属性开了无双还说不清为什么。

## 四、无视克制（破防）

需求原文："支持装备够好的时候, 可以直接无视克制"。

```
破防 = (武器等级 − 1) × 3% + (突破等阶 − 1) × 6% + 镶嵌颗数 × 3% + 防具加成
上限 90%
```

多把武器时取**最高那一件**，不是求和 —— 求和会让"三把武器各破防 30%"直接满防，
那等于把"专精一把"的路堵死了。

| 配置 | 破防 |
|---|---|
| 新武器 | 0% |
| 只升满金币（5 级） | 12% |
| 只升满材料（5 阶） | 24% |
| 满级 + 满阶 + 4 颗镶嵌 | 48% |
| ~~再加上全属性防具（+15%）~~ | ~~**63%**~~ |
| 硬上限 | 90% |

> **⚠️ 第九轮已作废"全属性防具 +15%"这一行**：防具改为抽卡获取后不再参与破防
> （`ForgeManager.armorCounterBreak()` 恒返回 `0`），防具只走"抗性 + 专属词条 + 套装属性"这条轨。
> 因此当前破防的上限是 **48%**（满级 + 满阶 + 4 镶），且防具不再是破防的第 4 条线。
> 详见 [防具套装系统设计.md](防具套装系统设计.md) 与总设计文档的缺口 A-6。

**没有任何一条线能单独点满**：金币只给 12%、材料只给 24%。
必须把金币、突破材料、属性碎片三样都投进去 —— 这正是"装备够好才无视"的含义。

### 为什么用"收敛"而不是"开关"

```
实际倍率 = 1 + (原始倍率 − 1) × (1 − 破防)
```

二元开关（够强就不吃克制、否则全吃）会让体验在阈值两侧断崖跳变：
刚凑够破防的那一发伤害暴涨，之后一直不变。
线性收敛让**每一分投入都看得见**：破防 42% → ×1.6 变成 ×1.27，破防 90% → ×1.06。

这也是克制面板要显示**实际倍率**而不是只写"克制"两个字的原因 ——
玩家看到"克 ×1.27"才知道自己的破防起了多少作用。

## 五、关卡属性编排：6 组 × 4 种

| 关卡 | 属性种类 | 属性组 | 例子 |
|---|---|---|---|
| 1~4 | 1 | 五行 | 火 → 水 → 木 → 金属 |
| 5~8 | 2 | 自然 | 草 → 虫石 → 石萌 → 萌虫 |
| 9~12 | 3 | 气象 | 电冰 → 冰风 → 风光电 → 电冰风 |
| 13~16 | 4 | 造物 | 机械剑武毒（四种轮转） |
| 17~20 | 4 | 灵异 | |
| 21~24 | 4 | 法则 | |
| 25 起 | 回到五行 | | 24 关走完一轮 |

**限制"同组"是为了让关卡有主题**："这关是五行关""这关是法则关"。
如果 24 种随便混，一关里出现"空间 + 虫 + 水"就没有任何可读的规律。

### 为什么组周期必须等于 4

`elementCountForLevel` 的四档边界是 4/5、8/9、12/13，也就是"每 4 关换一次属性种类"。
把 `LEVELS_PER_GROUP` 也设成 4，两者周期对齐，于是**每个组内部的属性种类恒定**，
窗口偏移才能干净地"每关 +1"。

曾经取的是 3（"每 3 关换组"），被 forge_e2e 的重叠不变式打回来了，两处破窗：
- 种类增加发生在组内部（lv5 自然组内 1→2 种），窗口又长又移，一个属性都留不下
- 为此加的"冻结偏移"补丁把序列从 0 直接打断到 2，重叠保证失效

四条不变式（都有测试守着）：
1. 同一关内属性互不重复
2. **双属性以上，同组内相邻两关必然共享 ≥1 种**
3. 单属性关之间**不重叠** —— 长度就是 1，本来就不可能；这是刻意的，
   它让玩家一关只记一种属性，正好把克制环一个个教完
4. 换组的那一关属性完全不同 —— 主题切换，是刻意的

## 六、突破等阶：等阶只管槽位，不管伤害

```
一阶 → 1 个镶嵌位      材料 3
二阶 → 2 个            材料 6
三阶 → 3 个            材料 12
四阶 → 4 个            材料 20
五阶 → 仍是 4 个        （满阶）
```

等阶本身**不加任何伤害**，它唯一的职责是"最多能镶几个属性"。
代价加速上升而槽位只在前四阶各 +1，所以"养满一把"始终比"铺三个一阶"贵得多。

**12 种突破材料与 12 把武器一一对应**（精铁/灵木/霜晶/玄铁/陨铁/流银/雷石/幽铁/重晶/风羽/星砂/轮心）。
掉落规则：**推荐武器掉 2 个、克制武器掉 1 个** —— 于是"打这关"与"我想要哪把武器变强"直接挂钩。

> `RANK_SOCKET_SLOTS` 的长度必须等于 `MAX_WEAPON_RANK`，否则 `socketSlotsOf(5)` 返回
> `undefined`，`.length = undefined` 会抛 `RangeError`，**5 阶突破后打开面板就崩**。
> 这个坑踩过一次。

## 七、属性材料：10 碎片 = 1 完整

```
每关按自己的属性掉碎片（1~3 个）→ 攒够 10 个 → 1 个完整材料 → 镶进某个槽位
```

24 种属性各有一个符合性格的名字（烈阳石 / 碧澜石 / 龙鳞石 / 时砂石…），
而不是"属性1/属性2" —— 玩家要在背包里一眼认出"这是火的那块"。

**镶嵌可退**：换装与卸下都退还完整材料。手滑损失掉落是最容易招差评的点。
**看广告只是可选加速**：`grantStoneByAd()` 直接给 1 个完整（跳过 10 个碎片），
不是任何流程的必经环节。

### 抗性与"无视抗性"相乘

石 / 时间 属性给 `pierceResist`。抗性 30% + 无视 15% → 实际只吃 `70% × 85% = 59.5%`，
**不是** `70% − 15% = 55%`。相乘的原因：无视抗性是"这块石头本身够硬"，
它与护甲的减免是两个独立的减伤来源，线性相加会让堆叠收益过高。

## 九、这套系统不做的事

| 不做 | 原因 |
|---|---|
| 材料必须看广告才能拿 | 玩家明确要求，`forge_e2e.js` 有专门一节断言 |
| 照搬洛克的 ×2 / ×0.5 | 实时走位玩法里一发 ×2 会被当成 bug |
| 洛克的"光属性免疫克制" | 依赖双属性精灵，我们的敌人只有 1 种属性 |
| 洛克的"双属性被双克 = ×4" | 同上，这条规则在我们这儿是空的 |
| 多属性无限叠加 | 封顶 ×2.0，否则 4 阶武器镶 4 个克制属性能到 6.5 倍 |
| 属性种类超过 4 种/关 | 24 种已经让"选哪几种"变难，再加就是一局查字典 |
| 破防能求和 | 会把"专精一把"的路堵死 |
| 镶嵌不可逆 | 手滑损失掉落是差评重灾区 |

## 十一、测试（144 项）

`forge_e2e.js` 八节，其中三节是本轮新增/重写的：

**第 2 节 · 关卡属性编排**
- 24 种无重复、6 组覆盖全部、每组恰好 4 种
- 四档种类数、单调不减、同组内种类恒定
- 同关内互不重复、全部取自同一组
- **双属性以上同组内必然重叠** / **单属性关必然不重叠** / **换组必完全不同**
- 组周期与种类边界对齐、24 关走完一轮回到第一组
- 战斗层按属性池轮转分配；关卡配置把属性下发到战斗层

**第 3 节 · 克制表与破防**
- 表自洽（目标存在、不自指、无重复）

- 战斗层：火武器打草伤害明显更高、克制伤害单独计入成就、破防 50% 后伤害真的下降
