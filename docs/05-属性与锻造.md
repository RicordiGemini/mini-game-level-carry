# 05 · 属性与锻造

> 24 种属性、克制表推导、破防公式、关卡属性编排、材料与掉落。
> 代码：`data/ElementConfig.ts` · `data/MaterialConfig.ts` · `ui/CounterPanel.ts`

---

## 一、为什么是 24 种属性

参考《洛克王国》（原 18 种）再补 6 种：金属、剑、木、风、空间、时间。

6 种时玩家两局就打透了，属性材料很快变成"每种都攒一点、镶哪都一样"。
洛克王国的辨识度来自**每种属性都有独立的性格**：火就是爆、水就是持续、机械怕火、龙怕冰。

但这个规模带来一条**不可省的实现约束**：

> 24 种属性下，UI 必须实时把克制关系标出来。
> 6 种时玩家边玩边学就能记住；24 种时 24×24 的表不可能靠脑子记 ——
> 不把"我这套武器打这一关到底是什么关系"直接写出来，
> 属性系统就退化成查字典，玩家被克制 5 次之后就会放弃镶嵌。

所以有两处**必需**的显示：

- `ui/CounterPanel.ts` —— 对局角落常驻，显示本关属性 + 逐颗镶嵌的实际倍率 + 破防
- 关卡确认页（难度面板标题下方）—— 直接列出"本关怪物属性"

## 三、克制表：单表推导 + 三类特殊关系

**只写一张 `COUNTERS`（X 克制谁），抵抗关系由它反推**：

```ts
resistedBy(X) = 所有满足 X ∈ COUNTERS[Y] 的 Y
```

洛克原表是 18×18 的**双向手写表**，而手写必然出现"A 克 B 但 B 也克 A 却倍率不同"的矛盾。
反推从根上杜绝这种不一致。

### 三类特殊关系（单独声明，不混进主表）

| 类型 | 关系 | 语义 |
|---|---|---|
| **双向克制** | 光 ↔ 幽、空间 ↔ 时间 | 双方攻击对方都吃 ×1.6，**只算一次**（不叠成 2.56） |
| **同属性互克** | 龙克龙、幽克幽（洛克设定） | `COUNTERS` 严禁自指，所以单独一个 `SELF_COUNTER` 集合 |
| **无克制** | 普通系不克任何（洛克设定） | 但会被武 / 石 / 机械克制，所以它有弱点 |

### 倍率

| | 本作 | 洛克 | 为什么不同 |
|---|---|---|---|
| 克制 | **×1.6** | ×2 | 洛克是回合制，看得见下一招；我们是实时走位，×2 会被当成 bug |
| 被克 | **×0.9** | ×0.5 | 同上 |
| 多属性叠加 | 相乘，**封顶 ×2.0**（下界 ×0.5） | 双属性 ×4 | 4 阶武器镶 4 个克制属性能叠到 1.6⁴ = 6.5 倍，那是"一套装备通吃"而不是"配装决策" |

**实现**：先算属性间倍率再 clamp 到 `[0.5, 2.0]`，最后按破防收敛。

### 这套系统不做的事

| 不做 | 原因 |
|---|---|
| 材料必须看广告才能拿 | 玩家明确要求 |
| 照搬洛克的 ×2 / ×0.5 | 实时走位玩法里一发 ×2 会被当成 bug |
| 洛克的"光属性免疫克制" | 依赖双属性精灵，我们的敌人只有 1 种属性 |
| 洛克的"双属性被双克 = ×4" | 同上，这条规则在我们这儿是空的 |
| 多属性无限叠加 | 封顶 ×2.0 |
| 属性种类超过 4 种/关 | 24 种已经让"选哪几种"变难，再加就是一局查字典 |
| 破防能求和 | 会把"专精一把"的路堵死 |
| 镶嵌不可逆 | 手滑损失掉落是差评重灾区 |

## 四、无视克制（破防）

需求原文："支持装备够好的时候, 可以直接无视克制"。

```
破防 = (武器等级 − 1) × 0.03
     + (品阶 + 1 − 1) × 0.06      ← 注意：传的是 rarity + 1
     + 镶嵌颗数 × 0.03
     + armorBonus                 ← 恒为 0（防具不参与破防）
上限 0.9
```

常量：`BREAK_PER_LEVEL = 0.03` · `BREAK_PER_RANK = 0.06` · `BREAK_PER_SOCKET = 0.03`
· `COUNTER_BREAK_MAX = 0.9`。

**多把武器时取最高那一件，不求和** —— 求和会让"三把武器各破防 30%"直接满防，
那等于把"专精一把"的路堵死了（`maxCounterBreak`，`ForgeManager.ts:816-823`）。

### 4.1 🔴 实测：破防上限是 **0.60**，不是文档写的 0.48

| 配置 | 破防 |
|---|---|
| 新武器 | 0% |
| 只升满金币（Lv5） | 0.12 |
| 满级 + 传说品阶 | 0.12 + 0.36 = **0.48** |
| 满级 + 传说 + 4 颗镶嵌 | 0.12 + 0.36 + 0.12 = **0.60** |
| ~~加全属性防具 +15%~~ | ~~0.63~~ **已作废**（`armorCounterBreak()` 恒为 0） |
| 硬上限 `COUNTER_BREAK_MAX` | 0.90 —— **永远不会被触及** |

**没有任何一条线能单独点满**：金币只给 12%，品阶只给 36%。
必须把金币、品阶、镶嵌三样都投进去 —— 这正是"装备够好才无视"的含义。

> 📌 历史文档的 0.48 基于**已废弃的 `forge.rank` 阶梯**（rank 1~5）。
> v6 迁移删掉了 `forge.rank`，改用品阶（0~6），
> 而代码传的是 `rarity + 1`（1~7），所以传说阶实际给到 0.36 而非 0.24。
> `BREAK_PER_RANK` 这个常量名与"满阶突破（5 阶）"的注释都已语义漂移。

### 4.2 为什么用"收敛"而不是"开关"

```
实际倍率 = 1 + (原始倍率 − 1) × (1 − 破防)
```

二元开关（够强就不吃克制、否则全吃）会让体验在阈值两侧**断崖跳变**：
刚凑够破防的那一发伤害暴涨，之后一直不变。
线性收敛让**每一分投入都看得见**：破防 42% → ×1.6 变成 ×1.27，破防 60% → ×1.24。

这也是克制面板要显示**实际倍率**而不是只写"克制"两个字的原因 ——
玩家看到"克 ×1.27"才知道自己的破防起了多少作用。

## 五、关卡属性编排：6 组 × 4 种

| 关卡 | 属性种类 | 属性组 |
|---|---|---|
| 1~4 | 1 | 五行 |
| 5~8 | 2 | 自然 |
| 9~12 | **3** | 气象 |
| 13~16 | 4 | 造物 |
| 17~20 | 4 | 灵异 |
| 21~24 | 4 | 法则 |
| 25 起 | 回到五行 | 24 关走完一轮 |

**限制"同组"是为了让关卡有主题**："这关是五行关""这关是法则关"。
如果 24 种随便混，一关里出现"空间 + 虫 + 水"就没有任何可读的规律。

### 为什么组周期必须等于 4

`elementCountForLevel` 的四档边界是 4/5、8/9、12/13（"每 4 关属性种类 +1"）。
`LEVELS_PER_GROUP = 4` 与之周期对齐，于是**每个组内部的属性种类恒定**，
窗口偏移才能干净地"每关 +1"。

曾经取的是 3（"每 3 关换组"），被重叠不变式打回，两处破窗：

- 种类增加发生在组内部（lv5 自然组内 1→2 种），窗口又长又移，一个属性都留不下
- 为此加的"冻结偏移"补丁把序列从 0 打断到 2，重叠保证失效

> ⚠️ `ElementConfig.ts:55` 的文件头注释仍写"**每 3 关换一次组**" —— 这是残留错误，
> 实际 `LEVELS_PER_GROUP = 4`（`:479`）。

### 四条不变式

1. 同一关内属性互不重复
2. **双属性以上，同组内相邻两关必然共享 ≥1 种**
3. 单属性关之间**不重叠** —— 长度就是 1 本来就不可能；这是刻意的，
   它让玩家一关只记一种属性，正好把克制环一个个教完
4. 换组的那一关属性完全不同 —— 主题切换，也是刻意的

### 属性分配到敌人：轮转而非随机

`BattleWorld` 用 `_elementCursor` 自增轮转分配属性，传 `elementCursor` 可完整复现。

## 六、材料与掉落

### 6.1 突破材料（12 种 + 1 专属）

`mat_<equipType>`，与武器 type 一一对应：
精铁(blade) / 灵木(bow) / 霜晶(orb) / 玄铁(spear) / 陨铁(hammer) / 流银(dagger) /
雷石(staff) / 幽铁(scythe) / 重晶(cannon) / 风羽(shuriken) / 星砂(lance) / 轮心(wheel)。

`fromLevel` 与武器 `unlockLevel` 对齐 —— 玩家拿到武器之后不久它的材料才开始掉，
否则会出现"为了材料去刷一把还没解锁的武器"的死循环。

**为什么按武器类型分而不是按关卡分**：材料是"这把武器变强的凭证"，
意义永远绑定在武器身上。若改成"任意材料都能突破任意武器"，玩家就没有收集目标了。

### 6.2 掉落规则（`ForgeManager.rollDrops`）

```
推荐武器的材料 ×2 · 克制武器的材料 ×1 · 每种本关属性的碎片 1 + floor(roll × 3)
```

**掉落规则与推荐/克制名单挂钩** —— 于是"打这关"与"我想要哪把武器变强"直接挂钩。

### 6.3 属性材料：10 碎片 = 1 完整

```
每关按自己的属性掉碎片（1~3 个）→ 攒够 10 个 → 1 个完整材料 → 镶进某个孔位
```

`SHARDS_PER_STONE = 10` · `SHARD_DROP_MIN = 1` · `SHARD_DROP_MAX = 3`。

24 种属性各有符合性格的名字（烈阳石 / 碧澜石 / 龙鳞石 / 时砂石…），
而不是"属性1/属性2" —— 玩家要在背包里一眼认出"这是火的那块"。

**镶嵌可退**：换装与卸下都退还完整材料。手滑损失掉落是最容易招差评的点。
**看广告只是可选加速**：`grantStoneByAd()` 直接给 1 个完整（跳过 10 个碎片）。

### 6.4 全属性石

24 种碎片各 10 个 = **240 碎片**合成 1 个。它是**万象线唯一的燃料**，
4 级共消耗 4 个 = 960 碎片。详见 [03-装备养成 §8](03-装备养成.md)。

### 6.5 神话之核（唯一的不可替代材料）

`mat_myth_core`，全游戏**唯一**不能金币买、不能碎片换、不能广告拿的材料。

**掉落条件**：

```ts
// ForgeManager.mythCoreDropChance（ForgeManager.ts:1207-1212）
elementsForLevel(levelId).length === 3 && normalizeTier(tier) === 3  →  0.25
否则 → 0
```

即**第 9~12 关 × 噩梦难度，掉率 25%**（`MYTH_CORE_DROP_RATE`）。

**为什么定 25%**：掉落窗口只有 4 关 × 1 个难度 = 4 种组合，而一次"神话→传说"只要 1 个。

- 定 10% 会让平均耗时翻倍到 10 次，那几关的噩梦并不好打，容易变成劝退
- 定 50% 又太便宜，传说会泛滥
- **25% ≈ 平均 4 次通关拿 1 个**，认真打一个下午能出一个传说

> ⚠️ 历史文档写"见 `LevelFlow.rollMythCore`" —— **`LevelFlow` 没有这个函数**。
> 判定在 `ForgeManager.mythCoreDropChance`，实际 roll 在 `ForgeManager.rollDrops` 内联
> （`:1177-1183`）。`MaterialConfig.ts:111` 的注释也指向了这个不存在的函数。

### 6.6 ⚠️ 死代码：整套 rank 系统已被品阶取代

`MaterialConfig.ts` 里这套常量**全部零调用点**：

```
MAX_WEAPON_RANK = 5
RANK_MATERIAL_COST = [3, 6, 12, 20, 0]
RANK_SOCKET_SLOTS = [1, 2, 3, 4, 4]
socketSlotsOf(rank)     ← 无调用方
rankCostOf(rank)        ← 无调用方
breakthrough()          ← 函数已删除
```

第八轮品阶**吸收**了 `forge.rank` 的职责（决定镶嵌槽数），
所以这套阶梯是死代码。历史文档《锻造与属性设计》§六 仍把它当现行机制完整描述，
连"RANK_SOCKET_SLOTS 长度必须等于 MAX_WEAPON_RANK，否则 5 阶突破后打开面板就崩"
这个坑也照抄了 —— **该坑已随函数一起不存在**。

> 这套死代码同时也是"重复武器 → 材料"转化失去消费方的原因（见 [04](04-抽卡与经济.md)）。

## 七、抗性

### 7.1 防具抗性（24 维）

见 [03-装备养成 §6.1](03-装备养成.md)。要点：

- 每件带 1 条轴的抗性，按部位权重分摊套装总抗性（身 .34 / 头 .30 / 裤 .20 / 鞋 .16）
- 穿戴 4 件各乘品阶倍率，**软压缩两次**后求和
- `RESIST_MAX = 0.75` 常量存在但在 `currentResist()` 中**未被引用**
  —— 实际上限由二次压缩隐式给出（恒 < 1.0）

### 7.2 抗性与"无视抗性"相乘

`石` / `时间` 属性给 `pierceResist`。抗性 30% + 无视 15%
→ 实际只吃 `70% × 85% = 59.5%`，**不是** `70% − 15% = 55%`。

相乘的原因：无视抗性是"这块石头本身够硬"，它与护甲的减免是两个独立的减伤来源，
线性相加会让堆叠收益过高。
