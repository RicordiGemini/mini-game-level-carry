# 04 · 抽卡与经济

> 许愿水晶、三池抽卡、保底、重复转化、祝福值、碎片兑换，以及全部货币的产出与消耗。
> 代码：`data/GachaConfig.ts` · `core/GachaManager.ts` · `ui/GachaPanel.ts`

## 一、许愿水晶

### 1.1 产出：按难度分档，通关必给

| 难度 | 水晶 | 等价单抽 | 设计意图 |
|---|---|---|---|
| 普通 | **10** | 1 次 | 恰好一次单抽，通关必有收获，不至于空手 |
| 困难 | **30** | 3 次 | 开始出现"能决定抽哪把"的选择空间 |
| 噩梦 | **100** | 10 次 | 一次十连，高难度独有的追求目标 |

`CRYSTAL_REWARD_BY_TIER = [0, 10, 30, 100]`（`GachaConfig.ts:66-71`）。

**为什么不按固定值给**：如果三档都给 100，玩家会永远刷普通难度（10 抽 = 一把），
**难度阶梯的推进动机被抽卡系统反向拆掉**。按难度分档让"打更难的"成为获得水晶的唯一有效路径。

**为什么复玩不打折**：金币有 `REPLAY_GOLD_RATE = 0.6`，防的是"反复刷同一难度快速出金"。
水晶不打折，因为它的速率被**通关**这个硬门槛锁死了 —— 你至少得把那一关的怪全部打完。
这与金币的"进场即有收益"性质不同。

## 二、三个卡池

| 池 | key | 展示名 | 规模 | 内容 |
|---|---|---|---|---|
| 武器池 | `weapon` | 武器池 | **18** | 12 常规 + 6 高阶专属 |
| 辅助池 | `aux` | 辅助池 | **14** | 8 常规 + 6 高阶专属 |
| 装备池 | `armor` | **装备池** | **92** | 23 套 × 4 部位（万象套不在内） |

**三池完全分开**，内容与保底进度都不共享（`pityWeapon` / `pityAux` / `pityArmor` 三个字段）。

> 📌 《许愿与抽卡设计》整篇只讲"武器池与辅助池两个池子"，**完全没提 armor 池**
> —— 那份文档写于防具改为抽卡获取之前。

### 2.1 为什么武器池与辅助池要分开

这不是数值问题，是**决策问题**：

- 武器池抽到 → 影响基础伤害与攻击方式，收益永久且立刻生效
- 辅助池抽到 → 影响每局的战斗修正，还要额外花金币升阶才变强

玩家在"这一百水晶花在哪边"上是**二选二选一**，不是同时看两个列表。
合并会让这个抉择消失 —— 那就退化成了纯随机消费。

### 2.2 抽卡三条不可让步的规则

1. **没有任何一步必须看广告。** `GachaManager` 的所有函数**不接受广告参数** ——
   从接口上就不可能做出强制。广告只有 `grantCrystalByAd()` 一个入口。
2. **重复件绝不静默消失。** `duplicateText` 字段让 UI 能明确告诉玩家"转化成了什么"。
3. **抽卡不提供数值碾压。** 抽到的武器 `level: 1`，与自动发放时一致。

> ⚠️ **规则 3 有个例外**：品阶**不是** 1 级那样统一。
> `grantWeaponToProfile` 按 `def.rarity` 入手，所以高阶专属武器
> **直接以钻石/史诗/神话品阶 + 1 级** 入库（星刃 Lv1 钻石 = 9×1.70 = 15.3 基础伤害，
> 而铁剑 Lv1 青铜 = 8）。这是设计意图（专属装备就该是那个品阶），但与"不提供数值碾压"的
> 字面表述有张力。

## 三、一次抽卡的三类结果

```
装备   74%   主结果，按品阶权重抽
材料   18%   突破/升级用的专属材料，× PULL_MATERIAL_COUNT(2)
碎片    8%   高阶碎片 × PULL_FRAGMENT_COUNT(2)
```

材料与碎片都是"非装备"结果，它们让每一次抽卡都有意义：
即使这抽是重复装备，也可能顺手给几个材料。

抽到材料时**按品阶越低给越多**，避免高阶抽卡变成材料农场（`GachaConfig.ts:169-170`）。

### 3.1 品阶权重

```
青铜 46  白银 26  黄金 16  钻石 8  史诗 3  神话 1  传说 0（不可抽）
```

总权重 100，读出来就是百分比。曲线刻意**指数衰减**（每升一阶大约减半）：
让"抽到神话"成为一件值得截图的事（1% ≈ 百抽一件），但又不至于像 0.1% 那样让人绝望。

**传说不可抽**（权重 0），只能由神话进化而来。

## 四、保底

### 4.1 规则

- 连续抽到"已拥有" **30 次**后，下一抽必定给还没见过的（`PITY_THRESHOLD = 30`）
- 抽到新的即清零
- **三池各自独立累计**
- **十连的第 10 抽必定不是重复**（`BATCH_GUARANTEE_LAST = true`）
- 全收集后保底归零（避免存档里留一个无意义的大数字）

**为什么定 30 而不是 10**：30 抽 = 300 水晶 = 普通难度 30 局 / 困难 10 局 / 噩梦 3 局，
对应"认真打几天"，这是能被接受的等待长度。定 10 太短的话每 10 抽必出一件，
收集感只剩 10 次，保底就从"兜底"变成了"节奏"。

### 4.2 ⚠️ 保底只被"装备"推进

```ts
// GachaManager.ts:373-379
if (r.kind === 'equip') {
    owned.push(r.id);
    if (r.isNew) pity = 0; else pity += 1;
}
```

**抽到材料或碎片既不推进也不清零保底进度。** 历史文档没写这条。

### 4.3 ⚠️ 保底触发时"刻意偏向高品阶"

保底分支（`GachaManager.ts:226-229`）不是"随便给一个未拥有的"：

```ts
fresh.sort((a,b) => b.rarity - a.rarity);
const top = fresh[0].rarity;
const topBand = fresh.filter(x => x.rarity === top);
// 从 topBand 里等概率取 1
```

也就是**只在未拥有的装备里挑品阶最高的那一档**。历史文档没写这个实现。

### 4.4 ⚠️ 品阶 band 为空会静默降级

```ts
const band = all.filter(x => x.rarity === rolled);
const candidates = band.length > 0 ? band : all;   // ← 静默回退到全池
```

如果某品阶在池里没有候选，会**静默回退到全池等概率取** —— 概率与显示的权重不符。
（正常情况下不会触发，因为 `rollRarity` 只会选出有候选的品阶。）

## 五、重复件转化

| 池 | 重复转化 |
|---|---|
| **武器** | `mat_<type>` × **2**（该武器类型的专属材料） |
| **辅助** | 金币 × **120** |
| **防具** | **⚠️ 不转化** —— 每次抽到都直接入库为**新实例**（升阶燃料） |

**为什么武器给材料而不是新货币**：材料背包（第四轮做的）已在升阶流程里跑通，
不需要新增任何背包与货币。更重要的是它形成正循环 ——
**抽卡与锻造互相喂**：抽到重复 → 推进升阶 → 那把武器变强 → 池子填得更快。

**为什么辅助给金币**：辅助没有专属材料线（它没有 `EquipmentDef`），
用金币与"金币 = 永久变强的货币"保持同一套货币语言。

> ⚠️ **但材料 `mat_<type>` 现在没有消费方** —— `ascendWeapon` 消耗的是**装备**不是材料，
> `EquipmentManager.upgrade()` 也只扣金币。重复武器转化出的材料目前是死资源。
> 见 `12-缺口与风险.md`。

> ⚠️ **防具重复件无条件进 `newIds`**（`GachaManager.ts:536-537`），
> 所以 UI 会把重复件也高亮成"新获得"。

> ⚠️ `duplicateTextOf` 对 armor 池会走到 `getEquipDef(id)` 返回 null 的分支，
> 产出 `'…转化为 undefined专属材料材料 ×2'` 之类的脏文案。
> 因为防具走特例分支，该文案实际不会被 UI 读到，但函数本身是错的。

## 六、祝福值

### 6.1 两条来源，都完全可选

| 来源 | 收益 |
|---|---|
| 献祭水晶 | **10 水晶 = 1 点**（不抽卡，直接换） |
| 看激励视频 | **+3 点** |

上限 **30**（`BLESSING_MAX`）。

### 6.2 作用：钻石及以上权重翻倍

```ts
// GachaManager.ts:260-289
highFrom = 3, MUL = 2.0
highSum = 8+3+1 = 12
boost   = 12 × (2.0-1) = 12
高阶 ×2 → [16, 6, 2, 0]，合计 24
lowSum  = 88, ratio = (88-12)/88 = 0.8636
低阶 → [39.73, 22.45, 13.82]
```

**无祝福：高阶合计 12%。有祝福：高阶合计 24%。总和恒为 100。**
这是能被玩家算清楚、也能被测试断言的明确收益 —— 不是保底，是实打实的概率翻倍。

**祝福值 0 时游戏完全正常**，它只是加速器，不是必需品。

**为什么广告只加成"概率"而不是"直接给装备"**：与"Manager 不接受广告参数"是同一条约束 ——
广告只能加速，不能成为任何成长动作的必经之路。

### 6.3 ⚠️ 献祭水晶的捷径风险（未评估）

"不抽、直接献祭水晶换祝福值"使高阶权重翻倍。若玩家纯刷噩梦（100 局/局的水晶产出）
后集中献祭，可能绕过抽卡随机、稳定高产高阶。

**这条路径的产出上限从未被评估过**，祝福值上限 30 是否足够封死也没有结论。
见 `12-缺口与风险.md`。

## 七、高阶碎片兑换

**25 个碎片 → 任选一件高阶装备**（`FRAGS_PER_HIGH_EQUIP = 25`，`EXCHANGE_RARITY = 3` 钻石）。
三池通用同一份碎片（`fragHigh`）。

它是"抽不到也不被卡死"的保底：纯随机有长尾，碎片让玩家永远有一条确定的路走到高阶。

> ⚠️ **只对 armor 池强制钻石。** `GachaManager.ts:679-694` 里：
> - **armor 池**：`grantArmorToProfile(EXCHANGE_RARITY)` → 固定钻石
> - **aux 池**：`grantAuxToProfile` 用形态表 `f.rarity`（3/4/5，取决于哪条线）
> - **weapon 池**：`grantWeaponToProfile` 用 `def.rarity`（**常规武器是 0 青铜！**）
>
> 所以"25 碎片换一件钻石装备"这句话**只对防具池成立**。用碎片换常规铁剑会得到青铜品阶。
> 历史文档说"三池通用同一份碎片"是对的，但没说品阶不统一。

> ⚠️ **已拥有时的返回值语义反直觉**：非 armor 池返回 `ok: false`
> + `reason: '已经拥有了，已按重复件折算'`，**但碎片已经扣了、奖励也发了**。
> 调用方若只看 `ok` 会误判为失败。armor 池则给新实例、返回 `ok: true`。

## 八、货币产出与消耗

### 8.1 金币

**产出**（`LevelConfig.ts:104-106` + `LevelFlow.ts:920-925`）：

```ts
goldReward = round((90 + levelId × 22) × diff.goldMul) × (1 + boost × 0.8)
实际发放   = goldReward × (clearCount > 1 ? 0.6 : 1) × (percent > 0 ? 1 + percent × 0.5 : 1)
```

| 难度 | `goldMul` |
|---|---|
| 普通 | 1.0 |
| 困难 | 1.8 |
| 噩梦 | 3.0 |

**复玩永久金币按 `REPLAY_GOLD_RATE = 0.6` 折算**，防"反复刷同一关攒金币"。

> ⚠️ `AFFINITY_GOLD_MUL = 1.30`（"带推荐武器金币 ×1.30"）常量存在但
> **`affinityGoldMul()` 是死函数，无任何调用方**。结算用的是上面的 `1 + percent × 0.5`，
> 与推荐武器无关。历史文档写"推荐武器 金币 ×1.30"，**这条实际不生效**。

**消耗**（全部来自 [03-装备养成](03-装备养成.md)）：

| 用途 | 花费 |
|---|---|
| 武器局外升级 Lv1→5 | 各武器 680~12400 不等（见 03 文档表） |
| 升阶 青铜→传说 | 400 / 900 / 2000 / 4500 / 9000 / 18000 |
| 辅助升阶 1→5 | 800 / 1800 / 3600 / 6800（合计 13000） |
| 防具开孔 | 10 水晶/孔（**不是金币**） |
| 万象线 | 6000 / 12000 / 24000 / 48000（合计 **90000**） |

### 8.2 🔴 金币 sink 缺口

**满传说满图鉴后金币无处可去。** 万象线的 90000 是唯一的大额 sink，且只消耗一次。

消耗端没有循环出口（无洗练 / 重铸 / 外观 / 分解）。
金币溢出后会直接抽干抽卡与养成的动机。

见 `12-缺口与风险.md`。

### 8.3 属性的消耗

| 用途 | 花费 |
|---|---|
| 镶嵌孔（武器） | 品阶给的免费，武器无法额外开孔 |
| 镶嵌孔（防具） | 10 水晶/孔；青铜套可用材料开孔 |
| 镶嵌 / 卸下 | 属性石本身（**可卸，退还完整材料**） |
| 全属性石 | 24 种碎片各 10 个 = **240 碎片** |
| 万象线 | 4 个全属性石 = **960 碎片** + 90000 金币 |

**没有任何成长动作必须看广告。**

## 九、抽卡的确定性

`pull(pool, count)`：

1. 抽数钳制 `n = clamp(floor(count), 1, 10)`
2. 水晶校验：不足则返回 `spent: 0` 且**不写档**
3. 扣费 `p.crystals = cur - cost`（是**赋值**不是减法，依赖上一步已校验）
4. 逐抽 `rollOnce`，每抽消耗 1 点祝福值（`useBless = blessLeft > 0`）
5. 只有装备推进保底
6. 写档：保底计数 / `gachaTotal` / `blessing`
7. **全收集冻结**：aux 满 14 / armor 去重满 92 / weapon 满 18 → 对应 pity 归零
