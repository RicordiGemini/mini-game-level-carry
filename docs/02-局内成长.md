# 02 · 局内成长

> 打怪攒经验 → 三选一 → 形态进化 / 合成 / 叠天赋。
> 代码：`core/RunLoadout.ts` · `core/RewardPicker.ts` · `core/FormGraph.ts`
> · `data/FormConfig.ts` · `data/TalentConfig.ts` · `data/RunConfig.ts`

当前武器进化规则：每个形态先选五次「武器强化」，每次增加 15% 攻击加成；再持有配套辅助，才出现该形态的进化路线。击杀培养经验和局外武器等级不能代替这五次选卡。进化不消耗辅助，已获得的强化攻击加成保留，新形态重新从 0/5 强化。武器合成的两件材料也分别满足五次强化及配套辅助要求；合成释放一个武器槽并补选。六把高阶专属仍保留原配置，无额外虚构进化路线。

配套按武器根配置于 `RunConfig.WEAPON_EVOLUTION_AUX`，辅助的进阶分支也可满足条件：

| 武器 | 配套辅助根 ID |
|---|---|
| blade、scythe | aux_blood（泣血戒） |
| bow、spear | aux_scope（鹰眼镜） |
| orb | aux_tome（智慧书） |
| hammer | aux_thorn（荆棘甲） |
| dagger | aux_greaves（疾行靴） |
| staff、wheel | aux_hourglass（时砂漏） |
| cannon、shuriken | aux_repeater（连装匣） |
| lance | aux_aegis（圣盾符） |

合成形态若有后续路线，需要其全部来源武器对应的辅助。奖励卡、持有武器说明及教学显示强化进度和配套要求；辅助候选优先推荐当前武器缺少的配套。

### 为什么辅助必须"进化不耗槽"

如果辅助装备也能像武器那样被合成吃掉，玩家会不愿意在局内培养它 ——
因为随时可能"白养了"。所以 `validateFormGraph()` 有一条硬校验（`FormConfig.ts:829-835`）：

> **`kind === 'aux'` 的边只允许是 `upgrade`。** 配置写错会在启动时直接报错，
> 而不是等到线上让玩家的辅助装备凭空消失。

代码事实：14 条辅助线共 46 个形态节点（depth0=14 / depth1=16 / depth2=16），
**全部 `upgrade` 边，没有一条 fusion**（`AuxConfig.ts:68-70` 的 `up()` 工厂硬编码）。

## 二、形态图

### 2.1 为什么不能用线性链

链（"第 0 层 → 第 1 层 → …"）有三个结构性问题：

1. **没有 build 差异** —— 所有人的铁剑都长成天罚剑，第 20 局和第 1 局看到的终局相同。
2. **无法表达合成** —— 两件武器合而为一是"多入一"的节点，链装不下。
3. **无法表达"复玩才出现"**。

形态图用 `FormNode` + `EvolutionEdge` 表达：

```ts
interface FormNode {
    id: string;
    name: string;
    kind: 'weapon' | 'aux';
    equipType: EquipType;      // 决定基础伤害/射程/间隔
    sources: string[];         // ★ 血脉来源
    depth: number;             // 0=根形态
    atkPct: number;
    rangePct: number;
    attackModeId: AttackModeId;
    aimModeId?: AimModeId;     // 可选，覆盖武器类型默认值
    evolveTo: EvolutionEdge[];
    rarity?: number;           // 高阶专属的出生品阶
    innate?: InnateDef;        // 自带复合属性
    effect?: EffectMods;       // 辅助专用
    desc: string;
    attackModeText: string;
}
```

> 📌 历史文档列了 10 个字段，实际有 **12 个**（漏了 `rarity` / `innate` / `effect`，多算了一个 `desc`）。

### 2.2 `sources` 是整个设计能成立的关键

`sources` 是一个形态的**血脉集合**：

- 根形态：`sources = [自己的 id]`
- 升级形态：继承父形态的 sources
- **合成形态：两件材料的 sources 并集**

合成合并迭代**最多 4 轮**（`FormConfig.ts:589`），因为 `fus_genesis` / `fus_eternal`
的材料本身也是合成产物。

它同时解决三件事：

1. **合成后基础伤害不亏** —— `baseDamageOfForm(sources)` 把 sources 里每件装备的基础伤害**求和**。
   "裂空剑 + 暴雨弩 → 剑雨风暴"之后，新形态吃的是两把武器之和。合成消耗了一个槽位，
   但战力没掉，这是"消耗一格"能被接受的前提。
2. **关卡适配不因进化失效** —— 推荐判定按 `sources` 走。玩家把铁剑进化成裂空剑之后，
   "铁剑是第 1 关推荐武器"依然生效。按形态 id 精确匹配的话，进化一次加成就消失。
3. **档案继承不断** —— 老档存的是形态 id，继承时按"形态所属武器线"匹配。

### 2.6 三类进化的行为差异

| | upgrade（升级型） | fusion（合成型） | advanced（复玩限定） |
|---|---|---|---|
| 槽位 | **不消耗** | **消耗一个武器槽** | 取决于边的类型 |
| 出现条件 | 武器五次强化＋配套辅助；辅助自身按培养经验 | 集齐材料 **且两材料都满足武器进化条件** | `allowAdvanced === true` |
| 实现 | `applyEvolve()` | `applyFusion()` | 只是边的 `advanced` 标记 |
| 数组长度 | 不变 | **−1** | 同 upgrade 或 fusion |

> ⚠️ `findFusions`（`FormGraph.ts:148-149`）有**三个**必要条件：
> 配方可用 + 两材料在手 + **两材料都已 `isReadyToEvolve`**。
> 历史文档只写"集齐两件材料"，漏了第三条。

> 📌 历史文档说 advanced 靠 `carrySource !== 'none'` 判断。代码参数名是
> `allowAdvanced: boolean`，由 `FormGraph.readyEvolutions(loadout, allowAdvanced)` /
> `getEvolveOptions(formId, allowAdvanced)` 消费 —— **是参数而非读存档字段**。
> 另外 `advanced` 边在代码里**恰恰就是"往后接"**，靠参数在候选生成时过滤掉。

#### 合成的槽位补偿

合成让武器从 2 件变 1 件，玩家会立刻感到"我亏了"。所以：

```ts
lo.weapons.splice(ib, 1);
lo.pendingPicks += 1;   // ★ 释放出待补选名额
```

`pendingPicks > 0` 时下一次三选一**强制优先给新武器候选**，
`LevelFlow.chooseReward()` 会**立刻**再开一次三选一。

> 玩家刚做完一个亏格子的决策，应该马上得到补偿，而不是带着空槽再打十几只怪。

**边界：池子空了怎么办** —— 若补选时池子已空，`openReward()` 返回 `false` 并
**主动把阶段归位到 `PLAYING`**。原实现只 `return`，阶段会永远卡在 `REWARD`，
战斗停住、面板不弹、玩家只能重启 —— **三选一死锁是最难查的那类线上问题**。

## 三、经验与两个"等级"

局内经验只在 `BattleWorld.damageEnemy()` 确认敌人死亡后发放，开局经验固定为 `0`，不会因为进入关卡或打开装备页直接弹出三选一。HUD 会持续显示当前等级、经验进度和下一等级门槛；等级门槛由 `levelExpFor(level)` 按 `70 + 20 × (level-1)` 递增，达到门槛后才暂停战斗并打开三选一。

2026-10-18 补齐以下行为（回归：`tests/level-growth.test.mjs`）：

- 每个敌人死亡事件携带敌人 ID 和经验值。相同 ID 在同一场战斗只结算一次击杀、资源和经验；一帧内群杀先全部结算，帧末才打开三选一。
- `pendingLevelUps` 按达到的等级排队，包含正在展示的这次奖励。一次跨多级也逐级选卡；每次成功选择仅消费一次机会。合成补选 `pendingPicks` 优先处理，与升级奖励独立计数。
- 经验加成分别作用于敌人的角色经验 `expValue` 和装备培养经验 `formExpValue`；未配置装备经验的旧接口沿用同额经验。达到 60 级后不再新增升级奖励，装备仍可培养。
- 最后一只怪产生奖励时，保存 `battleCleared`，等升级和合成奖励领取完才进入通关结算；重复通关回调不会再发本次奖励。
- 所有成功选卡和每帧击杀成长共用完整属性同步：新武器、辅助、天赋、攻速、生命上限、移速、护盾、反伤立即生效。同步保留武器冷却；生命上限增加时当前生命增加相同额度；护盾只增加新获得的额度，重复同步不会补满已消耗部分。

经验目前直接到账，没有经验球实体或拾取过程。上述回归使用真实业务代码和战斗模拟；本次尚未完成 Cocos 交互预览、微信工具或真机复测。

### 3.1 关卡等级（触发三选一）

`levelExpFor(level) = 70 + 20 × (level-1)`（`RunConfig.ts`），
`MAX_RUN_LEVEL = 60`。决定三选一的节奏。

**第一次三选一发生在升到 2 级时**（1 级是开局，没有面板）。

### 3.1.1 持续刷怪经验（2026-10-18 当前规则）

定时波次每次实际击杀基础角色经验 2、装备经验 3（由原 8/12 下调至四分之一），仍叠加智慧书与经验天赋。按角色线性门槛，新局无加成第 35/80/135/200/275/360 次击杀升级；首次升级已有 105 装备经验，但不能代替五次武器强化及配套辅助。经验加成保留小数并随存档恢复，避免小幅加成被单杀取整吞掉。升级继续排队，暂停选卡不推进波次时间。

普通首关无同屏限流的预计投放 1440 只，预计角色经验 2880、装备经验 4320，基础可升 14 次。初始铁剑配合选卡与移动的逻辑模拟约 11.8 秒首次升级、90 秒共 14 次选卡；仅为模拟样本。实际击杀少于投放估算时经验相应减少，经验加成可增加升级次数；并非保底奖励，不在通关时追补。现有 60 级上限不变。旧的固定敌人数预算规则仅供未配置 waves 的旧战斗接口使用。已有等级、装备经验和待领队列保留，降速作用于后续击杀。

configs/levels/roguelike-wave-plan-experience.csv 输出各关预估总量和升级击杀节点；tests/experience-budget.test.mjs 验证 3000 组参数及旧经验曲线迁移，tests/timed-waves.test.mjs 验证真实持续刷怪、波次计时和恢复。

### 3.2 形态深度（决定能进化到哪一层）

`DEPTH_EXP_NEED = [90, 190, 340, 620, 980]`（`FormConfig.ts:73`）。

该培养经验门槛当前只决定辅助装备的进化资格；武器的资格改为五次强化与配套辅助。武器进化仍沿用下面的经验扣除规则，以保留培养经验带来的形态等级收益。

**为什么进化后要"扣除门槛"而不是"清零"**：

```ts
function carryExpOver(exp: number, fromDepth: number): number {
    return Math.max(0, Math.floor(exp - depthExpNeed(fromDepth)));
}
```

归零的话，玩家在一局里能推到的深度完全由击杀数决定 —— 打得快也推不深，因为每层都从头攒。
扣除门槛后溢出经验会带到下一层，于是"清怪快"能直接换成"进化深"。**这才是刷分的意义。**

> 📌 合成形态的经验取两份剩余的 **min**（不是和），`RunLoadout.ts:331`。

### 3.3 ⚠️ 形态等级（历史文档完全没提，但代码实装并生效）

| 常量 | 值 | 位置 |
|---|---|---|
| `FORM_LV_EXP` | `[0, 110, 260]` | `FormConfig.ts:61` |
| `FORM_MAX_LV` | `3` | `FormConfig.ts:64` |
| `FORM_LV_ATK_PCT` | `0.10`（每形态等级 +10% atk） | `FormConfig.ts:67` |

即：`slot.exp` 跨过 110 / 260 时，该槽位的武器额外获得 **+10% / +20% 伤害**，
且**与形态深度无关**。这是除"深度"之外的第二层成长，属于实现细节，从未写进设计文档。

## 四、局内三选一

### 4.1 候选池与优先级

`RewardPicker` 给每个候选打一个优先级（数字越小越优先）：

| 优先级 | 类别 | 条件 |
|---|---|---|
| −2 | 高级合成 | `allowAdvanced`（复玩继承） |
| −1 | 常规合成 | 集齐材料 + 两材料都可进化 |
| 0 | 进化（升级型） | 武器五次强化＋配套辅助；辅助培养经验达标 |
| 0.5 | 武器强化 | 当前形态强化少于五次 |
| 1 | 新装备 | 槽位未满 |
| 2 | 天赋 | 永远有货 |

### 4.2 "固定三选一"与"2 主 + 1 其他"

恒产 **3 张卡**（`REWARD_CHOICES = 3`），组装方式是**主类别出 2 张、其他类别补 1 张**
（`FOCUS_TAKE = 2`）。

主类别按关卡等级轮转：`rewardFocusFor(level) = (level + 1) % 3`（`RunConfig.ts:81-93`）。
`+1` 这个偏移是为了让**首次三选一（2 级）落到武器档** —— 新手第一次选卡就看到武器，
而不是先看到一堆天赋。

补齐阶段**必须排除主类别**，否则三张会全同类。

### 4.3 天赋是"永不空屏"的保底

天赋不占槽位、可叠层，不受任何条件约束。只要还有没满层天赋，
三选一就一定能凑齐三张 —— 保证"玩家点了升级却什么都没发生"永远不会出现。

### 4.4 候选池来源（重要）

| 候选类别 | 来源 | 说明 |
|---|---|---|
| 新武器 | **`WEAPON_ROOT_IDS` 全池（18 条）** | **不限于局外已拥有** |
| 新辅助 | `AUX_ROOT_IDS` 全池（14 条） | 同上 |
| 天赋 | `getAvailableTalentIds` | 排除已满层的 |

局内抽到陌生武器**不是问题**：局内武器的基础伤害按 `EquipmentManager.baseDamageOf` 查局外等级，
没抽到就是 1 级、伤害极低。也就是说局内抽到陌生武器 = **"试用一把一级武器"** ——
提供 build 的**宽度**，不提供**数值碾压**。

> 📌 `RewardContext.ownedEquipIds` 字段保留、LevelFlow 仍传入，但 `weaponPool` **完全不读它**。
> 历史文档把它写成"未来若要做局内只给局外收藏模式的开关"—— 实际上它现在就是死字段。

### 4.5 三选一的确定性种子

`openReward` 用 `levelId × 7919 + difficulty × 1313 + rewardLevel × 17 + loadout.rewardSequence`
生成种子。`rewardLevel` 为队列中当前领取的等级；次数与当前卡片一起保存，续玩保留相同候选与后续序列。

### 5.2 `t_critdmg`（破甲印记）与暴伤合并规则

当前 `addEffect` 以 `CRIT_MUL_BASE=2.0` 区分两种语义：`critMul >= 2` 是绝对倍率，多件取最大；小于 2 是增量，逐层累加。`t_critdmg` 的 0.15 和幽属性增量均已接入，旧的「死天赋」结论已于 2026-10-16 修复。

辅助的绝对倍率（例如 2.2）与天赋增量可叠加；多个绝对倍率取最大。

> 📌 `TalentConfig.ts` 文件头注释描述了「`maxStacks = 1` 的唯一型天赋」机制，
> 但**表里没有任何 `maxStacks === 1` 的天赋**，所以 `talentSubtitle` 的 `'唯一'` 分支永远走不到。

### 5.3 ⚠️ `TalentDef.rarity` 与品阶是两套体系

`TalentDef.rarity` 是 **0~3 的 UI 配色**，与 `RarityConfig` 的 0~6 品阶
**命名相同、语义完全不同**。读代码时极易混淆。

## 六、战斗修正如何聚合（`FormGraph.aggregateModifier`）

### 6.1 签名与回调注入

```ts
export function aggregateModifier(
    loadout: RunLoadoutState,
    auxRankMulOf?:   (auxRootId: string) => number,
    auxRarityMulOf?: (auxRootId: string) => number,
    auxInnateOf?:    (auxRootId: string) => InnateBonus | undefined
): CombatModifier
```

**三个回调全部可选**（传 `undefined` 时 `rankMul = 1` / `rarityMul = 1` / `innate = undefined`）。

FormGraph **不 import GachaManager / SaveManager**，保持纯函数 —— 这样战斗相关测试不必建档。
与 `setElementResolver()` 由 GameEntry 注入是同一条工程原则。

唯一生产调用点：`LevelFlow.modifierOf()`（`LevelFlow.ts:687-694`），
三个调用点（战斗修正 / 战力快照 / 击杀经验）用同一份规则 ——
少一处注入就会出现"经验算升阶、伤害不算"的错位。

> 📌 历史文档只写 `aggregateModifier(loadout, auxRankMulOf?)`，实际是 **4 参**，
> 且漏了 `innate` 那行（它在 effect **之前**、且**不乘** mul）。

### 6.2 聚合算法

```
mod = emptyModifier()                      // critMul 起点 2.0
for a of loadout.auxes:
    f = formOfState(a)
    rootId = getRootOf(f.id)
    mul = (auxRankMulOf? auxRankMulOf(rootId) : 1)
        * (auxRarityMulOf? auxRarityMulOf(rootId) : 1)      // ★ 阶数 × 品阶，乘算
    innate = auxInnateOf? auxInnateOf(rootId) : undefined
    if innate: addEffect(mod, innate)                      // ★ 不乘 mul
    addEffect(mod, f.effect, mul)                          // ★ 乘 mul
    if f.atkPct: addEffect(mod, { atkPct: f.atkPct })       // ★ 不乘 mul
for id of loadout.talents:
    addEffect(mod, getTalentDef(id).effect, talents[id])   // ★ 乘层数
```

**倍率只放大 effect，不放大形态自带的 atkPct** —— `atkPct` 描述"这把东西的攻击方式有多强"，
阶数买的是"这个效果有多浓"，两者语义不同，混在一起会双重放大。

`addEffect` 规则：**critMul 取 `Math.max`，其余 15 个字段相加。**

### 6.3 修正如何作用到每一发攻击

| 字段 | 作用点 |
|---|---|
| `atkPct` | 单发伤害乘算 |
| `atkSpeedPct` | `interval = base / max(0.2, 1+atkSpeedPct)`，下限 0.2s |
| `critRate` / `critMul` | 命中时判定暴击，默认 `critMul = 2.0` |
| `lifesteal` | 造成伤害的一部分回血，每件武器各自结算 |
| `rangePct` | 放大 `range`（影响近战够不够得着、剑气多宽） |
| `extraShots` | 额外弹道数 |
| `maxHpFlat` | 生命上限，进场时加到 `playerHp` |
| `shield` / `thorns` | **走 `setup` 而不是武器表** |

**护盾与荆棘为什么单独走 setup**：它们是"玩家被打时"生效的属性。
挂在武器上会有两个问题 —— 合成会吃掉一把武器，挂在它身上的护盾就一起没了；
一把武器都不带时护盾会失效。

护盾在血条上方单独画一条，受击**先扣护盾再扣血**；
**荆棘只在近战接触时反伤** —— 远程弹丸打到身上不触发，
否则"站着不动弹死全场"会变成无风险的挂机策略。
