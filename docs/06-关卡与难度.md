# 06 · 关卡与难度

> 三档难度、解锁规则、难度驱动能力、远程怪上限、阵型与推荐、关卡曲线。
> 代码：`data/DifficultyConfig.ts` · `data/LevelConfig.ts` · `data/LevelAffinity.ts`

---

## 一、为什么是「每关 × 三档」而不是一条全局难度线

一条全局难度线（通关第 N 关后所有内容整体变难）有结构性缺陷：

```
玩家在第 12 关卡住
  → 唯一出路是"变强"
  → 变强只能靠打通第 12 关拿金币
  → 死循环
```

**每关独立解锁**没有这个问题：

```
第 12 关（困难）打不过
  → 回头打第 11 关的困难
  → 既能练手，金币产出还比第 12 关普通高 80%
  → 是平行可选项，不是唯一出路
```

这同时解决了另一个问题：玩家不需要"为了继续玩而被迫重复最讨厌的那一关"。

## 二、三档难度六维（`DIFFICULTY_TABLE`）

| 参数 | 普通 | 困难 | 噩梦 | 作用 |
|---|---|---|---|---|
| `hpMul` | 1.0 | 1.9 | **3.3** | 拉长单只敌人的对抗时间 |
| `atkMul` | 1.0 | 1.45 | **2.05** | 提高失误的代价 |
| `countMul` | 1.0 | 1.30 | **1.60** | 提高场面压力与走位需求 |
| `speedMul` | 1.0 | 1.10 | 1.20 | 压缩走位空间（**始终远低于玩家 330**） |
| `rangedRatio` | 10% | 24% | **42%** | **改变战斗结构**，见下 |
| `goldMul` | 1.0 | 1.8 | 3.0 | 高难度必须有回报，否则没人打 |
| `scoreMul` | 1.0 | 1.5 | 2.2 | 冲榜分数 |

其他每档参数：`kiteRange` 300 / 320 / 360 · `shotSpeed` 260 / 300 / 380 ·
`shotInterval` 2.4 / 2.0 / 1.5 · `MAX_TIER = 3`。

### 只加血量会把战斗从"刺激"变成"磨损"

玩家体感是累，不是难。所以前四个维度是量变（"同一件事做得更久/更痛"），
而**远程怪比例是质变**：

- 近战怪会一路贴脸，玩家站桩也能自动反击
- 远程怪保持 `kiteRange` 间距射击，站桩就只能挨打
- 想赢必须**主动绕后切入** —— 这正是拖动走位这个核心操作的存在意义

**远程怪比例把"站着不动也能赢"这件事直接废掉。**
难度提升因此被玩家"看得见"：不是血条变长了，而是敌人行为变了。

### ⚠️ 调参基调：微信小游戏，宁可偏简单

玩家绝大多数是碎片时间进来的泛用户。目标体验是"打得爽、进化快、死不掉"：

- 关卡间增长只有 **10%**（硬核向的 20%+ 曲线在这里会把玩家劝退）
- 敌人血量锚定在"玩家不继承也能轻松打掉"的水平
- 经验产出给得足，一局内就能看到进化

## 三、远程怪比例的硬上限（已统一为 45%）

### 3.1 现行值

```
普通 10%  ·  困难 24%  ·  噩梦 42%
RANGED_RATIO_MAX = 0.45      ← 跨档位硬上限，专门为噩梦档设置
```

**45% 是专门为噩梦档设的上限，不是三档通用上限**：

- 普通 10% + 关卡加成 + 复玩加难 → 最多 16%，**永远到不了 45%**
- 困难 24% + 同样的加成 → 最多 30%，**永远到不了 45%**
- 只有噩梦（42% 起步）才可能顶到 45%

**定 45% 的理由**：45% 之上同屏弹丸就太多了，玩家注意力被"躲弹"分走，
游戏从爽游变成手忙脚乱。（实测 50%+ 才会出现明显的手忙脚乱感，
但 45% 已经远超被动玩法能承受的水平。）

符合用户原始需求"只有恶魔难度达到 42% 甚至更高"。

### 3.2 关卡进度加成（`levelRangedBonus`）

```ts
// LevelConfig.ts:91-94
function levelRangedBonus(levelId: number): number {
    if (levelId <= 2) return 0;                      // 前 2 关不加
    return Math.min(0.03, (levelId - 2) * 0.0025);  // 每关 +0.25%，封顶 +3%
}
```

**每关 +0.25%，封顶 +3%（第 14 关封顶）**。同一档难度下越靠后的关卡，
远程压制越明显。前 2 关完全不加，保证新手看不到远程弹丸。

### 3.3 收敛公式

```ts
// LevelConfig.ts:151-154
const rangedRatio = Math.min(
    RANGED_RATIO_MAX,                                    // 0.45
    diff.rangedRatio + levelRangedBonus(levelId) + boost * 0.06
);
```

| 档位 | 基础 | +关卡（封顶） | +复玩加难（封顶 ×6%） | 收敛结果 |
|---|---|---|---|---|
| 普通 | 0.10 | +0.03 | +0.06 | **0.16** ≪ 0.45 |
| 困难 | 0.24 | +0.03 | +0.06 | **0.30** ≪ 0.45 |
| **噩梦** | 0.42 | +0.03 | +0.06 | 0.51 → **收敛到 0.45** |

**只有噩梦会真正触到上限**，这就是"上限不是摆设"的含义。

> ⚠️ **历史文档曾把这三个数写成 `10 / 24 / 34` + 封顶 40%，且 `levelRangedBonus`
> 写成"每关 +0.5%、封顶 +6%"** —— 那是第五轮的旧值，第六轮修补后没有回头改前文。
> 已按代码统一为 `10 / 24 / 42` + 封顶 45% + 关卡加成每关 0.25% / 封顶 3%。
>
> §七 保留了一段修订说明引文块，里面的旧值（34% / 40%）是**历史追溯，故意保留**，
> 并已加 📌 标注说明"不要按里面的数字调参"。

## 四、解锁规则

难度**只能靠"打过了"解锁**，不能跳级：

```
第 1 关：只有普通
  通关普通 → 解锁困难
  通关困难 → 解锁噩梦
```

顺序解锁保证玩家进入噩梦之前，已经通过困难采集到足够的金币把局外等级升上去，
并且拿到了难度专属装备。**不存在"直接跳级被劝退"的路径。**

### 为什么档位存在每关而不是全局

`maxTiers` 按 `levelId` 分开存（`{ "3": 2 }` = 第 3 关已解锁到困难），不是一个全局数字：

玩家可能第 8 关只能打普通，但第 9 关（敌人少、地形开阔）能打困难。
一个全局数字表达不了这种差异，而且会让"回头刷低难度"失去意义。

`globalMaxTier` 只是 `maxTiers` 的最大值，单独存在是因为**跨关卡的东西**需要它：
出战槽位数量、新装备的开放条件。

### 为什么顺序解锁比"打满 N 关解锁噩梦"更好

`maxTiers` 的语义是"这一关我已经打到第几档"，
而不是"这个玩家已经通关了多少关"。这样难度轴是**每关独立推进**的 ——
玩家可以在第 3 关就打到噩梦，不影响第 4 关的普通难度。

## 五、难度驱动能力扩张

难度不只是"怪更硬"，它同时是**能力解锁的闸门**。

### 5.1 出战槽位

```ts
// DifficultyConfig.ts:138,147-150
EQUIP_SLOT_LIMIT = 4;
getEquipSlotCount(globalMaxTier) = min(1 + globalMaxTier, 4)
```

| 全局最高难度 | 出战槽位 |
|---|---|
| 普通 | **2 件** |
| 困难 | **3 件** |
| 噩梦 | **4 件** |

**多一件武器不是数值增长 —— 它是多一套瞄准方式同时生效**：

```
2 件：前向挥砍（要瞄准） + 锁定射击（自动）
4 件：前向 + 锁定 + 最近（自动） + 移动向/全屏
```

玩家的操作负担不增反降，但输出结构完全不同。这是"推进难度"最直观的回报。

`EquipmentManager.syncProfile()` 在槽位增加时**自动补满**，
让玩家在通关那一刻就立刻感受到变化，而不用去背包里手动选。

### 5.2 新装备

| 装备 | 关卡 | 难度门槛 |
|---|---|---|
| 铁剑 / 短弓 | 1 | 普通 |
| 冰晶球 | 2 | 普通 |
| 长枪 | 3 | 普通 |
| **铁锤** | 3 | **困难** |
| 飞刃 | 4 | 普通 |
| **雷杖** | 5 | **困难** |
| **回旋轮** | 5 | **噩梦** |
| 巨镰 | 6 | 普通 |
| **重炮** | 7 | **困难** |
| 手里剑 | 8 | 普通 |

两条门槛是**"与"关系**而不是"或"：只推关卡不推难度，新装备一样拿不到。

## 六、噩梦专有的三种敌人

把"噩梦更难"从"怪更硬更多"升级成"怪有性格"。
这三种怪**只在噩梦出现**，普通 / 困难完全不会刷出（比例强制为 0）。

理由：它们各自把玩家逼向不同的应对动作，三种同时出现时玩家不可能靠单套走位套路撑过去。

| 种类 | 血 / 速 | 特殊 | 逼迫玩家做的事 |
|---|---|---|---|
| **精英 (elite)** | 3× 血 / 0.7× 速 | **护盾 = maxHp × 45%** | 持续输出，不能靠走位躲 —— 打它必须站桩 |
| **突进 (swift)** | 0.7× 血 / **1.7× 速** | — | 反应走位，看到它就要提前调整方向 |
| **冲锋 (charger)** | 1.2× 血（硬编码） | 蓄力 0.8s → 冲刺 0.5s × 3.5 倍速，命中 ×2 伤 | 读招预判，看到蓄力就要侧移躲冲刺 |

### 占比

```
eliteRatio   0.08   少而肉，一关只刷 1~2 只，是持续压力源
swiftRatio   0.12   较多，足够多的"突然加速贴脸"练习
chargerRatio 0.05   更少，太多会让战斗变成躲蓄力圈
剩余 0.75    普通近战 + rangedRatio 的远程
```

> 📌 状态机实现见 [01-战斗玩法 §6.3](01-战斗玩法.md)。
> ⚠️ `EnemySpawnSpec.chargerWindupSpeedMul` 声明了但**从未被读取**；
> 阶段 2 用硬编码常量，spec 覆盖只生效一半。

## 七、关卡公式化

### 7.1 曲线

```ts
levelScale = (1 + LEVEL_GROWTH)^(levelId-1) × DIFFICULTY_EASE
LEVEL_GROWTH = 0.10      // 关卡间增长 10%
DIFFICULTY_EASE = 1.0    // 全局旋钮：0.8 更简单，1.2 更难
最终敌人强度 = 关卡成长(levelScale) × 难度倍率(hpMul / atkMul …)
```

**这两个维度是正交的**，各自独立可调：

- 关卡成长让"同一难度下越往后越难"
- 难度倍率让"同一关的困难/噩梦明显更凶"

### 7.2 各关卡量的公式

| 量 | 公式 |
|---|---|
| 敌人数量 | `max(3, round((4 + floor(levelId/2)) × countMul × (1 + boost × 0.5)))` |
| 敌人血量 | `round(BASE_ENEMY_HP(55) × levelScale × hpMul × (1+boost))` |
| 敌人攻击 | `round(BASE_ENEMY_ATK(6) × levelScale × atkMul × (1+boost))` |
| 敌人移速 | `round(92 × (1 + (levelScale-1)×0.35) × speedMul)` |
| 每只经验 | `round((30 + levelId × 2) × (1 + (tier-1)×0.25))` |
| 通关金币 | `round((90 + levelId × 22) × goldMul × (1 + boost × 0.8))` |
| 关卡内 atk | `round(6 × levelScale)` |
| 关卡内 hp | `round(15 × levelScale)` |
| 分波 | `batchSize = max(2, ceil(enemies/3))`，`batchInterval = 3.2` |

`hasNextLevel(levelId) = levelId < 200` —— 关卡公式化至 **200 关**。

### 7.3 远程怪参数

| 参数 | 值 | 理由 |
|---|---|---|
| `rangedHpMul` | **0.72** | 比近战脆，鼓励玩家优先切入点掉 |
| `rangedSpeedMul` | **1.15** | 比近战灵活，会主动拉开距离 |
| `RANGED_SHOT_ATK_MUL` | **0.72** | 弹丸伤害刻意低于接触伤害 —— 远程怪数量多又是持续骚扰，如果单发和贴脸一样疼，高难度会变成"一进场就被秒"，那是劝退不是难度 |

### 7.4 不继承时的初始数据

```ts
initialStats = { atk: 0, hp: 100, critRate: 0.05, speed: 1 }
```

**刻意不随关卡变化**，且**不放装备的基础伤害**（避免"同一份攻击被算两次"）。
`hp` 给得厚（100）：走位玩法里玩家挨打往往是操作失误，一两次失误就死会让泛用户直接流失。

## 八、阵型：让"每关最合适的武器不一样"真的成立

### 8.1 阵型做两件事

`LevelAffinity.formationForLevel(levelId)` 给每关一个 `FormationKind`，
**战斗层的刷怪位置生成会照着它摆位**：

| 阵型 | 中文 | 刷怪位置特征 | 推荐（伤害 ×1.25 · 金币 ×1.30） | 克制（伤害 ×0.80） |
|---|---|---|---|---|
| `scatter` | 零散突进 | 从各方向零散出现，彼此离得远 | 单体精准 | 范围武器白给 |
| `line` | 成列推进 | 排成一列推进，前排挡住后排 | 贯穿一串 | 只能打一个的 |
| `cluster` | 密集扎堆 | 挤成一团冲过来，越打越密 | 范围 / 连锁 | 单体溢出 |
| `swarm` | 人海散兵 | 数量多但各自为战，满场乱窜 | 高频 / 全屏 | 慢速单体 |

**两条来自同一张表**，所以文案与数值永远不会打架。

### 为什么必须让阵型真的改位置

如果推荐武器只是 UI 上的一句话、而怪永远从同一个分布里冒出来，
玩家第一次不信、第二次就无视了。要做到"每关最合适的武器不同"，必须同时满足：

1. 关卡真的**有一种形状**
2. 那种形状真的**偏爱某些武器**（贯穿打一列很强、范围打散兵很弱）

### 阵型对武器强度的影响（"覆盖率红利"）

```js
const CLUMP = { scatter: 0.25, line: 0.55, cluster: 1.0, swarm: 0.8 };
const covEff = 1 + (coverage - 1) * CLUMP[formation];
```

覆盖率 1.8 的意思是"一次挥砍平均打到 1.8 个敌人"，
但敌人零散分布时场上根本没有 1.8 个敌人挨在一起，覆盖率就退化成 1。
**这张表是"阵型"这个概念唯一真正的数值落点** ——
如果所有阵型都用同一个系数，"每关最合适的武器不一样"就只是文案上的。

### 8.2 轮转：否则会退化成"每四种阵型里最合适的不一样"

阵型每 4 关循环，但**同一个阵型内部的推荐名单还会按关卡轮转**：

```
第 1 关 零散突进 → 铁剑 + 短弓
第 5 关 零散突进 → 短弓 + 重炮
第 9 关 零散突进 → 重炮 + 铁剑
```

否则"散兵关永远推铁剑+短弓"，玩家打十关看到的建议一模一样。

`AFFINITY_POOL` 只含 **12 把常规武器** —— 高阶专属 6 把**不进推荐池**
（它们走抽卡引导，硬塞进去会同时破坏战力平衡与轮转节奏）。

### 8.3 刻意不做成硬克制

带推荐 ×1.25、带克制 ×0.80，是"带了明显更爽"，不是"必须带"。
做成硬克制会让泛用户卡关，而这是个微信小游戏，不是硬核 Roguelite。

同时命中推荐与克制时两者抵消为 ×1.0（`AFFINITY_MIN_COUNT = 1`）。

## 九、调参顺序

如果后期太软，按这个顺序调：

1. `DIFFICULTY_TABLE[].hpMul` —— 先加噩梦（3.3 → 3.8），不动普通
2. `LEVEL_GROWTH` —— 0.10 → 0.13，让关卡间成长更陡
3. `EQUIPMENT_TABLE[].levels[].upgradeCost` —— 抬高局外升级成本，放缓战力增长
4. `EQUIP_SLOT_LIMIT` —— 4 降到 3（但会削弱"难度推进的回报"）

**不要动 `DIFFICULTY_EASE` 除非整体都要调** —— 那是全局旋钮，会把普通难度也一起调难，
破坏"不惩罚新手"的基调。
