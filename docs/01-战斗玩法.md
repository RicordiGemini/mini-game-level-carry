# 01 · 战斗玩法

> 玩家在关卡里到底怎么动、怎么打。
> 代码：`battle/` 为无引擎依赖的模拟；`ui/BattleLayer.ts` 与 `ui/DragInput.ts` 是 Cocos 展示/输入组件。

---

## 一、核心设计：两个正交维度

**攻击方式 = 瞄准方式（打谁） × 打击形状（打几个）**

这两个维度在 `FormNode` 上是分开的字段（`aimModeId` / `attackModeId`），任何一把武器或形态都是在
这两个维度各取一个值。换一把武器就等于换一套操作手感 —— 这是全作手感的来源。

代码入口：`data/FormConfig.ts` 的 104 个形态节点、`data/EquipmentConfig.ts` 的 18 把武器。

## 二、五种瞄准方式（`AimModeId`）

| 枚举 | 名称 | 方向来源 | 有记忆 | 需要走位 | 代表武器 |
|---|---|---|---|---|---|
| 0 `FRONT` | 前向 | 玩家朝向 | — | **必须** | 铁剑 / 长枪 / 巨镰 |
| 1 `LOCK_ON` | 锁定 | 锁定的敌人 | ✅ 目标死/出射程才换 | 不需要 | 短弓 / 重炮 / 光矛 |
| 2 `MOVE_DIR` | 移动向 | 拖动方向 | ❌ 实时跟随 | 需要（决定方向） | 铁锤 / 飞刃 / 手里剑 |
| 3 `NEAREST` | 最近 | 最近的敌人 | ❌ 每次重算 | 不需要 | 冰晶球 / 雷杖 |
| 4 `SCREEN_ROLL` | 全屏 | 无方向 | — | 不需要 | 回旋轮 |

三者最易混淆的：`FRONT` 完全不索敌，背后有敌人也照挥（玩家可以故意打空）；
`NEAREST` 每帧重算，两个敌人交替靠近时弹道左右横跳；`LOCK_ON` 锁住不放，目标死了才换。

**回退链**（`FormGraph.ts:51-56`）：`form.aimModeId` → 根形态 `aimModeId` → `FRONT`。
实际 104 个形态全部显式配了 `aimModeId`，兜底分支不可达。

### 2.1 射程：默认等于全屏

`BattleWorld.engageRange` 不传时等于**场地对角线**：
`sqrt(720² + 1280²) ≈ 1468.6`（`BattleTypes.ts:112-114`）。

索敌射程统一全屏，武器差异只体现在**打击尺度**上。
理由：武器差异靠"谁够得着"来区分，玩家只会当成 bug。

想让某关做"够不着就不开火"的克制手感，给 `BattleSetup.engageRange` 传小值即可。

### 2.2 射程外解锁 + 停火

`LOCK_ON` / `NEAREST` 共用一条规则（`AimResolver.ts`，`AIM_RANGE_SLACK = 1.6`）：
目标超出 `射程 × 1.6` 时**解锁 + 停火**，而不是对着打不到的目标空挥；目标回到射程内立刻恢复锁定。

默认射程全屏，所以这条规则平时不触发 —— 它是给"将来加相机 / 敌人跑出可视范围"留的安全网。

`FRONT` 与 `MOVE_DIR` **不受此约束** —— 它们本来就允许打空，那是玩家主动的选择。

### 2.3 弹道飞行距离：不打空气

`WeaponSpec.range` 只管**打击尺度**（近战够不够得着、剑气多宽），**不决定够不够得着**。
弹道能飞多远由 `AttackFactory.travelDist()` 单独算：

```
有目标：min(全屏射程, max(武器射程, 目标距离 + AIMED_SHOT_TAIL))
无目标：全屏射程
穿透弹：全屏射程（设计意图就是一路贯穿全场）
```

`AIMED_SHOT_TAIL = 90`（`BattleTypes.ts:120`）。三条规则各解决一个问题：

1. **目标距离 + 尾巴** → 保证「锁定了必定打得到」。否则会出现"锁定 400px 外的敌人、
   子弹飞到 337px 就凭空消失"，这是最典型的假 bug 来源。
2. **`max(武器射程, …)`** → 武器射程变成弹道的**最短飞行距离**，进化表的「攻击距离%」依然有意义。
3. **`min(全屏射程, …)`** → 上限就是场地对角线，不飞出屏幕做无用飞行。

## 三、十种打击形状（`AttackModeId`）

> ⚠️ **术语澄清**：枚举有 10 个值，但落地为 **9 种判定体**
> （`ProjectileKind` 9 种，`AttackFactory` 9 个实现函数，
> `SINGLE_RANGED` 与 default 分支共用实现）。历史文档"十种打击形状"的说法不严谨。

| 枚举 | 名称 | 实现要点 |
|---|---|---|
| `SINGLE_MELEE` | 近战单体 | `attachDist` 挂玩家身上，随走位移动 |
| `SINGLE_RANGED` | 远程单体 | 辅助装备统一用这个（文案"挂件射击"） |
| `TRIPLE_SHOT` | 三连射 | **散布 ±7°**（`0.1222 rad`）；**每发伤害 ×0.62** 后取整 |
| `SWEEP` | 范围剑气 | 扇形判定，半径 = 武器射程 |
| `PIERCE` | 穿透直线 | speed 780，半径 19，`pierce = w.pierce ?? 5` |
| `SHOCKWAVE` | 震荡波 | 以自身为中心扩散，`growRate = range × 2.2`，`r0 = range × 0.35` |
| `RAIN` | 剑雨覆盖 | 单发 delay 0.32 / dmg ×0.85 / 半径 58；全屏 delay 0.30 / dmg ×0.7 / 半径 66 |
| `CHAIN` | 连锁闪电 | speed 1500，寿命 `max(.1, min(.8, travel/1500))`，跳数 `max(1, min(8, 3+floor(chainBonus)))` |
| `METEOR` | 陨石轰击 | **落地预警 delay 0.42 + 存在 life 0.20**（实际 0.62s），伤害 ×2.2，半径 `max(90, range × 0.55)` |
| `FULL_SWEEP` | 全屏滚动 | speed 900，行程 `W+140 = 860`，半径 76，起始点 ±70 |

### 3.1 三连射的 0.62 衰减（重要）

`AttackFactory.buildBullet` 在 `count > 1` 时，**每发**伤害要乘 0.62 再取整。
真实 DPS = `3 × round(单发 × 0.62) / 间隔`，**不是** `单发 / 间隔`。

漏掉 0.62 会把三连射高估约 1.9 倍 —— 历史上平衡脚本就因此误判，
把飞刃与手里剑一起上调了伤害，被 `balance_guard` 挡下后才回退
（飞刃 5→4、手里剑 6→5）。

**教训：任何"每次攻击多发"的形态，都必须按 `多发 × 单发衰减 / 间隔` 算真实 DPS。**

### 3.2 额外弹道（extraShots）的散布

`attachDist >= 0`（近战类）→ 以 60px 间距向两侧线性外推；
否则 → 弹道角度 `±0.17 rad`（≈9.74°），左右交替，判定体 id 从 `900000` 起递增。

## 四、拖动走位（`ui/DragInput.ts`）

两种模式，`dragMode` 切换：

### JOYSTICK（默认，推荐）
相对拖动 / 虚拟摇杆。方向 = `当前点 − 起点`，力度正比于拖动距离。
手指可放屏幕任意位置（不挡角色），力度可调，死区 **14px**。

### FOLLOW
角色朝手指位置跑，越远越快，进入 **100px** 到位半径停下。
直觉最强，新手一秒上手；代价是手指挡住角色，精细走位稍差。

两种模式最终归一到同一输出：**方向 + 强度**。战斗层完全不需要知道用的是哪种输入。

### 4.1 必须逐帧轮询，不能只靠回调

**手指按住屏幕不动时，系统不再派发 `TOUCH_MOVE` 事件。**
若角色移动只由触摸回调驱动，玩家按住不动那一刻输入就丢了、角色半路停下
—— 这是真机必现、编辑器里不易复现的问题。

解法：`DragInput.compute()` **每帧轮询重算**（`GameEntry.update` 调用）。
`FOLLOW` 模式更是必须轮询：角色一边跑一边靠近手指，方向得实时重算才不会绕着手指画圈。

安全网：`BattleWorld._inputHold` 保留 **0.12 秒** —— 事件彻底丢失时角色会自行停下，
而不是一直朝某个方向跑。

## 五、战斗循环

当前关卡接入定时三波：每波 30 秒，波内持续补怪，同屏上限 240；末波结束后清场通关。无固定击杀配额，数量配置仅作未限流估算。每波内部统一生命、攻击及远程/冲锋伤害，禁用精英护盾差异；下文种类血量/护盾倍率保留给旧固定数量接口。详细数值见 [关卡与难度](06-关卡与难度.md)。定时模式玩家受击保护 0.35 秒，避免同帧怪群重复扣血；死亡实体及时清理。

战败后进入 `DEFEAT`，不再等待 2.2 秒自动重开。面板展示本局击杀、得分、用时、局内金币、等级、经验及装备，玩家可广告复活继续、免费保留成长重试或返回选关。复活保留波次进度并满血重建；重试从首波开始，但历史敌人奖励不重复发放；返回选关放弃临时收益，未通关不发永久结算奖励。战败标记保存后，重启仍回到选择面板。当前战场重建范围见 [存档与继承](07-存档与继承.md)。

`BattleWorld.update(dt)` 每帧顺序（**顺序错了会穿模和重复结算**）：

```
1. updatePlayer      读取拖动输入 → 移动玩家 → 更新朝向
2. fireWeapons      每件武器独立结算冷却 → 瞄准 → 生成判定体
3. updateProjectiles 判定体移动 + 命中判定 + 伤害结算
4. updateEnemyShots 远程弹丸飞行与命中
5. updateEnemies    敌人 AI
6. updateSpawn      分波投放
7. cleanup           清理死亡实体
8. checkEnd          判定胜负
```

> 📌 历史文档写"6 步"，那是加入 `updateEnemyShots` 与 `updateSpawn` 之前的版本。

### 5.1 每件武器独立开火

玩家同时带 2~4 件装备，各自按自己的瞄准方式工作。铁剑在前方挥砍的同时、
短弓锁定另一个目标射箭 —— "换武器 = 换手感"才真正成立。

### 5.2 判定体而不是子弹

近战挥砍、震荡波、陨石不是飞行物，但和子弹共享同一套生命周期：
**出现 → 存在一段时间 → 判定命中 → 消失**。统一成 `Projectile` 后循环里只有一条 update 分支。

| 字段 | 用途 |
|---|---|
| `attachDist` | 挂靠在玩家身上（沿朝向），走位时判定跟着动。挥砍/剑气/震荡波用它 |
| `growRate` | 半径持续变大。震荡波扩散用它 |
| `delay` | 落地延迟。陨石/剑雨先用空心圈预警，给玩家反应时间 |
| `pierce` | 剩余穿透数，`-1` = 无限 |
| `chainLeft` | 连锁剩余跳数 |

### 5.3 固定随机种子

`setup({ seed })` 固定后整场战斗可完整复现。默认种子 **`20261014`**
（`BattleTypes.ts:629`），rng 是 mulberry32。
关卡号可当种子（`1000 + levelId × 977`），因此"第 7 关打不过"能稳定复现定位。

## 六、敌人设计

### 6.1 两条底线

1. **敌人移速（92）必须明显低于玩家移速（330）。** 这是走位游戏，
   敌人跑得比玩家快的话走位就失去意义，玩家会被无限贴脸。
   压力只能来自"数量多、从多方向来、远程压制"，不是"跑得快"。
   注意：关卡成长会缓慢抬升敌人移速（`LevelConfig.ts:189`：
   `92 × (1 + (levelScale-1) × 0.35) × diff.speedMul`），但始终远低于玩家。
2. **不从下边缘刷怪**，出生点与玩家保持 **260px** 以上。贴脸刷怪在走位游戏里是致命的。

### 6.2 五种敌人

| kind | 出现档位 | 血/速 | 特殊 |
|---|---|---|---|
| `melee` | 全档 | 1× / 1× | 贴脸攻击 |
| `ranged` | 全档 | **0.72×** / 1.15× | 保持 `kiteRange` 间距射击，弹丸伤害 ×0.72 |
| `elite` | **仅噩梦 8%** | **3×** / 0.7× | **护盾 = maxHp × 45%** |
| `swift` | **仅噩梦 12%** | 0.7× / **1.7×** | 高速突进 |
| `charger` | **仅噩梦 5%** | **1.2×**（硬编码） / 1.0×（硬编码） | 蓄力 0.8s → 冲刺 0.5s × 3.5 倍速，命中 ×2 伤害 |

噩梦三怪合计 25%，其余 50% 是普通近战 + 42% 远程。
比例设计意图：精英少而肉（持续压力源）、突进较多（足够练习突然加速贴脸）、
冲锋更少（每次都给读招预判的考验，太多会变成躲蓄力圈）。

> 📌 **代码与文档的已知不一致**：`EnemySpawnSpec.chargerWindupSpeedMul` 声明了但**从未被读取**；
> 冲锋怪阶段 1 用 spec 的 `chargeMax`/`chargeSpeed`，阶段 2 却用硬编码常量
> `WINDUP_SPEED_MUL(0.3)` / `DASH_TIME(0.5)` —— **spec 覆盖只生效一半**。

### 6.3 冲锋怪三阶段状态机

```
1) 走近（chargeTimer == 0）
   → 玩家进入 trigger 范围（kiteRange × 0.7）→ 进入蓄力
2) 蓄力（chargeTimer > 0）
   → 几乎不动（speed × 0.3），锁住方向
   → 蓄力 0.8s 完成 → 进入冲刺
   → 玩家跑出 trigger × 1.4 → 取消蓄力，回到阶段 1
3) 冲刺（isCharging）
   → 朝 chargeDir 冲刺 0.5s（speed × 3.5）
   → 撞到玩家 → chargeDmg 单次高伤
   → 时间到 → 回到阶段 1
```

**为什么计时在状态机里减，而不是主循环里减**：主循环统一减所有 cd 省事，
但 `chargeTimer` 必须用 `chargeTimer - dt <= 0` 判完成 —— dt 是浮点，
主循环减过再判断会出现 0.0003 之类的残留值，让"完成 → 进入冲刺"这一支被跳过。
蓄力是"我曾经进入过这个状态"才有意义，所以计时收在子函数里。

### 6.4 位置钳制的不一致

`melee` **不做位置钳制**；`elite` / `swift` **只在移动分支内**钳制边界。
这是代码现状，非设计意图，如需修正见 `12-缺口与风险.md`。

## 七、局内成长如何当场生效

```
击杀敌人
  → BattleWorld 触发 onEnemyKilled
      → LevelFlow.onEnemyKilled()
          → 加分 / 掉资源 / gainExp()
              → 达级写入 pendingLevelUps，整帧群杀逐只结算并去重
                  → 帧末 flushBattleRewards() 同步击杀成长，再逐级 openReward()
                  → phase = 'REWARD'
                      → RewardPanel 弹出；GameEntry.update() 直接 return（战斗真的冻结）
                          → 玩家选卡 → LevelFlow.chooseReward(i)
                              → applyReward() 改局内 build
                                  → onLoadoutChanged → GameEntry.syncCombatLoadout()
                                      → syncWeapons / syncPlayerStats 更新武器和玩家属性
                              → 合成？→ 立刻再开一次三选一（补选）
                              → 否则 → phase = 'PLAYING'，战斗继续
```

### 7.1 两处容易踩的点

所有选卡（含强化、辅助及天赋）共用属性同步入口；同步保留现有武器冷却、已经损失的生命和消耗的护盾。清场时若仍有升级奖励，选完后才完成一次性通关结算。

1. **冻结必须是"真的不推进世界"，不是"不画"。**
   `GameEntry.update()` 在 `REWARD` / `REPLAY_BOOST` 阶段直接 `return`，不调 `tick(dt)`。
   只把面板盖在画面上而世界继续 tick，玩家会在选卡时被围殴致死。

2. **`REWARD` 显示战斗层，`REPLAY_BOOST` 不显示。**
   `REWARD` 是**战斗中**弹出的，背景留着刚打出来的战场最连贯；
   `REPLAY_BOOST` 是**进关之前**弹出的，此时战斗层里只有上一关残留画面，
   显示会让玩家误以为"我已经开打了"。两个阶段不能用同一个标志位。

### 7.2 syncWeapons 保留什么

`BattleWorld.syncWeapons()`（`BattleWorld.ts:462-472`）按 `equipId` **就地合并**，
**只保留 2 个字段**：

- **冷却 `cd`** —— 否则进化瞬间会白送一发，手感很怪
- **锁定 `lockedId`** —— 进化不该丢掉当前锁定的目标

其余字段全部覆盖，数组整体替换。

> 📌 历史文档称 syncWeapons 在 `RunLoadout` 里，实际在 `BattleWorld.ts` 与 `BattleLayer.ts`。

## 八、渲染层

`ui/BattleLayer.ts` 用 `Graphics` 直接画圆和矩形，**零美术资源就能跑通完整玩法**。

这是刻意取舍：预制体方案需要先做一套美术资源，工程拿到手跑不起来。
用 Graphics 先验证手感和数值，等玩法定下来再逐个换成预制体 + 序列帧。

配色即语义，调试时一眼可辨：

| 对象 | 颜色 |
|---|---|
| 玩家 | 蓝色实心圆 + **朝向短线** |
| 敌人 | 红色实心圆（击中闪白，受伤后显示血条） |
| 锁定目标 | 红色双环标记 ← 让"锁定"与其他四种瞄准一眼区分 |
| 近战/剑气 | 黄 |
| 弹丸 / 穿透 | 绿 / 青 |
| 震荡波 / 陨石 | 橙 / 深橙 |
| 剑雨 | 紫 |
| 连锁闪电 | 蓝 |
| 全屏滚轮 | 粉 |
| 落地预警 | 白色空心圈 |

**朝向短线**是"前向攻击能不能命中"的唯一视觉依据，不能省。
