## 一、加内容的标准步骤

### 1.1 加一把常规武器

约 5 步，不动架构：

1. `data/EquipmentConfig.ts` 的 `EQUIPMENT_TABLE` 加一条
   （含 `id` / `name` / `type` / `aimMode` / `unlockLevel` / `unlockDifficulty` / `levels[]`）
2. `data/EquipmentConfig.ts` 的 `WEAPON_BASE_RANGE` / `WEAPON_BASE_INTERVAL` /
   `WEAPON_BASE_PIERCE` 各加一项
3. `data/FormConfig.ts` 的 `WEAPON_ROOT_IDS` 加 id
4. 写形态节点（建议 depth 0~3，depth 4 视需要）
5. 想让它在某关被推荐 → 往 `data/LevelAffinity.ts` 的 `AFFINITY_POOL` 加

> ⚠️ **第 3 步漏了会静默出错**：`WEAPON_ROOT_IDS` 是硬编码列表，
> 同时是 `fillSources()` 的遍历依据。漏掉任何一个根形态，那个形态的 `sources`
> 会停留在 `[]`，基础伤害算不出来。
> 形态图自检（`validateFormGraph`）会报"武器形态缺少 sources"。

> ⚠️ **没有 `WEAPON_BASE_DAMAGE`** —— 基础伤害只能在 `levels[].baseDamage` 里逐把手写。

### 1.2 加一把高阶专属武器

在 1.1 的基础上额外需要：

1. `EQUIPMENT_TABLE` 里设 `rarity`（出生品阶，钻石=3 / 史诗=4 / 神话=5）
2. `data/FormConfig.ts` 里给根形态配 `innate`（自带复合属性）
3. **不要**加进化线 —— 高阶专属的强度来自品阶，不是局内深度
4. **不要**加进 `AFFINITY_POOL` —— 会破坏推荐/克制的战力平衡与轮转节奏

### 1.3 加一条合成配方

1. `data/FormConfig.ts` 的 `FUSION_RECIPES` 加一条 `{ a, b, to, advanced? }`
2. 给产物写一个 `FormNode`

**配方会被校验**（`validateFormGraph` 第 13 组），任一条不满足直接报错：

- `a` / `b` / `to` 必须都存在于形态表
- 产物必须是 `kind === 'weapon'`
- `a !== b`
- 产物 `sources` 不能为空
- `t.depth >= max(a.depth, b.depth)`
- **`t.atkPct > max(a.atkPct, b.atkPct)`** —— "合完反而更弱"会被判为配置错误

### 1.4 加一件辅助装备

同武器，但**只能挂 `upgrade` 边** —— 这是硬校验，配置错了启动即报错，
不会等到线上让玩家的辅助装备凭空消失。

写进 `data/AuxConfig.ts`，并加入 `AUX_ROOT_IDS`（14 项）。

### 1.5 加一件防具

最简单：在 `data/ArmorConfig.ts` 的 `SET_THEMES` 加一条主题，
`buildSet` 会自动生成 4 个部位。`allArmorPieces()` 自动变成 96 件，
抽卡池、保底、全收集判定全部自动跟随。

> ⚠️ 全收集判定用「去重后的部件数 >= 92」的硬编码，需要同步改 `GachaManager.pull()`。

### 1.6 加一条属性

1. `data/ElementConfig.ts` 的 `ELEMENT_IDS` 加 id
2. 加进某个 `ELEMENT_GROUPS` 组
3. 配 `ELEMENT_DEF`（含 `effectText`）
4. `data/MaterialConfig.ts` 的 `STONE_NAME` / `SHARD_NAME` 加名字
5. 加进 `OMNI_SHARD_COST`

> ⚠️ 组内种类数变了会影响 `LEVELS_PER_GROUP` 的对齐不变式，
> 四条不变式（互不重复 / 双属性重叠 / 单属性不重叠 / 换组不同）都要成立。

### 1.7 加一条天赋

`data/TalentConfig.ts` 的 `TALENT_TABLE` 加一条。
`kind`（如果有）必须在 `AchievementManager.progressValue()` 已支持的类型内。

> ⚠️ **`critMul` 有绝对/增量两种语义**（2026-10-16 修复）：
> - `>= 2.0` → **绝对倍率**（辅助装备 2.2 / 2.3 / 2.8），多件取max 不叠加
> - `< 2.0` → **增量**（天赋 0.15 / 幽属性 0.35），逐层累加
>
> 加新条目时必须想清楚自己写的是哪一种：
> 「暴击伤害 2.5 倍」写 2.5；「暴击伤害 +0.25 倍」写 0.25。
> 写错语义不会报错，只会让它默默失效 —— 这正是原来`t_critdmg` 死掉的原因。

## 三、踩过的坑（不要重犯）

### 3.1 三连射 DPS 被高估 1.9 倍

`AttackFactory.buildBullet` 在 `count > 1` 时**每发**伤害乘 0.62 再取整。
真实 DPS = `3 × round(单发 × 0.62) / 间隔`。

漏掉 0.62 会把三连射高估约 1.9 倍 —— 平衡脚本曾据此把飞刃与手里剑
一起上调了伤害，被 `balance_guard` 挡下后才回退。

> **任何"每次攻击多发"的形态，都必须按 `多发 × 单发衰减 / 间隔` 算真实 DPS。**

### 3.2 长枪曾是光矛的严格下位

两者都是 `PIERCE`，但长枪是 `FRONT`（要靠走位对准、约 1/3 挥击打空），
光矛是 `LOCK_ON`（自动瞄准、从不落空）且射程更长。
硬数据显示长枪 11 发只打出 70 伤害（约 36% 打空），光矛 8 发打出 120。

> **`PIERCE` 不能所有武器统一给一个穿透数，"能不能自动瞄准"必须参与定价。**

### 3.3 巨镰曾是全阵型最优解

它是 `SWEEP`（半径 = 射程×0.7、命中范围内全部敌人），
却只有 0.72s 间隔，而铁剑同为"近身全命中"半径只有 0.5×射程。
结果是"每关最合适的武器都不一样"这个设计目标根本不成立。
已把间隔拉到 0.95s 并下调伤害。

> **覆盖面积大 ≠ 可以更快。** 横扫的覆盖面积是近战的 4 倍以上，
> 间隔不拉开就会变成通用最优解。

### 3.4 锁定 400px 外的敌人却打不到

子弹寿命原本按武器射程算，锁定 400px 外时子弹飞到 337px 就凭空消失。
改为按全屏射程飞行，并在目标身后 90px 收尾（`AIMED_SHOT_TAIL`）。

> **这是最典型的"假 bug"来源。** 索敌射程与弹道飞行距离必须是两个概念。

### 3.5 三选一死锁

补选时池子已空，`openReward()` 原本只 `return`，阶段永远卡在 `REWARD` ——
战斗停住、面板不弹、玩家只能重启。

> **三选一死锁是最难查的那类线上问题。** 所有"提前 return"的分支
> 都必须确认阶段会被正确归位。

### 3.6 手指按住不动时输入丢失

系统不再派发 `TOUCH_MOVE`。若角色移动只由触摸回调驱动，
玩家按住不动那一刻角色就半路停下。

> **真机必现、编辑器里不易复现。** 任何输入驱动的逻辑都必须逐帧轮询重算，
> 并留一个 `_inputHold` 安全网。

### 3.7 `!!indexOf()` 误删首元素

```ts
// 错误：indexOf 对首元素返回 0，!!0 === false
list.filter(x => !!x && !!ARR.indexOf(x));
// 正确
list.filter(x => !!x && ARR.indexOf(x) >= 0);
```

> **测试断言不要用 `indexOf('短字符串')` 做否定判断** ——
> 这不止影响断言，同样会咬到生产代码。

### 3.8 品阶 0 被当哨兵值

`canCraftArmor` 用 `rarity > 0` 判断持有，而品阶 0（青铜）是合法品阶，
结果青铜防具永远可以重复打造。

> **0 是合法值，不能拿来当"未持有"的哨兵。** 直接查数组里有没有这个 id。

### 3.9 升阶燃料按 id 排除

同 id 的重复件恰恰是最主要的燃料来源。若按 id 排除，
会出现"有两把铁剑却提示燃料不足 0"。

> **按对象引用排除，不要按 id 排除。**

### 3.10 `WEAPON_ROOT_IDS` 漏加新武器

漏掉的那个形态 `sources` 停留在 `[]`，基础伤害算不出来。
形态图自检能抓住，但要主动跑。

### 3.11 蓄力计时不能放在主循环

主循环统一减所有 cd 省事，但 `chargeTimer` 必须用 `chargeTimer - dt <= 0` 判完成 ——
dt 是浮点，主循环减过再判断会出现 0.0003 之类的残留值，
让"完成 → 进入冲刺"这一支被跳过。

> **凡是"我曾经进入过这个状态"才有意义的状态机，计时收在自己的子函数里。**

### 3.12 `RANK_SOCKET_SLOTS` 长度必须等于 `MAX_WEAPON_RANK`

`socketSlotsOf()` 用 `rank - 1` 直接索引，长度对不上会读到 `undefined`，
然后 `while(len < undefined)` 恒假、紧接着 `.length = undefined` 抛 `RangeError`，
**5 阶突破后打开面板就崩**。

> ⚠️ **此坑已随整套 rank 系统删除而消失**（函数零调用点）。

## 五、架构不变量（改动不得破坏）

1. **战斗层不认识属性表 / 装备表** —— `battle/` 只吃 `WeaponSpec` 与 `BattleSetup` 两个纯数据接口。
2. **没有任何成长动作必须看广告** —— 所有 `Manager` 函数不接收广告参数。
3. **重复件必须有回报**，绝不静默消失。
4. **抽卡不提供数值碾压** —— 抽到的一律 1 级（品阶例外见 [04](04-抽卡与经济.md)）。
5. **刻意不做成硬克制**（推荐 ×1.25 / 克制 ×0.80，是"更爽"不是"必须带"）。
6. **单条线不能点满** —— 无视克制必须由金币、品阶、镶嵌三样共同投入。
7. **推荐与数值同源** —— 阵型表既决定刷怪分布，也决定推荐/克制名单。
8. **教学只讲"现在该做什么"，且同一条提示只弹一次**。
9. **纯函数层不被污染** —— `FormGraph` 不 import `GachaManager` / `SaveManager`，
   靠回调注入（`aggregateModifier` 的 3 个可选参数）。
10. **形态图必须自洽** —— `validateFormGraph()` 的 **23 条**校验任一不过就是配置错误。
    （历史文档写"14 条"是错的，实际 `errors.push` 有 23 个分支。
    每条都有对应测试，并用变异测试验证过 23/23 都能被抓到。）

## 六、环境说明

### 6.1 类型检查（✅ 2026-10-16 已可用）

```bash
npx tsc --noEmit -p tsconfig.json
```

**当前状态：全工程 0 错误**（48 个 .ts / 20219 行）。

`tsconfig.json` + `types/cc-stub.d.ts` 是本轮新增的。
Cocos 的类型定义在 `temp/declarations/` 下，而 `temp/` 是 gitignore 的生成物 ——
**没有 stub 的话，克隆下来的仓库无法做任何类型检查**。
stub 只声明工程实际用到的 13 个引擎成员，让 tsc 聚焦检查我们自己写的逻辑。

> ⚠️ 用 Cocos 编辑器打开工程后，编辑器会在 `temp/declarations/` 生成真实类型。
> 如果希望用真实类型检查，把 tsconfig 里的 `paths.cc` 指向它即可：
> `"cc": ["temp/declarations/cc.d.ts"]`

#### 为什么需要 cc 桩

配置表 `import { ... } from 'cc'`，而 cc 只在运行时由引擎提供。
`build-tests.mjs` 生成一份最小桩并把 `from 'cc'` 重定向过去。

另外两个必须处理的细节：

- **Node 的 ESM 解析器不认不带扩展名的相对路径**（`./GameTypes` 会失败），
  而 tsc 输出的 ES2020 模块保持原样 —— 所以编译后必须统一补 `.js`。
- 产物目录要放一份 `package.json` 声明 `{"type":"module"}`，
  否则 Node 会报 `MODULE_TYPELESS_PACKAGE_JSON` 并反复尝试按 CommonJS 解析。

#### 测试的核心思路：喂坏数据，不是验"当前是对的"

`form_graph.test.mjs` 的每条用例都是这个结构：

```
① 造一份最小的坏配置 → ② 断言校验器报出对应错误 → ③ 断言只报这一条
```

只验"当前配置通过"的话，**校验逻辑写错了测试也会绿**。

为此 `validateFormGraph()` 已重构为两层（生产行为不变）：

```ts
// 生产入口，签名与行为完全不变
validateFormGraph(): string[]

// 纯函数版，供测试注入畸形数据
validateFormGraphData(forms, recipes, weaponRoots, auxRoots): string[]
```

再跑测试看是否变红。**当前 23/23 全部被抓到。**
