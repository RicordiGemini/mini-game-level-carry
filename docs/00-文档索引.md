## 一、怎么用这个目录

### 1.1 文档边界规则（写新内容前必读）

**一种类型 = 一份文档。** 新增内容先判断它属于哪一类，然后写进对应文档，**不要**在已有文档里新开一个大章节。

| 我要写的内容 | 写到哪份 |
|---|---|
| 战斗手感、瞄准、打击形状、敌人 AI、渲染 | `01-战斗玩法.md` |
| 局内成长：三选一、形态进化、合成、天赋、槽位 | `02-局内成长.md` |
| 武器 / 辅助 / 防具的养成轴、数值表 | `03-装备养成.md` |
| 抽卡、许愿水晶、祝福值、碎片兑换 | `04-抽卡与经济.md` |
| 24 属性、克制、破防、关卡属性编排 | `05-属性与锻造.md` |
| 三档难度、解锁规则、阵型、关卡曲线 | `06-关卡与难度.md` |
| 存档结构、版本迁移、继承、复玩加难 | `07-存档与继承.md` |
| 新手引导、首通教学、成就 | `08-新手引导与成就.md` |
| 广告位、变现策略、提审 | `09-广告与变现.md` |
| 加内容怎么改、调参入口在哪 | `10-开发指南.md` |
| 全部数值速查 | `11-数值总表.md` |
| **还没做的、已知缺口、风险** | `12-缺口与风险.md` |

判断不准时，问自己：**这条内容如果不改代码就永远不会变，它属于哪份？** 属于 `12-缺口与风险.md`。其余都属于"已实现"，归到对应模块。

### 1.2 写文档的三条硬规矩

1. **数值必须能指到代码行。** 写 `10 / 24 / 42`，就注明 `DifficultyConfig.ts:57,74,91`。
2. **代码里没有的，不许写成已有功能。** 未实现的写进 `12-缺口与风险.md`。
3. **改代码后必须回头改对应文档。** 文档滞后于代码是这个目录唯一不可接受的缺陷 —— 历史上已经因此产生过 40+ 处矛盾。
