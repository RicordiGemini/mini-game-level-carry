## 二、🔴 P0 · 仍开放的功能性缺陷

### 原 A-1（已关闭，留档）· 防具词条 / 套装 / 镶嵌增益没接入战斗

**事实链**：

1. `ForgeManager.armorBonus()` 实现了完整的聚合逻辑（单件 innate + 套装 2/4 件 + 镶嵌石）
2. `GameEntry.ts:48` 的 import 列表里**没有** `armorBonus` ——
   只 import 了 `armorCounterBreak` / `currentResist` / `maxCounterBreak`
3. 战斗 setup（`GameEntry.ts:214,218`）只用了 `currentResist()` 与 `maxCounterBreak()`
4. `armorBonus()` 的**唯一调用点是 `ForgePanel.ts:521`** —— UI 展示

**后果**：

- 防具的**单件 innate 词条**（如 `atkPct 0.04`）在战斗中不生效
- 防具的**套装 2/4 件属性**（传说大套 7 条）不生效
- 防具的**镶嵌属性石**增益不生效
- 防具目前**只提供「抗性」一条轨**，
  而设计文档反复强调的"抗性 + 词条双轨并存"不存在

**讽刺之处**：玩家在锻造面板能看到词条数值（因为 UI 读了 `armorBonus()`），
进战斗后却完全不生效。这是最容易招差评的一类问题。

**修复成本**：低。`GameEntry.ts` 加一个 import + 一行 setup 传参。
**但要先确认设计意图**：镶嵌石不乘品阶倍率、innate 乘 —— 这个不对称是有意的还是要统一？

---

### 原 A-2（已关闭，留档）· 局外武器升级不消耗材料

**事实链**：

1. 《品阶与升阶设计》§二 承诺"局外升级（level 1→5）除了金币，还要消耗 `mat_<type>` 突破材料"
2. `EquipmentManager.upgrade()`（`:194-214`）**只扣金币**：`p.gold -= cost; owned.level += 1`
3. 原定的另一条消费方 `breakthrough()` 已在第八轮**随 forge.rank 一起删除**
4. 结果：`mat_<type>` 只被**产出**（重复武器转化、关卡掉落），**没有任何 `bagTake`**

**后果**：

- 12 种突破材料是死资源
- 「打推荐武器关 → 掉双份材料 → 升级那把武器」这条设计闭环**不存在**
- `MaterialConfig.ts` 的整个 rank 章节是死代码

**修复成本**：中。要决定"升级消耗多少材料"并改 `upgrade()` +
`getUpgradeCost()` 的返回结构（现在是单个数字，要改成 `{gold, material}`）。

### A-3 · 复活 / 双倍奖励标签无设计、无调用方

`AdTag.REVIVE` 与 `AdTag.DOUBLE_REWARD` 在枚举与广告位映射里存在，
但**全工程零调用方**，7 份历史设计文档也没有描述这两个系统。

要么补设计并接线，要么删掉。详见 [09-广告与变现 §7.3](09-广告与变现.md) 的建议方案。

### 原 A-4（已关闭，留档）· `t_critdmg` 天赋完全无效

`GameTypes.ts:699` 的 `addEffect` 对 `critMul` 是 **`Math.max` 取最大而非相加**，
而 `emptyModifier().critMul` 起点是 **2.0**。
`TalentConfig` 给 `t_critdmg` 的 `critMul: 0.15` < 2.0 → **永远被丢弃**。

同理，`幽`属性的 `+0.35 暴击倍率` 也不生效
（`buildWeapons` 的 `critMul = mod.critMul` 不吃镶嵌）。

**修复成本**：低。`critMul` 要么改成相加，要么给天赋配 > 2.0 的值。

### A-5 · 🔴 "站桩能不能通关噩梦"在代码中无任何支撑

**这是最重要的未决问题** —— 它决定"拖动走位是核心操作"这个设计前提是否成立。

历史文档对此有**两份互相矛盾**的结论：

| 来源 | 结论 |
|---|---|
| 《难度体系设计》§七表格 | 三种操作水平都 **15/15 通关**，站桩也全过 |
| 同文件 §七注释 | "被动玩法回到 **3/5** 通关噩梦……**墙回来了**" |
| 《总设计文档》§十三 第 9 条 | 明确标注"**这堵墙是刻意削平的**……是需求变更的直接后果，不是 bug" |

**为什么无法判定**：交付物中**没有任何探针脚本**。
`difficulty_probe.js` / `chain_probe.js` / `range_probe.js` / `affinity_measure.js`
**全部不存在**，10 余处引用它们的历史结论目前都无法复现。

而且历史文档自己也承认机器人不可靠：

> 站桩模式系统性偏袒远程武器（不动的玩家近战永远够不着）；
> 躲避模式又冤枉了移动向武器。两者给出的武器排名互相矛盾，谁也不能当基准。

**结论**：这个问题**不能用模拟回答，必须用真机数据**。
上线前必须验证：当前 `rangedRatio 0.42` + 噩梦三怪，在真机上是否真的能挡住站桩。

以及 Cocos 分包、首包大小（微信小游戏主包限制 4MB）均未规划。

## 四、🟡 P2 · 经济与留存

### C-1 · 金币 sink 缺口（后期金币溢出）

消耗端：升级 / 升阶 / 辅助升阶 / 万象线（90000 一次性）。
**没有循环出口** —— 无洗练、重铸、外观、分解。

满传说满图鉴后金币无处可去，会直接抽干抽卡与养成的动机。
建议至少加一个"金币 → 装备分解 → 材料"的循环。

### C-2 · 留存与终局循环缺失

关卡公式化至 200 关、24 关一轮，内容不会耗尽，
但**满传说 / 满图鉴之后玩家做什么**完全没有设计：
无日常 / 周常 / 赛季、无排行榜、无社交分享、无好友助战。

### C-3 · 献祭水晶换祝福值可能形成捷径

"不抽、直接献祭水晶换祝福值"使高阶权重翻倍。
若玩家纯刷噩梦（100 水晶/局）后集中献祭，可能绕过抽卡随机、稳定高产高阶。
**这条路径的产出上限从未被评估过**，祝福值上限 30 是否足够封死也没有结论。

### C-4 · 辅助装备"三轴过载"风险

辅助同时有局外阶数（1~5）× 品阶（0~6）× 自带属性三条成长轴。
阶数与品阶**都是"放大 effect"**，存在概念重叠 ——
玩家难区分"升阶"和"升阶数"。是否要合并需拍板。

### C-5 · 传说无碎片保底

神话之核掉率 25%（仅 9~12 关噩梦），平均 4 次但方差大；
抽卡最高只到神话（1%），**传说只能靠神话进化**。
整条传说线完全依赖随机掉落，没有"碎片保底"之类的兜底
（对比：高阶碎片可换钻石装备）。

### C-6 · 认知负荷可能过重

保守算玩家要面对的独立决策轴：18 武器 × 104 形态 + 8 配方 + 14 辅助 × 3 轴
+ 21 天赋 + 23 套防具 × 4 部位 + 7 品阶 + 24 属性 + 3 难度 + 3 池 + 复玩加难。

这不是"内容丰富"，是**认知负荷**。
文档自己意识到了 24 属性需要实时显示克制面板（"24×24 表不可能靠脑子记"），
但同样的逻辑没有应用到"18 武器 × 104 形态 × 8 配方"上 ——
玩家凭什么记住哪两把能合成？只有 TreePanel。

## 六、历史文档的归档说明

`docs/_archive_v0/` 存放 2026-10-16 之前的 10 份轮次设计文档 + 旧 README。

**归档原因**（这些是它们不能继续作为事实依据的理由）：

4. **多处"作废"内容未标注**，比如《锻造与属性设计》§六 整节仍把已删除的
   `forge.rank` 系统当现行机制完整描述

需要追溯"当初为什么这么设计"时可以看，但**不要按里面的数字调参**。
