# 08 · 新手引导与成就

> 4 步新手引导、14 条首通提示、去重持久化、成就表。
> 代码：`data/TutorialConfig.ts` · `core/TutorialManager.ts` · `ui/TutorialLayer.ts`
> · `data/AchievementConfig.ts` · `core/AchievementManager.ts`

---

## 一、问题与方案

此前游戏没有任何教学：玩家进入后不知道怎么移动、不知道目标是什么、
遇到抽卡 / 锻造 / 属性克制 / 三选一 / 进化 / 难度 / 继承 / 复玩加难等系统时没有任何上下文。

| 体系 | 触发 | 形态 | 是否重复 | 目标 |
|---|---|---|---|---|
| **新手引导**（Onboarding） | 首次进入游戏 | 线性、多步脚本化卡片 | 只看一次（`tutorials.newbie`） | 让玩家**立刻会玩** |
| **首通教学**（First-Encounter） | 第一次遇到某系统 | 单张上下文提示卡 | 每系统只看一次（按 id 去重） | 在**玩家真正需要**时解释一个系统 |

两者互补：新手引导是"第一印象"（覆盖移动 / 目标 / CTA），
首通教学是"随用随教"（更细的系统解释全部交给它）。
避免引导过长导致跳过率升高。

## 二、持久化

```ts
// PlayerProfile
tutorials?: Record<string, boolean>;   // key = 教学 id，存在即"已看"
```

- `defaultProfile()` 初始化为 `tutorials: {}`
- 兜底 `p.tutorials = p.tutorials || {}`
- **不依赖版本号升级**（只是新增可选字段，老存档默认可安全迁移）
- 标记写进**签名存档**（载荷里可见 `"tip_tree":true`），清缓存后重新载入仍然记得

## 三、架构分层

```
data/TutorialConfig.ts   所有文案集中地（NEWBIE_STEPS / FIRST_TIME_TIPS）
core/TutorialManager.ts  读取/标记已看；内容查询（纯逻辑，可单测）
ui/TutorialLayer.ts      纯代码构建的覆盖层（遮罩 + 卡片 + 按钮）
各 UI 面板 / 事件         首次出现时调用 TutorialLayer.showTipById(id)
```

### 为什么 TutorialLayer 用代码构建 UI

场景编辑器无法在本次开发流程中改动，且教学覆盖层应当"零依赖资源"。
`TutorialLayer` 在 `onLoad` 时用 `Graphics` + `Label` 画出遮罩与卡片，
通过 `TutorialLayer.ensure()` 在 `Canvas` 下按需创建节点，**无需在编辑器里挂预制体**。

## 四、新手引导 4 步（`NEWBIE_STEPS`）

| 步 | 标题 | 内容要点 |
|---|---|---|
| 1 | 欢迎 + 目标 | 这是"拖动走位 + 自动开火"的闯关游戏。击败敌人、攒金币与许愿水晶、解锁更高难度 |
| 2 | 操作 | 按住屏幕拖动角色移动；角色会**自动攻击**，你只需专注走位躲伤害 |
| 3 | 目标与产出 | 清空本关全部敌人即通关。通关获得**金币**（去装备界面升级武器）与**许愿水晶**（去许愿抽更稀有的武器/防具） |
| 4 | CTA | 按钮"开始第 1 关" → `LevelFlow.inst.openLevel(1)` |

可一键跳过（"跳过引导"按钮），跳过即标记 `newbie` 已看。

> ⚠️ `NEWBIE_STEPS` 的步骤**没有 `id` 字段**，靠数组顺序索引。
> 存档标记的 key 是固定字符串 `NEWBIE_KEY = 'newbie'`。

> ⚠️ **第 2 步的文案说"角色会自动攻击最近的敌人"** ——
> 但五种瞄准方式里只有 `AimModeId.NEAREST` 是打最近的，
> 初始武器 `blade` 是 `FRONT`（前向，需走位对准）。
> 开局武器与教学文案不一致，会让第一次游玩的玩家困惑。**建议修文案。**

## 五、首通教学 14 条（`FIRST_TIME_TIPS`）

| id | 触发点 | 教学要点 |
|---|---|---|
| `tip_move` | 首次进入战斗 | 拖动走位、自动开火、躲远程怪弹丸 |
| `tip_element` | `CounterPanel.show` | 24 种属性互相克制，克制武器有伤害/金币加成；破防可无视克制 |
| `tip_reward` | 首次 `REWARD` 阶段 | 三选一是变强主要来源；合成会占一个武器槽但可补选 |
| `tip_evolve` | 首次 HUD 出现"★可进化"或首次进化 | 攒经验让武器进化；分支进化需在三选一里选路线 |
| `tip_clear` | 首次通关结算（`SETTLE`） | 金币升级装备、水晶去许愿、可挑战更高难度或复玩加难刷纪录 |
| `tip_equip` | `EquipPanel.show` | 用金币升级出战武器的局外等级（永久生效） |
| `tip_gacha` | `GachaPanel.open` | 水晶抽卡；保底与祝福值机制；高阶碎片可兑换专属 |
| `tip_forge` | `ForgePanel.open` | 升阶、属性石镶嵌、碎片合成、防具套装；材料全靠打关卡 |
| `tip_armor` | 首次打开锻造防具页 / 首次获得防具 | 四部位套装，单件专属 + 套装属性，低阶可升到高阶 |
| `tip_difficulty` | `DifficultyPanel.show` | 三档难度独立解锁，越高敌人越强但金币/水晶越多 |
| `tip_loadout` | `LoadoutPanel.show` | 看广告继承上次通关装备；否则从初始数据开局 |
| `tip_replay` | `ReplayEnhancePanel.show` | 同一关可自选加难百分比，冲更高分与纪录 |
| `tip_achievement` | `AchievementPanel.open` | 成就覆盖所有系统，是"把游戏玩一遍"的引导 |
| `tip_tree` | `TreePanel.open` | 查"哪些武器能合成/进化成什么"，规划养成路线 |

### 5.1 `tip_armor` 补了一句万象线

`TutorialConfig` 里 `tip_armor` 额外提到"凑齐全属性石后会解锁「万象线」→ 万象套"。

### 5.2 防重复与克制

- 每个 id 仅弹一次：`showTipById` 内部先查 `hasSeen(id)`，已看直接返回
- **首通教学不抢镜**：新手引导进行中（`newbie` 未看完）时，**不弹 `tip_move`**
  （避免"怎么移动"讲两遍）；其余首通教学仍可在引导结束后正常触发
- 覆盖层点击遮罩非卡片区域可快速关闭当前卡，但**不影响"已看"标记**（关了就算看过了）

### 5.3 ⚠️ `consumeTip` 与 `showTipById` 的关系

`TutorialManager.consumeTip(id)` 是纯逻辑层（返回该弹什么并标记已看），
`TutorialLayer.showTipById(id)` 是显示层（内部先查 `hasSeen`）。
历史文档提到的 `tutorial_e2e` 会扫描编译产物里所有 `showTipById('x')` 调用，
断言「每个触发 id 都有文案」**且**「每条文案都有人触发」——
这个**双向一致**断言能防打错 id 导致静默失效，是这套体系里最有价值的一条测试设计。

> ⚠️ **但测试脚本本身不存在**（交付物无任何测试文件），所以这条保护目前是**纸面设计**。

## 六、成就

### 6.1 定位：引导而非墙

成就的定位是"引导"不是"墙"：把"把所有系统玩一遍"做成可达成目标。

**第十轮起，真正的上手引导由教学体系承担**（见本文档），
成就从"软引导"**退回为长线目标**。

### 6.2 结构

- `AchievementConfig.ts` — `ACHIEVEMENT_TABLE`
- `AchievementManager.ts` — `progressValue()` 支持的 kind

新增成就时 `kind` 必须是 `progressValue()` 已支持的类型，否则进度永远为 0。

### 6.3 进化图鉴（`TreePanel`）

图鉴标注"★ 复玩解锁的更上级进化"及触发条件，
让玩家在决定要不要看广告之前就知道"看完广告我能拿到什么"。

> 📌 `FormGraph.advancedTailOf(formId)` 扫**整条主线**（不只末端）找 advanced 边，
> 所以即使某形态在中间也能被图鉴识别。
